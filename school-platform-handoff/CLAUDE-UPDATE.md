### 다른 버전의 제안이 충돌하는 부분

- 초기 기획은 학교별 저장소·배포와 학교별 DB 스키마·역할을 권했고, 최신 0-E는 새 플랫폼 하나에 두 학교를 두고 먼저 검증하는 안을 제시했다. 14차에서는 한 새 프로젝트 안에서 예시 학교 두 곳을 논리적으로 구분한다. 학교에 임의 서버 코드를 실행할 권한을 주거나 독립 배포가 필요한 단계에서 격리 단위를 다시 결정한다.
- 두 번째 문서에 적힌 기존 포털의 미푸시 커밋, 로컬 키와 세션 이관은 기존 포털 자체를 원격 개발하는 시나리오다. 새 플랫폼 구축 과정에서는 새 저장소와 새 환경에 필요한 항목을 구성한다.
- 공유판의 337개 표는 Claude 쪽 조사값이다. 제시한 스키마별 수의 합은 323개로, 나머지 14개의 범위는 해당 절에 적혀 있지 않다. 이번 인계에서 기존 DB를 직접 조회하지 않았으며 이 값은 설계 참고치로만 기록한다.

기존 포털 설계를 나중에 참고할 때는 권한 소속(allowed_users·profiles·module_admins), 학기 참조(수업·시간표·학사력), 발행 시점 보존(record_snapshots·통계 값)부터 보는 것이 공유판의 제안이다. 이들은 새 플랫폼 테이블의 확정 이름이 아니다.
