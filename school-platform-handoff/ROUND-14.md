# 14차 첫 구현

**목표**는 같은 앱이 두 예시 학교의 자료를 받아 서로 다른 학기 표기를 담은 검토용 문서를 발행하는 것이다. 드리미와 룽아룬의 이름은 시연용이며 fixtures 폴더의 파일 내용은 두 학교의 실제 제도를 재현하지 않는다.

## 구현 순서

1. 새 저장소의 상태를 확인하고 Next.js 앱, 이 프로젝트 전용 Supabase 마이그레이션, 합성 데이터를 준비한다. 학교별 예시 관리자 두 명이 로그인한다. 각 자료·업로드 파일·규칙·문서에는 소속 학교가 있고 읽기와 쓰기 양쪽에서 이를 검증한다.
2. 여러 파일을 한 번에 끌어 넣고 이후에도 추가할 수 있게 한다. 시트는 + 버튼으로 주소를 여러 개 추가한다. 주소를 등록한 상태와 실제 내용을 읽은 상태는 구별한다. 비공개 시트 권한 또는 외부 분석 연결이 없는 환경에서는 그 상태를 표시하고 첨부 CSV로 첫 흐름을 끝까지 구현한다.
3. 아래 fixture의 행을 실제로 읽어 학기와 평가 기간의 관계를 추정하고, 어떤 파일과 행에서 추정했는지 함께 보여 준다. AI 연결이 준비되지 않았을 때는 규칙 기반 분석으로 표시한다. 관리자가 직접 수정한 답과 그 근거를 저장하고, 다음 자료 추가가 확정값을 조용히 덮어쓰지 않게 한다.
4. 저장한 학기 규칙으로 예시 문서 한 장을 발행한다. 발행 후 원본·규칙·양식이 바뀌어도 당시 표기와 값이 재현돼야 한다. 수정 발행본은 앞선 발행본과 연결한다.

## 검증할 예

| 상황 | 기대 결과 |
| --- | --- |
| 예시 A의 일정 CSV를 넣고 추후 평가 CSV를 추가 | 기존 일정 유지. 두 학기와 네 평가 기간의 관계를 출처와 함께 질문한다. |
| 예시 B에 세 텀 자료 등록 | B의 문서는 A와 다른 세 텀 표기를 사용한다. |
| 관리자 A와 B가 서로 상대 학교 기록이나 첨부를 열거나 바꾸려고 함 | 양방향으로 읽기·쓰기 거부를 확인한다. 각 학교 관리자의 정상 접근도 함께 확인한다. |
| 다시 로그인한 후 같은 문서를 조회 | 자료·확정 규칙·발행본이 DB에서 복원된다. |
| A의 규칙 수정 후 두 번째 문서 발행 | 첫 발행본의 값과 당시 규칙·양식은 그대로 복원되고 새 문서에 새 표기가 나온다. |

구현과 검증 결과를 PR에 담는다. 검토 배포를 위해 연결할 대상은 새 Vercel 프로젝트와 신규 Supabase 개발 프로젝트다. 이미 연결돼 있다면 검토 URL을 남기고, 자격 증명이 없다면 로컬에서 확인한 내용과 추가로 필요한 설정을 구체적으로 구분한다.
