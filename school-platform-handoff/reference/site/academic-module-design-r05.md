# 학교 제도 분석과 기본 기능 모듈 · 5차

## 4차에서 바로잡은 정의

기본 모듈은 제도와 관계없이 호출하는 기능 단위다. 기간 생성, 학적 이력, 수업 개설, 참여 배정, 시간 슬롯 배치, 출결 기록, 평가 관측값 등록, 양식 필드 매핑, 문서 렌더링, 업무 권한 부여가 예다. 각 모듈에 필요한 입력, 지원 기능, 출력, 오류와 제약을 명시한다. 학기제·텀제, 교과·프로젝트 구성, 루브릭·서술 평가, 시간표의 순환 방식은 학교 자료에서 도출하는 정책이다. 여러 과정이 서로 다른 정책을 쓰는 학교도 같은 기능 모듈을 조합해 운영한다.

| 층 | 내용 | 예 |
|---|---|---|
| 학교 자료 | 출처, 버전 및 해당 위치가 남는 자료 | 학사력, 엑셀 시간표, 시트, 학칙, 교육과정 편제, 성적표·학생부 양식, 업무분장 |
| 사실 후보와 질문 | 자료에서 읽은 내용과 추론, 충돌·누락, 관리자 질문 | ‘1·2학기’ 열을 읽었지만 집중과정이 이와 별도로 열리는지 확인 |
| 학교 제도 프로필 | 관리자에게 확인한 값, 적용 대상과 기간, 예외, 확인 근거 | 정규 두 학기, 전체 공통. 방학 집중과정은 신청 학생 대상 |
| 기본 기능 모듈 | 학교 규칙을 실행할 수 있는 기능과 입출력 | 기간 등록과 중첩 검증, 수업 개설, 기간별 참여 배정 |
| 연결과 검증 | 학교 규칙을 모듈 입력으로 변환하는 매핑과 시험 | 기간 경계일의 수강·출결·문서 출력 비교 |

## 1. 학교 자료 받기

- 파일은 PDF·DOCX·XLSX·CSV·TSV와 텍스트를 등록한다. 문서는 페이지/표를, 스프레드시트는 탭/행/범위를 식별한다. PDF의 표나 스캔은 검출 결과의 정확도를 확인하도록 표시하고, 엑셀은 수식과 표시값을 구분한다. 원문 및 추출 결과 버전을 보관한다.
- 실제 Google Sheets 연동에서는 관리자가 읽을 수 있는 문서와 탭·범위를 지정한다. 문서 ID·범위·수집 시각·수집 버전과 필요한 셀만 수집한다. 링크만 제공된 경우에는 자료로 등록하고 열람 가능 여부를 구분한다. 접속 권한을 확인하거나 셀 내보내기를 요청한다. 새로 읽은 값이 달라지면 이전 확인에 영향이 있는 항목을 재검토한다.
- 빈 서식·비식별 자료로 첫 도입을 진행한다. 실자료 연동 시에는 학적, 성적, 직원 정보를 필요 범위로 제한하고 학교의 자료 유효기간·권한을 적용한다. 원본의 안내문이나 셀은 분석할 데이터로 취급한다.

## 2. 추정하고 묻기

질문은 자료별 사실을 학교 정책으로 바꾸는 데 필요한 것만 묻는다. 시스템은 자료에서 읽은 내용, 제도라고 추정한 부분, 확인이 필요한 이유와 출처를 함께 보여준다. 관리자는 확인, 수정, 추가 자료 요청 또는 해당 없음으로 처리한다. 같은 주제의 자료가 다르면 각 근거의 적용 대상과 시행 시점을 먼저 묻는다. 이미 확인한 사실은 재질문이 필요한 자료 변경이 있을 때만 다시 연다.

| 영역 | 자료에서 발견할 수 있는 것 | 관리자에게 물을 것 |
|---|---|---|
| 학사력 | ‘1학기·2학기’와 ‘집중 기간’ 표기 | 집중 기간이 학기, 별도 이수 기간, 행사 중 어느 것인가 |
| 교육과정·수강 | 학년표와 선택수업 신청표 | 학급 배정과 수업 신청이 함께 존재하는가. 학년 혼합 여부와 신청·변경의 시점은 언제인가 |
| 시간표 | A/B주, 교시, 블록이 표에 등장 | 실제 주기와 휴일·보강 적용 규칙, 예외가 적용되는 과정은 어디인가 |
| 출결 | 일일 출결표와 프로젝트 명단 | 일일·교시·활동 중 어느 단위가 원기록인가. 마감·정정 권한은 누구에게 있는가 |
| 평가·문서 | 점수, 서술, 빈칸, 과목·활동 표기 | 무엇이 원자료이고 무엇이 공식 출력인가. 결측·미응시·면제를 어떻게 표시하는가 |
| 조직·권한 | 담임, 멘토, 수업 담당, 학사 승인자가 분장표에 등장 | 역할의 범위와 겸임, 입력·승인·발급 담당은 누구인가 |

예를 들어 ‘멘토’라는 명칭만으로 전체 학생 열람을 부여하지 않는다. 확인할 범위는 적용 학교·과정·대상 학생·행위·기간을 포함한다. 문서 양식의 제목과 실제 교육과정 계산 기준도 개별 확인한다.

## 3. 확인 답변을 모듈로 연결하기

확인 결과는 유형, 범위, 날짜, 예외, 증빙, 응답자와 출처 해시를 갖는 버전형 정책으로 저장한다. 모듈 카탈로그에는 지원하는 설정 스키마와 요구 입력, 제약, 버전, 검증 조건을 둔다.

예를 들어 ‘같은 프로젝트를 3개 학년이 선택 수강한다’가 확인되면 수업 개설, 학년 혼합 참여 배정, 실제 회차 기록 기능을 조합한다. 양식에서 공식 표기가 ‘탐구활동’이면 문서 필드 매핑에 공식 명칭을 별도로 둔다. 이수를 계산하려면 필요한 회차·최소 기준·제외 규칙을 확인하고 가상 결과를 비교한다. 미확정 항목은 연결 보류로 남긴다. 모듈 지원 범위를 넘는 요구에는 개선 요청 번호와 근거를 남긴다.

정책 답변 확인과 실제 적용 승인은 별개다. 운영에서는 기준일/사례/권한 범위 검증, 기존 기록과 출력 비교 및 승인 후에 프로필을 활성화한다. 처리 시 이미 승인된 정책·모듈 버전을 기록한다. 자료 갱신이나 규칙 수정이 과거 발행본을 소급 변경하지 않도록 한다.

## 시안의 범위

5차는 TXT·CSV·TSV 및 시트에서 붙여넣은 셀 값을 브라우저에서 읽고, 예시 규칙 기반으로 후보와 근거 위치를 보여준다. PDF·XLSX·DOCX 및 시트 주소는 등록과 열람 대기 상태를 시연한다. 실제 문서의 AI 분석, 시트 인증과 조회, 실제 학사 모듈 연결은 제품 구현 범위로 남아 있다. 시안은 확인 답변과 연결안만 브라우저에 저장한다.
