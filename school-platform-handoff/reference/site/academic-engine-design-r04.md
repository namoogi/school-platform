# 학교별 학사 운영 설계 · 4차

## 설계 목표

학교와 캠퍼스의 실제 학칙, 서식, 운영 절차를 분석해 이미 구축된 학사 엔진에 연결한다. 같은 학교에서도 학교급·과정·학년도에 따라 규칙이 다를 수 있다. 외부 학교 적용 전에는 기존 엔진의 지원 범위를 코드와 테스트로 확인한다. 아래 엔진 및 규칙 이름은 설계안이다.

## 1. 자료에서 학교 운영 프로필로

| 단계 | 산출물 | 담당 |
|---|---|---|
| 자료 등록 | 학사력, 시간표, 조직도·업무분장, 학칙, 평가계획, 성적표·학생부 빈 양식, 학교가 작성한 예시 | 학교 담당자 |
| 구조 추출 | 문서 버전, 날짜, 페이지·표·셀 위치, 값·단위·조건, 적용 대상 | 문서 추출기 및 AI |
| 대조 | 일치·충돌·누락 목록과 근거. 사본·이전 버전·학년별 예외를 구별 | AI 제안, 담당자 판정 |
| 엔진 대입 | 학교 규칙별 엔진·설정·확장 요구 및 검증 사례 | 시스템 추천, 교무·운영 승인 |
| 검증 후 적용 | 가상 학생 재현, 경계조건·누락·예외·출력 검증, 적용일과 승인한 프로필 버전 | 학사 승인권자 |

정책 결정 순위를 코드에 보편 규칙으로 고정하지 않는다. 학교가 확인한 현행 규정·시행일·적용 범위를 먼저 입력하고, 예전 양식이나 실제 입력 사례와 불일치하면 남긴다. 예를 들어 시간표 파일은 수업 시간을 보여주지만 지각을 결석으로 바꾸는 기준을 확정해 주지는 않는다. 근거 상태는 확인됨·확인 필요·충돌·적용 대상 아님으로 기록한다. AI의 추론은 승인 대상이며 실제 학적이나 평가를 계산하는 서버는 승인된 규칙 버전으로 동일 입력에 동일 결과를 내야 한다.

초기 자료는 빈 서식과 비식별 가상 샘플을 우선 사용한다. 실제 학적 자료를 다룰 수 있는 배포에서는 접근 범위, 저장과 파기, 모델 입력 범위, 승인과 열람 이력을 학교 정책에 맞춰 구현한다. 웹 공개 콘텐츠는 별도의 발행 흐름을 사용한다.

## 2. 엔진에 대입할 규칙

| 엔진 | 공통 구조 | 학교별 결정과 예외 |
|---|---|---|
| 학적·학사력 | 학생, 재학 기간, 소속, 학년도, 기간 버전 | 학년제·무학년, 복수 캠퍼스, 학기·텀·집중과정 병행, 전입·휴학·전출일, 평가 기간과 문서 발급 기준일 |
| 수강·교육과정 | 과목/활동 정의, 개설 분반, 참여·이수 기간 | 필수·선택·프로젝트, 학년 혼합, 공동 수업, 외부 과정 인정, 수업명·공식 기록명 연결 |
| 시간표 | 반복 패턴과 실제 수업 회차 분리, 실제 시간과 장소·담당 연결 | 고정 교시, 블록, A/B 주기, 6일 순환, 공휴일 이후 순환 기준, 집중수업, 대체교사·장소 변경·보강 |
| 출결 | 일일·수업 회차·활동 단위 원기록, 입력자·기록 시각·정정 이력 | 지각·조퇴·인정 사유 코드, 일일과 수업 출결의 관계, 미입력/결석 구별, 마감·정정 권한 |
| 평가·이수 | 원 평가와 공식 결과 분리, 척도와 기준 버전 | 점수·성취수준·루브릭·서술·이수 여부, 혼합 평가, 가중치·반올림·경계값·미응시/면제·재평가·과정 이수 조건 |
| 성적표·학생부 | 문서 종류, 서식 버전, 필드 매핑, 발급 스냅샷 | 표 순서·그룹·학기별 페이지·다국어·서명, 표기명, 빈칸·미평가 표시, 단일 성적표 또는 누적 기록, 학교별 출력 검토 |
| 조직·권한 | 사용자, 업무 역할, 대상 범위, 행위 권한, 유효 기간 | 담임/멘토, 교과교사, 보조교사, 행정, 학사 승인자, 발급 담당, 캠퍼스·학급·과목 범위, 대리 승인 및 기간 종료 |

학교 운영 방식은 미리 정한 단일 학교 유형으로 판정하지 않는다. 예를 들어 학사력은 두 학기지만 시간표는 A/B이며, 학부별로 평가 방식이 다른 조합이 가능하다. 규칙의 적용 범위는 학교·캠퍼스·과정·학년/그룹·과목 및 효력 기간으로 표현한다. 우선순위는 승인된 규칙으로 표현하며 같은 우선순위의 조건이 겹치면 차단한다. 대상이 없거나 값이 없을 때 적용할 기본값도 근거를 둔다.

## 3. 문서 양식과 데이터 매핑

성적표·학생부 양식은 서식과 데이터 매핑을 각기 버전 관리한다. 필드마다 원천, 대상 기간, 집계/표시 방식, 미입력/면제 표시, 표시 언어, 출력 여부를 지정한다. 문서 유형과 필드의 공란 처리가 확인되지 않으면 해당 과정을 승인 대기 상태로 둔다. PDF 원본 좌표나 레이아웃을 그대로 재현해야 하는 학교, 가변 높이의 서술형 페이지가 필요한 학교를 각각 검증한다.

예시: 학교 내부 수업명 '지역탐구 프로젝트' → 해당 학교가 정한 공식 기록명 → 루브릭 기록·교사 서술 → 성적표 과목/활동 영역 → 해당 학기 학생부 활동 기록. 서술·원점수·환산값은 서로 다른 필드다. 과거 발행 문서는 당시의 프로필·규칙·템플릿 버전과 결과를 보관해 재발급 때 재계산 여부를 판단할 수 있게 한다. 학교 공식 양식 준수 여부는 시안 자동 검사만으로 판단하지 않으며 학교 승인과 실물 대조를 포함한다.

## 4. 학교 배포와 기존 데이터

학교 프로필은 `draft → 검증 → 승인 → 지정일 적용 → 대체` 흐름을 따른다. 적용 대상·적용일·지도 담당자·문서 발급 담당·승인자 및 변경 이유를 기록한다. 적용일보다 앞선 성적·출결·문서가 새 규칙으로 덮이지 않아야 한다. 승인한 입력값이나 매핑이 바뀌면 검증과 승인을 초기화한다. 이전 프로필 복원은 미래 처리 설정을 다시 선택하는 절차로 설계하고 운영 DB 복원과 구분한다.

| 대응 | 예시 | 적용 조건 |
|---|---|---|
| 설정 | 기간 수, 반복 주기, 척도, 용어, 공란 정책 | 지원 엔진의 허용값과 교차 검증 통과 |
| 매핑·서식 | 시간표 파일 열, 성적표 출력 위치, 학생부 표기명, 조직 직무 | 검토된 필드 연결과 문서 비교 통과 |
| 학교 확장 | 지원하지 않는 이수 규칙, 공식 시스템 연동, 특수 판단 절차 | 개선 요청 판에 근거·규칙·완료 기준을 넘기고 격리 환경에서 검증 |

## 5. 구현 단계와 통과 기준

1. 기존 엔진의 기능·설정·입출력·한계 목록을 작성한다. 학교별로 필요한 자료는 학교 운영 프로필 항목에서 역산한다.
2. 학급 중심·프로젝트 중심·복수 텀 학교의 빈 양식과 가상 자료로 서로 다른 조합을 재현한다. 한 학교의 두 과정에 서로 다른 시간표와 평가 척도를 적용하는 사례를 포함한다.
3. 학기/텀 변경일, 순환 시간표의 휴일·보강, 전입·전출, 미응시와 면제, 척도 경계 및 반올림, 서술 페이지 넘김, 직무 겸임과 승인 범위 검증을 통과한다.
4. 기존 시스템에서 출력한 가상 문서와 신규 출력의 필드·형태를 비교한다. 불일치의 사유와 승인 여부를 기록한다.
5. 읽기 전용 시험 운영에서 과거 발행본과 이력을 확인한 후 범위를 한정해 운영에 적용한다.

4차 HTML 시안은 세 가지 가상 학교 자료에서 발견한 충돌, 엔진 매핑 수정, 미해결 규칙 차단, 표본 확인, 프로필 승인·저장을 시연한다. 파일 분석·AI 연결·실제 성적 계산 또는 발급과 운영 반영은 구현 전이다.
