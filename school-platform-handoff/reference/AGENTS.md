# 학교 플랫폼 시안 변경 원칙

사용자가 새로 밝힌 목적을 이번 차시의 구현 기준으로 삼는다. 종전의 디자인 결정, 템플릿, 예시, 구현 지침은 새 요청에서 다시 선택할 수 있는 기본값이다. 오래된 메모와 새 요청의 범위가 겹치면 해당 조항을 고치고 결과 화면까지 바꾼다.

- 화면 구성, 서체, 명칭, 탐색, 모듈 조합처럼 되돌릴 수 있는 변경은 재승인을 기다리지 않고 다음 차시에 구현한다. 사용자가 탐색을 부탁한 제안은 비교 가능한 시안으로 남긴다. 시안 채택과 운영 학교 전체 적용은 각각 요청 범위에 맞춘다.
- 사용자 데이터 손실, 기존 기록의 덮어쓰기, 개인정보 공개 범위 확대, 실제 결제나 외부 발송처럼 되돌리기 어렵고 요청에 구체적인 승인이 없는 작업은 실행 전 그 부분의 대상과 영향을 확인한다. 그동안 가상 자료나 복사본에서 가능한 시안과 테스트는 진행한다.
- 과거 차시는 고유 주소로 다시 열 수 있게 보존한다. 이전 결과를 보존하라는 요구를 새 차시에서도 같은 모양이나 동작을 유지하라는 뜻으로 적용하지 않는다.
- 변경 완료는 실제 화면 또는 동작에서 확인한다. 바뀐 기준과 이유, 적용 범위, 비교할 이전 차시를 짧게 남긴다. 구현하지 못한 부분은 구체적인 사유와 함께 밝힌다.
