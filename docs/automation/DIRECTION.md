# 방향 설계 (자동 개발 세션)

> **요약** 자동 개발 세션은 대기열의 일만 처리하지 않는다. 연구소의 할 일·아이디어·도구·방법론, 결정 기록(ADR), 차시 문서를 모아 **이 플랫폼이 다음에 당연히 갖춰야 할 것**을 미리 설계하고, 되돌릴 수 있고 비용이 들지 않는 개선부터 진행한다(2026-11-27 사용자 지시).
>
> **왜** 사람 세션은 선생님 지시를 따라 큰 기능을 만든다. 그 사이에 쌓이는 빈틈(화면 완성도, 운영 안전, 시험, 문서)을 메우는 쪽이 있어야 기능이 실제로 쓰일 수 있는 상태가 된다.

이 문서는 자동 세션이 매 실행 0단계에서 읽고, 일을 마치면 갱신한다. 순위는 바뀔 수 있는 기본값이다. 선생님·관제가 고치면 그것을 따른다.

```terms
방향 설계 | 다음에 할 일을 미리 정리해 둔 지도 | "출결 화면을 휴대폰에서도 쓰게"를 F3 다음 할 일로 적어 둠
당연한 개선 | 지시가 없어도 목적에 비춰 해야 하는 일 | 빈 화면에 '다음에 할 일' 안내 넣기
자동 허용 | 사람 확인 없이 PR까지 가는 일 | 화면 문구·배치, 시험 추가, 문서
승인 필요 | 설계 문서까지만 하고 관제에 결정 요청 | 데이터 형식 변경, 비용, 공개 범위, 외부 발송
```

## 1. 무엇을 보고 정하나 (출처)
| 출처 | 어디서 | 무엇을 본다 |
| --- | --- | --- |
| 연구소 | `GET https://onschools.vercel.app/api/admin/items` (점검 토큰은 환경이 붙임) | 종류 `todo`·`lab`·`tool`·`method`·`plan` 중 상태 `todo`·`idea`·`candidate`·`trial`·`running` |
| 관제 센터 | `/api/control/mine?session=<내 id>` | 나에게 온 답·지시(가장 먼저) |
| 결정 기록 | `docs/decisions/` | 채택했지만 코드가 아직 따르지 않는 것 |
| 차시 문서 | `docs/rounds/` 최근 것, `docs/NEXT.md` | '다음', '하지 못한 것' |
| 연구 문서 | `docs/research/` | 결론이 났는데 구현 전인 것 |
| 품질 신호 | UI 점검 표, `lint:colors` 기준 목록, `npm audit`, E2E 실패 이력 | 줄여야 할 빚 |

## 2. 방향 (2026-11-27 기준, 큰 줄기 다섯)
1. **화면이 기능을 따라잡게.** F1~F6 학사 토대가 끝났지만 화면은 72차(수업)까지다. 성적·출결·기록·학교 구조 화면을 실제로 쓸 수 있게 다듬는다(빈 상태·오류·휴대폰 폭·용어 통일). UI 점검 표가 이 줄기의 도구다.
2. **운영 안전.** 파일 저장소(R2)와 학교별 사용량·요금 추정은 ADR 0018로 갖췄다. 남은 것은 올리는 그림을 줄이는 일(원본 보관 결정 필요)과 비용이 커지는 지점을 미리 보는 일이다.
3. **품질 루프 자동화.** 시험·접근성·색상 린트·UI 캡처를 CI에서 같은 방식으로 돌린다. 회귀 시험을 기능마다 둔다(예: F2 동시성 #125).
4. **학교가 혼자 시작하기.** 가입 신청·초대·첫 설정 흐름. 외부 발송(메일)이 들어가므로 설계까지만 자동, 구현은 승인 필요.
5. **구독 AI와 함께 일하기.** 학교 AI·Codex가 범위 토큰과 지시문으로 일하게 하는 지시문·점검표를 다듬는다(ADR 0022·0032). 플랫폼 서버의 유료 API는 만들지 않는다.

- **이미 끝난 것은 넣지 않는다.** 후보를 더하기 전에 `docs/decisions/`·`src/lib/`에서 같은 기능이 있는지 먼저 찾는다. 예: 파일 저장소·학교별 사용량·요금 추정은 ADR 0018·0019(R2, 키 `s/<school_id>/<sha256>`)로 이미 있다(#141 Codex P2). 연구소에 남은 todo가 실제로는 끝난 것이면 관제에 상태 정리를 알린다.
- 순위를 바꾸거나 새 후보를 더하면 이 표를 고치는 커밋을 그 실행 PR에 넣는다.
- 사람 세션·전담 세션이 맡은 영역(홈페이지 `/site`·`/s/`는 홈페이지 세션)은 후보에 넣지 않는다. 겹치면 그 세션에 넘긴다.
- 사람 세션이 같은 주제를 시작하면 내 PR을 닫고 차이만 증분으로 낸다(#62 교훈).

## 4. Codex CLI와 함께 UI·UX 만들기
- 쓰는 곳: 화면을 새로 짜거나 크게 바꿀 때, Codex CLI가 스크린샷(`.ui-review/`)을 보고 UI_REVIEW 5장 체크리스트로 **독립 검토**를 하고, 필요하면 배치안을 낸다. 고치는 일과 선별은 Claude가 한다(UI_REVIEW 2장 역할표).
- 지금 막힌 것: 이 클라우드 환경에는 Codex CLI가 깔려 있지 않다. 깔 수는 있지만(npm `@openai/codex`), **로그인**이 필요하다.
  - ChatGPT 구독으로 로그인하면 구독 사용량을 쓴다(ADR 0032와 맞음).
  - API 키로 로그인하면 사용량만큼 과금된다. 첫 실행 전에 사용자 확인이 필요하다(UI_REVIEW 7장).
  - 클라우드 세션에서 구독 로그인을 어떻게 넘길지는 **확인 필요**하다. 브라우저 로그인 경로가 원격 컨테이너에서 되는지 시험하지 않았다.
- 그 전까지: GitHub의 `@codex review`(코드만 봄)는 계속 쓰고, 화면 판정은 자체 점검으로만 적는다.

## 5. 하지 않는 일 (방향 설계여도)
병합, main 직접 push, 배포·환경 설정 변경, 유료 API, 결제, 외부 발송, 이미 적용된 마이그레이션 수정, 실제 학생·교직원 정보 사용, 사용자가 정하지 않은 제한·상태 늘리기(AGENTS '설계 유지보수').
