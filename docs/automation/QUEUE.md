# 자동 개선 대기열

자동 개선 실행(②)이 고를 수 있는 작업 목록. **자동 허용**만 사람 확인 없이 구현 PR까지 진행한다. **승인 필요**는 설계 문서까지만 만든다. 위에서부터 처리한다.

## UI 점검 (85차부터, 한 번 실행에 페이지 하나)

**언제 고르나**: 이어갈 `[자동·진행 중]` PR이 없으면, 아래 기능 대기열보다 이 표에서 먼저 고른다.
- 자체 점검이 `대기`이고, 제목이 `[자동] UI 점검: <그 페이지>`(또는 `[자동·진행 중] UI 점검: <그 페이지>`)인 **열린 PR이 없는** 맨 위 페이지 하나를 고른다.
- 상태 갱신(`자체 점검 PR #번호`)은 그 PR 안에만 있다. 병합 전까지 `main`의 이 표는 계속 `대기`로 보인다. 그래서 열린 PR로 중복을 거른다(85차, Codex 지적 P1).
- 검토 대기 `[자동]` PR이 3개 이상이면 새로 시작하지 않는다(RUN-PROMPT 0-4). 관제가 UI 점검 PR을 차시마다 선별·병합해서 이 흐름이 멈추지 않게 한다.

**한 번의 절차** (`docs/UI_REVIEW.md` 4장)

> **주의** 이 클라우드 환경에는 Codex CLI가 없고, Codex GitHub 리뷰는 코드만 본다(`.ui-review/` 그림은 커밋하지 않는다). 그래서 자동 세션의 화면 판정은 **임시 자체 점검**이다. UI_REVIEW 2장(Claude는 자기 화면을 스스로 통과 처리하지 않는다)에 따라, 이 표의 어떤 페이지도 자동 세션이 `통과`로 바꾸지 않는다. `통과`는 그림을 본 **독립 화면 검토**(Codex가 스크린샷을 보는 경로, UI_REVIEW 4-3) 결과가 있을 때만 관제가 적는다. 그 경로가 마련될 때까지 독립 화면 검토 칸은 `대기`로 둔다(85차, Codex 검토 지적 1).

1. 로컬 DB + 시드 → `npm run build && npx next start -p 3000` → `npm run ui:review -- <페이지>`
2. 기계 검사(콘솔·가로 스크롤·axe·`npm run lint:colors`)가 실패하면 그것부터 고친다.
3. `.ui-review/<페이지>/*.png`를 직접 보고 5장 체크리스트(A~E)로 판정한다. 6장 형식으로 PR 본문 `## UI 점검`에 적는다.
4. 판정은 자체 점검이다. **높음·중간** 중 범위가 작고 규약 안에서 고칠 수 있는 것만 고친다. 화면 구조·명칭·흐름을 크게 바꾸는 것은 보류로 남긴다(관제가 선생님께 올린다).
5. 1·2를 다시 돌려 통과시킨다. PR 제목은 `[자동] UI 점검: <페이지>`. Codex는 자동 리뷰가 켜져 있어 PR을 열면 검토한다. Codex 코드 지적은 `docs/COLLABORATION.md` 8절대로 수용·기각·보류 표로 답한다.
6. 병합하지 않는다(관제가 선별해서 병합한다). 고칠 것이 없으면 자체 점검 칸만 `이상 없음(날짜)`으로 바꾸는 문서 PR을 연다.
