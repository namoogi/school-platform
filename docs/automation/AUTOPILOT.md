# 자동 개선 운영 (Autopilot)

요청이 없어도 설계·도구·방법론·기능을 주기적으로 개선한다. 사람의 결정이 필요한 일은 **PR과 보고로 멈추고**, 병합·배포·비용은 사용자가 승인한다.

## 두 층

| 층 | 수단 | 주기 | 하는 일 |
| --- | --- | --- | --- |
| ① 자동 점검 | GitHub Actions (`.github/workflows/`) | PR·push마다, 주 1회 | `ci.yml`: 타입 검사·단위·통합(Postgres)·빌드·E2E. `weekly-health.yml`: 의존성 업데이트·보안 취약점·테스트 결과를 이슈 "주간 점검"에 기록 |
| ② 개선 실행 | Claude Code 예약 작업(새 세션) "학교 플랫폼 자동 개선" | **매시간 58분 (2026-11-22 사용자 결정: 유휴 시간에 계속 개발, 30분 요청 → 예약 최소 간격 1시간)** | 아래 '실행 종류' 중 하나를 골라 PR 1개 + 실행 기록 |

## 실행 종류 (② 한 번에 하나)

| 종류 | 언제 고르나 | 결과물 |
| --- | --- | --- |
| A. 기능 구현 | `QUEUE.md`에 **자동 허용** 항목이 있으면 우선 | 구현 PR (테스트 포함) + `@codex review` |
| B. 설계 갱신 | A가 없고, 결정 기록·디자인 시스템과 코드가 어긋난 곳이 있으면 | 디자인 브리프 또는 결정 기록 초안 PR(문서만) |
| C. 도구·방법론 갱신 | A·B가 없거나 주간 점검 이슈에 처리할 항목이 있으면 | 의존성 갱신 PR(2주 지난 버전만) 또는 도구 비교 결정 기록 초안 |

## 안전 규칙 (예외 없음)

1. **병합 금지.** main에 직접 push 금지. 브랜치 `auto/<날짜>-<주제>`, PR 제목 앞에 `[자동]`.
2. Vercel·Supabase·GitHub 설정, 환경 변수, 도메인, 배포 보호를 바꾸지 않는다.
3. 유료 API 호출, 결제, 메일·메시지 발송을 하지 않는다. 비용이 생기는 일은 PR 본문 '승인 필요'에 적고 멈춘다.
4. 이미 적용된 마이그레이션을 고치지 않는다. 새 마이그레이션이 필요한 기능은 **초안(draft) PR**로만 연다.
5. 데이터 경계(AGENTS.md 1~6)와 디자인 시스템을 지킨다. 테스트가 통과하지 않으면 PR을 초안으로 두고 실패 내용을 적는다.
6. 한 실행에 새 기능 하나. 시작한 기능은 **끝날 때까지 이어간다**: 작업 중에는 `[자동·진행 중]` 초안 PR에 단계마다 push하고, 다음 실행은 40분 안에 커밋이 있으면 기다리고, 멈춘 PR이 있으면 새 작업 대신 그것을 이어서 끝낸다. 검토 대기 `[자동]` PR이 3개 이상이면 새 기능은 시작하지 않는다(검토 적체 방지).
7. 할 일이 없으면 아무것도 만들지 않고 실행 기록에 "변경 없음"만 남긴다.

## 실행 기록

`docs/automation/runs/YYYY-MM-DD.md` (PR에 포함): 고른 종류와 이유, 한 일, 테스트 결과, 승인 필요 항목.

## 사용자가 할 일

- `QUEUE.md`에서 자동으로 해도 되는 항목을 **자동 허용**으로 표시하거나 지운다.
- `[자동]` PR을 검토·병합하거나 닫는다. Codex 검토 결과를 참고한다.
- 주기를 바꾸거나 멈추려면 Claude에게 "자동 개선 주기 바꿔/멈춰"라고 요청한다(claude.ai의 예약 작업 목록에서도 끌 수 있다).
- 실행이 쌓인 PR(3개 이상)에서 멈추면, `[자동]` PR을 병합하거나 닫아야 다음 실행이 새 작업을 한다.
