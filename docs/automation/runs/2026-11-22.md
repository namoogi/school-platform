## 실행 2 (23:37, 이어가기 — PR #13)

- **종류**: 이어가기. PR #13의 Vercel 미리보기 배포가 실패(`must be able to SET ROLE "app_writer"`). Codex 리뷰는 아직 없음.
- **원인**: PG16+에서 CREATEROLE로 역할을 만든 비슈퍼유저는 ADMIN 구성원이 되지만 SET 권한은 없다. 기존 검사(`pg_has_role(..., 'MEMBER')`)가 참이라 SET 부여를 건너뛰었다. 실패한 마이그레이션은 트랜잭션째 롤백돼 Supabase DB에는 아무것도 남지 않았다.
- **수정**(로컬 커밋, push 보류): ① PG16+면 `SET` 권한을 검사해 `with inherit false, set true`로 부여 ② 소유자 변경 동안만 `app` 스키마 CREATE 권한을 주고 곧바로 회수 ③ 함수 권한 회수·부여를 소유자 변경 전에 실행(비슈퍼유저는 새 소유자가 준 PUBLIC 실행 권한을 회수하지 못해 anon 실행이 열려 있었음).
- **검증**: Supabase 조건을 흉내 낸 별도 클러스터(UTF8, 비슈퍼유저·CREATEROLE 소유자, authenticated·anon 구성원)에서 `npm test` 79개 통과. 로컬 슈퍼유저 조건에서도 79개 통과, typecheck·check:repo 통과.
- **push 보류 이유 (승인 필요)**: Vercel `DATABASE_URL`이 production·preview 공용이다. 이 브랜치에 push하면 미리보기 빌드가 **운영 DB에 이 마이그레이션을 바로 적용**한다(병합 전, 검토 전). 적용되면 이후 Codex 지적을 이 파일에 반영할 수 없다(적용된 마이그레이션 수정 금지). 초안 PR이면 적용되지 않는다는 AUTOPILOT 규칙 4의 전제가 실제 배포 구성과 맞지 않는다.
