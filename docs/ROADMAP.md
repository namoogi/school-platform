## 2. 로그인과 계정

요구: 로그인 시도 제한, 비밀번호 변경, 관리자 초대, **Google 로그인**, 기타 계정(Microsoft, Apple, 카카오 등) 로그인.

| 안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. Supabase Auth로 전환 (16차 채택: Google 로그인) | 로그인·초대·비밀번호 재설정·소셜 로그인을 Supabase가 처리. 앱은 Supabase가 발급한 사용자 ID를 지금처럼 RLS에 넘김 | 소셜 로그인 공급자 설정만으로 추가, 이미 쓰는 Supabase 안에서 해결(결제처 추가 없음), 보안 기능을 직접 만들지 않음 | 지금의 자체 로그인 표를 옮기는 마이그레이션 필요, 로컬 테스트에 Supabase Auth 대역이 필요 |
| B. 자체 로그인 유지 + Auth.js | 지금 방식에 OAuth 라이브러리를 붙임 | 외부 서비스 의존이 적음 | 초대·재설정 메일, 시도 제한, 세션 관리를 직접 구현·보안 검증해야 함 |

확인 필요: 각 공급자의 무료 범위와 카카오 등 지원 목록은 연결 시점의 Supabase 문서로 확인한다. Google 로그인은 Google Cloud에서 OAuth 클라이언트를 만들어야 한다(무료).

## 3. 전체 관리 모드 (플랫폼 운영자)

학교 관리자 위에 **전체 관리자** 역할을 둔다. 사용자 결정(2026-11-22)에 따라 전체 관리자는 모든 학교에 접근하고, 입장은 그 학교가 볼 수 있는 기록으로 남긴다. 실제 학생 자료가 들어오기 전에 접근 범위를 학교와의 개인정보 처리 약정에 맞춰 다시 확인한다.

| 기능 | 내용 | 결정할 점 |
| --- | --- | --- |
| 학교 등록·관리 | 16차 구현: 학교 생성, 상태(시범·운영·중지), 첫 관리자 초대 | 남은 결정: 학교가 직접 가입 신청을 할 수 있게 할지 |
| 라이선스 등록·할당 | 16차 구현: 학교 단위, 학교 관리자가 좌석·기능 등록, 월 예상액·청구 예정 기록 | 남은 결정: 실제 결제 대행사·청구 주기·세금계산서 (되돌리기 어려운 작업이라 별도 승인) |
| 대시보드 | 학교별 사용량, 자료·질문·발행 수, 오류, 미해결 질문, 라이선스 만료 임박 | 지표 목록 |
| 연구소 | 학교들의 확정 규칙·질문 패턴을 비식별로 모아 기본 엔진(분석기·모듈) 개선안을 만들고, 합성 자료로 시험한 뒤 새 버전으로 배포 | 학교 자료를 엔진 개선에 쓰는 동의 범위(개인정보), 새 엔진 버전을 학교에 적용하는 승인 절차 |
| 엔진 버전 관리 | 분석기·모듈 버전을 기록하고 학교별로 적용 버전을 고정·업그레이드 (발행본은 당시 버전 유지) | 자동 업그레이드 여부 |
| 연례 토큰 점검 | 38차 구현: 학교 AI 작업 공간 토큰의 기한 연장(값 그대로), 만료 30일 전 알림(/site 설정), 180일 넘게 안 쓴 무기한 토큰 표시, 전체 관리 → 학교별 개발 연동에 모든 학교 토큰 목록(ADR 0014) | 남은 결정: 해마다 정해진 달에 학교에 점검 알림을 보낼지(메일 발송은 외부 발송이라 별도 승인) |

## 5. 개발 방식

- **방법론·도구 비교 적용**: 새 도구나 방법(테스트, 배포 검사, 에이전트 작업 방식)은 바로 지침에 넣지 않는다. `docs/decisions/`에 비교 기록(ADR)을 남기고, 시범 적용 결과를 본 뒤 채택한다.
- **지침 충돌 방지**: 작업 지침은 루트 `AGENTS.md` 하나를 기준으로 한다. 우선순위는 사용자의 최신 요청 → `AGENTS.md` → 차시 문서 → 과거 인계 자료 순서다. 새 규칙을 넣을 때는 기존 조항과 겹치는지 확인하고, 겹치면 옛 조항을 고치거나 지운다. 규칙 추가는 PR로만 하고, 개발을 막는 조항(예: 고정 숫자, 특정 도구 강제)은 이유와 만료 조건을 함께 적는다.
- **Codex와 협업**: `AGENTS.md`는 Codex도 읽는 공통 지침이다. ChatGPT 구독 계정에서 Codex에 GitHub 저장소를 연결하면 같은 저장소에서 작업·PR을 나눠 할 수 있다. 연결 절차는 ChatGPT·Codex 설정에서 사용자가 하며, 메뉴 위치는 연결 시점에 확인이 필요하다. 협업 규칙(브랜치 이름, PR 하나에 한 차시, 서로의 PR 검토)은 `AGENTS.md`에 추가한다.
