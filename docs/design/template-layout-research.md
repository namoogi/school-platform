# 템플릿 레이아웃 조사와 적용 원칙 (100차)

> **요약** 잘 정돈된 화면은 장식보다 먼저 **같은 콘텐츠 폭, 되풀이되는 간격, 예측 가능한 구역 머리, 화면 폭에 따라 접히는 격자**를 공유합니다. 이 문서는 공개 디자인 시스템과 상용 제작 도구의 공식 설명에서 구조 원리만 추려 학교 템플릿의 공통 레이아웃으로 옮긴 기록입니다.

> **왜** 이야기형·프로젝트형·유치원형의 사진과 색은 서로 달라도, 구역 시작선과 카드 줄·머리글·바닥글은 같은 규칙으로 움직여야 방문자가 내용을 빠르게 훑을 수 있습니다.

```terms
레이아웃 토큰 | 폭·간격을 매번 새 숫자로 쓰지 않고 이름 붙여 함께 쓰는 값 | `--t-space-6`을 카드 사이와 구역 머리 아래에 함께 사용
12칸 격자 | 콘텐츠 폭을 같은 12칸으로 나눠 3·4·6칸 조합으로 정렬하는 기준 | 카드 3장은 각각 4칸, 글·사진은 각각 6칸
재배치 | 좁은 화면에서 칸을 줄이거나 세로로 쌓는 규칙 | 데스크톱 3열 카드가 휴대폰 1열이 됨
```

## 조사 방법과 저작권 경계

2026-11-27에 각 서비스의 **공식 문서**를 확인했다. 판매 템플릿의 코드·사진·문구·고유한 시각 표현은 열람하거나 가져오지 않았다. 아래에는 숫자와 동작 같은 일반적인 구조 원리만 기록했다. 구현 또한 저장된 블록과 `variant`를 바꾸지 않고 렌더러의 공통 틀과 CSS 토큰으로 독자 작성했다(ADR 0034).

## 대표 3종 적용

- **이야기형(`ivory`)**: 편집형 hero의 글·사진을 6칸씩 맞추고 행사 카드를 사진 경계 안으로 넣으며 모든 뒤 구역이 같은 1200px 선과 간격 단계에 맞는다.
- **프로젝트형(`studio`)**: 작품·멘토·소식 카드가 보이는 항목 수에 맞춘 열 수와 줄별 균등 분배로 마지막 줄까지 차고, 구역 행동 단추는 머리 오른쪽으로 이동한다.
- **유치원형(`play`)**: 둥근 사진과 색은 유지하고, 반·하루·알림·FAQ가 같은 구역 머리와 교차 띠를 쓴다.
- 세 테마의 홈과 안쪽 9쪽은 같은 `SiteFrame`·`SiteBlocks`를 사용하므로 별도 저장 자료 변경 없이 공통 적용된다.

## 100차 마무리 구현·인계 (PR #159)

> **요약** 저장된 블록·variant를 바꾸지 않고 구역의 시작선, 머리, 카드, 머리글·바닥글을 공통 규칙으로 정리했다. 아래 검증은 구현자의 자체 점검이다. 브라우저가 실행되지 않아 화면 완료 판정과 독립 검토는 남아 있다.

### 구현 계약

- `--t-space-1..8`: **4 / 8 / 12 / 16 / 24 / 32 / 48 / 80px**. `--t-content`: **1200px**, `--t-reading`: **720px**, `--t-card-min`: **16rem**.
- `--t-page-inset`: **32px**, 600px 이하 **16px**. `--t-gutter`: **32px**, 900px 이하 **24px**, 600px 이하 **16px**. `--t-section-y`: **80px**, 900px 이하 **48px**. 구역 padding과 내부 gap을 분리해 중복 간격을 없앤다.
- `SectionHead`를 일반 구역·소식·상담 신청 칸에서 공유한다. 목록 머리는 12칸 중 글 8칸 / 행동 4칸, 사진 옆 글·하루 일과 옆 글은 한 열이다. 900px 이하에서 머리의 행동은 설명 아래에 놓인다. 기존 편집 경로·읽기 순서는 유지한다.
- 배경 띠는 내용에 좌우 여백을 추가하지 않고 가상 요소로 바깥까지 칠한다. `--t-bg`와 `--t-accent-soft`를 교차한다. CTA·인용은 강조 띠, 첫 배너는 기존 사진 표현을 유지한다.
- 일반 카드·사진·소식은 `data-count`·`data-columns`와 CSS flex 줄바꿈으로 마지막 줄까지 채우고 사진은 **4:3**으로 맞춘다. 4의 배수는 4열, 나머지 중 3의 배수는 3열, 나머지 짝수는 2열, 5·7개 같은 수는 3열로 시작해 마지막 줄의 항목끼리 남은 폭을 나눈다. 0개는 빈 목록, 1개는 전체 폭이다. `TagFilter`는 분류를 바꿀 때 숨김 상태와 보이는 수·열 힌트를 함께 갱신하며 저장 자료는 바꾸지 않는다. 제목·설명은 최소 **2줄 / 3줄** 높이를 확보하되 긴 내용은 자르지 않는다. 멘토 카드의 글 칸도 늘려 밑선을 맞춘다. 사진 콜라주, 큰 첫 작품, 가로 사진·글 행은 기존 variant의 의미를 유지하며 전체 폭·간격만 공유한다. 카드 전체가 링크여도 사진·글 행이 유지된다.
- 첫 화면의 글·사진은 **6칸 / 6칸**. 이야기형 행사 카드는 사진 안쪽 24px에 놓고, 900px 이하에서는 글 → 사진 → 행사 순서로 겹침 없이 쌓는다.
- 머리글은 학교 이름 / 줄바꿈 가능한 메뉴 / 언어 / 주요 행동 순서다. 기존 `profile.visit`를 우선하고, 별도 행동이 없지만 연락 정보가 있으면 바닥글의 연락 칸으로 안내한다. 구조화된 연락 정보가 없는 기존 템플릿은 저장된 바닥 안내를 연락 칸에 그대로 표시한다(전화·메일을 문자열에서 추출하거나 새로 저장하지 않음). 메뉴는 900px 이하에서 접히며 기존 Enter·Escape·바깥 누르기 동작을 재사용한다.
- 바닥글은 **4 / 2 / 2 / 4칸**, 태블릿은 2열, 휴대폰은 1열이다. 주소·지도는 독립 칸이다. 메뉴에도 기존 `menu` 번역 제목을 두고 연락·주소 제목과 위쪽을 맞춘다. 메뉴 링크는 최소 높이 **24px**(`--t-space-5`), 사이 간격 **8px**(`--t-space-2`)이며 제목 아래 총 간격은 **12px**이다. 메뉴 밑줄은 hover 때만 표시하며 초점 표시는 유지한다.
- **campus·dawn 제외:** 100차 CSS의 모든 선택자에 두 테마 제외 조건이 있다. dawn의 주소는 다시 연락 칸 첫 문단에 두고, 새 h3·주소 칸·연락 행동은 `kit` 분기에서만 만든다. `SectionHead`가 추가한 `data-layout`은 키트 CSS에서만 읽는다.
- 메뉴 이름·쪽 구성·저장 형식·마이그레이션·시드는 수정하지 않았다. 현재 저장 형식에는 하위 메뉴가 없으므로 2단 메뉴 데이터 추가·쪽 재편은 하지 않았다.

### 검증과 남은 확인

- `tests/site-layout.test.ts`: dawn 원래 바닥 구조, campus·숨은 쪽, 키트 3종의 연락 행동·기존 행동 우선, 12쪽 렌더·자료 불변, CSS 제외·간격 규칙에 보이는 수별 열 선택·렌더 속성·메뉴 제목·간격 검사를 더해 **21개**. `test:unit`에 포함했다.
- 일회성 비교: **초안 이전 `0b2122b`**의 `SiteFrame`·`SiteBlocks`와 현재 코드를 대표 12쪽 × campus/dawn으로 렌더링했다. 키트 전용 `data-layout` 속성을 제외한 **24개 HTML이 동일**했다. 100차 이전 CSS는 빈 줄 외에 동일하다. 픽셀 비교를 대신하는 증거는 아니다.
