# 0051. 차시·결정 기록·마이그레이션 번호는 관제 센터가 나눠 준다

- 상태: 채택
- 날짜: 2026-11-28
- 제안: Claude(학사 시스템 개발 전담 세션)
- 결정: 사용자(2026-11-28) "차시 번호 미리 나눠 주는 규칙 PR 올려"
- 관련: ADR 0015(관제 센터), 0024(관제 = 전체 관리자), `docs/COLLABORATION.md` 2절

## 배경
- 세션마다 일을 시작할 때 'main에서 가장 큰 번호 + 1'로 차시 번호(`N차`, `docs/rounds/round-N.md`)·ADR 번호·마이그레이션 접두어를 골랐다. 여러 세션이 동시에 일하면 같은 번호를 고르고, 병합 직전에야 부딪쳤다.
- 2026-11-28 하루에만 여러 번 겹쳤다(115→116→118, 121→123→125, 126→127, 128→130→131, 마이그레이션 001400→001500). 그때마다 파일 이름·본문·PR 제목·주석을 고쳐야 했고, 다른 세션의 표기를 실수로 고친 일도 있었다.

## 고려한 안
| 안 | 내용 | 장점 | 단점·위험 | 비용 |
| --- | --- | --- | --- | --- |
| A | 관제 DB가 번호를 나눠 줌(`POST /api/control/numbers`), 세션은 본 가장 큰 번호(floor)를 함께 보냄 | 동시에 받아도 겹치지 않음(잠금). 사람 손이 안 듦. 저장소를 모르는 DB도 floor로 이미 쓰인 번호를 피함 | 관제 API에 닿지 못하는 환경은 받지 못함(번호 없이 진행 후 PR 전에 받기) | 표 1개, 함수 2개, 스크립트 1개 |
| B | 관제 세션이 사람처럼 대화로 번호를 배정 | 새 코드 없음 | 관제가 바쁘거나 자리에 없으면 멈춤(ADR '승인을 기다리며 멈추지 않는다'와 어긋남) | 관제 시간 |
| C | PR 번호를 차시 번호로 씀 | 겹치지 않음 | PR 전에는 번호가 없음. 차시가 띄엄띄엄(221차 등), 기존 문서 규칙과 다름 | 문서 규칙 다시 씀 |
| D | 지침에 '최신 main을 받고 정하라'만 강조 | 바로 됨 | 지금까지 그렇게 했는데도 겹침(동시 작업은 main에 없음) | 없음 |

## 결정
A를 채택한다.
- 표 `public.control_numbers(kind, value, session_id, title, reserved_at)`: 플랫폼 운영 기록(학교 자료 아님). 고치기·지우기 막음. 사람은 전체 관리자만 읽음.
- `control.reserve_number(token, {kind, session, title, floor})`: 종류별 잠금 뒤 `greatest(지금까지 준 최대, floor) + 1`(마이그레이션은 오늘 UTC 날짜 + 100 단위). `control.numbers(token, kind)`: 최근 30개.
- `npm run number -- <round|adr|migration> "<제목>"`: main과 모든 원격 브랜치에서 floor를 세어 함께 보낸다. 세션 id는 환경에서 읽는다. 토큰은 프록시가 붙인다.
- 받은 번호를 쓰지 않으면 빈 번호로 둔다. 번호가 이어지지 않아도 된다.

## 결과
- 승인하면 바뀌는 것: 세션이 번호를 직접 정하지 않고 관제에서 받는다(세션 시작 점검 6단계).
- 안 바뀌는 것: 기존 차시·ADR·마이그레이션 번호와 파일, 학교 자료.
- 되돌리는 길: `docs/COLLABORATION.md` 2절 '번호 받기' 줄을 지우면 예전 방식으로 돌아간다. 표는 남아도 해가 없다.
- 다시 검토할 조건: 번호 충돌이 다시 생기거나, 관제 API에 닿지 못하는 세션이 늘 때.
