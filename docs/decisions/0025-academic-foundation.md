# 0025. 학사 토대: 사건 원장 · 마감 판 · 출력 프로필 · 학교 정의 확장

- 상태: **제안** (사용자 검토 후 채택. 채택 전에는 구현하지 않는다)
- 날짜: 2026-11-25
- 제안: 관제 세션(Claude)
- 근거: `docs/research/sis-rea-2026-11.md`(종합)와 `docs/research/sis-rea/` 갈래 보고서 4편, ADR 0001·0004·0008·0012~0016·0024, 드리미포털 학생부 진단(`docs/research/portal-gradebook-review.md`)
- 관계: ADR 0004(도메인 모델 정규화, 안 B)를 **대체하지 않고 확장**한다. 0004의 5단계 중 1·2단계(사람·학사 차원·수업)는 구현됐고, 3~5단계(평가·마감·발행·학생·보호자)를 이 ADR의 틀로 구현한다.
- 표기: 사실(근거 문서) / 추정 / 확인 필요.

## 1. 문제
학사정보 시스템은 기능(성적, 출결, 학생부, 동아리, 상담…)을 하나씩 붙이면 무너진다.
- 드리미포털 학생부가 그렇게 자랐다(구현하면서 설계를 다듬음). 같은 개념이 여러 표에 생기고, 이름 문자열로 잇고, 사고가 날 때마다 예외 규칙이 붙는다.
- 오픈소스 SIS도 같은 흔적을 남겼다. 외래키 0개, `ALTER TABLE` 사용자 필드, 학년도마다 학교 복사, 코드 업로드 확장의 원격 코드 실행 사고가 그 예다(REA 3절).
- 우리는 거기에 더해 **각 학교가 자기 AI로 기능을 만들고 키우게** 하려 한다. 공급사 누구도 하지 않는 일이다(REA 발견 5).

그래서 기능보다 먼저, 모든 기능이 같은 방식으로 올라설 **토대**를 정한다.

## 2. 결정 요약
1. **학사 사실은 모두 '누가(행위자) · 무엇을(사건) · 무엇에 대해(대상·자원)'로 기록한다** — REA(Resources–Events–Agents) 원장 사고. 화면·서식·통계는 이 원장의 투영이다.
2. **시간 축 셋을 섞지 않는다**: 업무 유효 기간(begin/end), 기록 판(version), **마감 판**(closure). 마감 판은 1급 개념이다.
3. **핵심은 작고 형이 정해져 있다.** 학교 차이는 값·규칙·기록 유형·출력으로 흡수한다. 국가 서식은 **출력 프로필**이다.
4. **학교의 AI는 코드가 아니라 '정의(definition)'를 만든다.** 기록 유형·코드·규칙·양식·흐름·출력의 판을 '기능 꾸러미'로 묶는다. 플랫폼 엔진이 검증·미리보기·실행하고, 사람이 켠다. DDL과 코드 업로드는 없다.

## 3. 원장 모델 (REA로 본 학사)

| REA | 우리 개념 | 예 |
| --- | --- | --- |
| 행위자(Agent) | 사람(`people`)과 그 역할(학생·교직원·보호자·멘토·외부 강사), 학교 | 담임이 출결을 기록, 위원회가 정정을 승인 |
| 사건(Event) | 날짜가 있는 사실 하나. 추가만 하고, 정정은 원 사건을 가리키는 새 사건 | 입학·전학, 수강 신청·배정, 출결, 평가 결과, 서술, 증거 제출, 확인(서명), **마감**, **발행** |
| 자원(Resource) | 사건이 쓰거나 만드는 것 | 수업 자리(정원), 학점·이수, 역량 성취, 발행 문서, 산출물 파일 |

- **쌍대성(duality)**: 수강 배정은 자리를 쓰고, 이수 판정은 학점을 만든다. 학점·이수 합계는 언제나 사건에서 다시 셀 수 있어야 한다. 트리거로 덮어쓴 합계를 원본으로 삼지 않는다(openSIS 교훈).
- 이 틀을 쓰는 이유: 학교가 새 기능을 만들어도 결국 '누가 무엇을 언제 했다'는 사건이다. 같은 꼴이면 권한(누가), 감사(언제·무엇), 마감(그때 값), 출력(투영)이 기능마다 따로 생기지 않는다.

## 4. 핵심 층 (플랫폼 소유, 모든 표 `school_id` + RLS + 복합 FK)

✔ 있음 / ＋ 추가 / △ 보강. 표 이름은 가칭이고 구현 PR에서 확정한다.

| 층 | 내용 | 표 |
| --- | --- | --- |
| L0 학교·계정 | 테넌트, 계정, 소속 권한 | ✔ `schools` · `memberships` · `person_accounts` |
| L1 학사 구조 | 학교급, 학년도, **학기 나무**(학기·텀·평가기간, `parent_id`·`kind`·입력 창), 반·기수, 수업일(나중) | ✔ `school_levels` · `academic_years` · `cohorts` · `homerooms` / △ `terms`(나무) / ＋ `calendar_days` |
| L2 사람·관계 | 사람, 이름 이력, **외부 식별자**, 학적(기간 행 + 사유 코드), **가족·보호자 관계**, **교직원 배정** | ✔ `people` · `person_names` · `enrollments_school` / ＋ `external_identifiers` · `families` · `guardian_links` · `staff_assignments` |
| L3 배움의 틀 | 과목(판), 갈래 규칙(판), 개설(**기원**: 학교 개설·학생 제안·프로젝트·인턴십), 담당·수강(기간·역할), **수업 제안 판**, **역량 틀**(CASE 모양) | ✔ `subjects` · `course_types` · `course_offerings` · `offering_staff` · `offering_enrollments` / ＋ `course_proposals` · `competency_frameworks` · `competency_items` · `competency_links` · `rubrics` |
| L4 사건 원장 | 출결 사건, 평가 항목, 결과(점수·등급·수준·P/F·서술 — `result_kind`), 서술(작성자 역할), 증거물(파일·링크), 확인·서명(위원회·멘토·결재를 한 경로로) | ＋ `attendance_events` · `assessments` · `assessment_results` · `narratives` · `evidence_items` · `attestations` |
| L5 규칙 | 학교별 **코드 목록**(표준 사상·유효 기간·이전 코드), 척도 판, 계산 규칙 판(가중치·반올림·출결 환산·글자 수) | ＋ `code_lists` · `scales` / △ `school_settings`(판) |
| L6 마감·발행 | **수업 마감 판**(모집단·결과·통계를 그때 값으로), **학년도 기록 마감 판**, 정정 판(이전 판 FK·사유·승인), 발행본 스냅샷, **출력 프로필**(서식별 매핑·변환·가림 판) | ＋ `offering_closures` · `record_closures` · `output_profiles` / ✔ `published_documents` · `document_templates` |

원칙:
- 사람·수업·과목·학교는 id로만 참조한다(지침 7). JSON 안에 참조를 숨기지 않는다.
- 사건 행은 추가만 한다. 정정 사건은 `corrects_id`로 원 사건을 가리킨다. 현재 값은 뷰나 계산 캐시로 둔다.
- 마감 판은 적용한 규칙·척도·코드 판 id를 고정한다. 정정은 이전 판을 가리키는 새 판이고, 한 판에서 두 후속 판이 갈라지지 않는다(ADR 0004 B3).
- 국가 제도(성취평가제 A–E, 석차등급, 태국 0–4·มส·ร, 고교학점제 이수 기준)는 **척도·코드·계산 규칙 판 + 출력 프로필**로 들어온다. 핵심 표에 열로 박지 않는다.
- 민감 식별자(주민번호·국가 ID)는 핵심에 두지 않는다. 필요하면 별도 비공개 확장 + 접근 정책 ADR로 둔다(지침 9).

### 4-1. 드리미포털 학생부에서 배운 것 (`docs/research/portal-gradebook-review.md`)
- **표기는 판이다**: 학생부 과목명은 '대학 제출용 표기'이고 바꾸는 것이 정상 실무다. 학생부 행 = 개설 id + 과목 표기 판 id(ADR 0004 P5 `subject_labels`)를 F2에서 구현한다. 표기를 바꿔도 모집단·통계는 그대로다.
- **자료 단위를 정의에 둔다**: 성적·수상은 학기, 창체·봉사·자격증은 학년도처럼 기록 유형마다 자료 단위(학기·학년도·수시)를 정의 속성으로 두고, 마감 판이 그 단위를 따른다. 포털은 학기 키 하나에 연 단위 자료를 묶었다가 학기를 넘기며 그 해 기록이 사라졌다.
- **규칙은 DB에, 계산은 판 + 경계값 시험**: 포털은 SQL 함수 0·트리거 1이라 앱 밖 경로를 막지 못한다. 마감·정정·참조는 DB 제약·트리거·명령 함수로, 계산 규칙(반올림·분할점·가중치)은 판 + 경계값 시험으로 둔다.
- **규칙 판에 '왜' 칸**: 사고에서 나온 규칙은 밖에서 비일관으로 보인다. 규칙·설정 판에 결정 근거(결정자·사고·날짜)를 두고, 학교 AI가 규칙 변경을 제안할 때 이 칸을 먼저 읽게 한다.
- **양식은 렌더 판, 자료는 하나**: 구양식을 '전환 중'으로 두면 화면·도구가 두 벌이 된다. 발급 당시 양식은 출력 프로필·템플릿 판으로 고정하고 자료 모델은 하나로 둔다.
- **자국은 모든 판 표에**: 학생과 무관한 정의(과목·가중치·표기·마감)의 변경도 판·행위자·사유로 남긴다.
- **학교의 정상 실무를 AI에게 알린다**: 포털 AI가 표기 변경을 '위조'로 거절한 사고가 있었다. 학교 AI 연결 글(ADR 0022)에 그 학교의 정상 실무 목록을 싣는 자리를 둔다.

## 5. 확장 사다리 — 학교(와 학교의 AI)가 기능을 만드는 방법

| 단 | 무엇을 바꾸나 | 예 | 누가 · 어떻게 |
| --- | --- | --- | --- |
| E1 값 | 코드 목록에 학교 값 | 출결 사유, 관계, 결과 수준, 갈래 | 학교 관리자·학교 AI(범위 토큰). 즉시, 판으로 |
| E2 규칙 | 판이 있는 규칙·척도(결정 근거 '왜' 칸 포함) | 가중치, 반올림, 글자 수, 출결 환산, 자료 단위 | 학교 관리자 승인으로 새 판. 마감 판은 옛 판을 고정. AI는 '왜' 칸을 읽고 제안 |
| E3 기록 유형 | **학교 정의 기록**: 필드 정의(JSON Schema 판) + 일반 기록 표에 값 | 창체·독서·봉사·신앙생활·상담·동아리·프로젝트 일지 | 학교 AI가 정의 판을 만들고 플랫폼 검증기를 통과한 뒤 관리자가 켬. 사람·수업 참조는 정해진 열(`person_id`, `offering_id`, `term_id`)로만 |
| E4 화면·출력 | 양식, 목록 보기, 출력 템플릿 | 학생 관찰 기록 양식, 반별 요약, 자체 학생부 | 정의 판 → 플랫폼 렌더러. 미리보기는 합성 자료로 |
| E5 흐름 | 선언형 상태 흐름 | 초안 → 검토 → 승인 → 마감, 학생 수업 제안 → 승인 | 정의 판 → 플랫폼 흐름 엔진. 상태 전환은 사건 |
| E6 모듈 승격 | 여러 학교가 같은 E3 유형을 쓰면 형이 정해진 핵심·모듈 표로 승격 | 출결, 평가처럼 | 관제 세션이 ADR + 마이그레이션으로 |

**기능 꾸러미**: 하나의 기능은 E1~E5 정의 판을 묶은 꾸러미다.
- 예: '프로젝트 수업 기록' = 기록 유형 + 코드 + 양식 + 흐름 + 출력.
- 꾸러미 판을 켜고 끄고 되돌릴 수 있다. 다른 학교와 나눌 수 있다(나중).

**학교 AI의 작업 순서**(ADR 0012~0016 범위 토큰을 정의 종류로 넓힌다):
1. **명세**: 학교 요구를 꾸러미 초안으로 쓴다.
2. **검증**: 플랫폼 검증기가 확인한다.
   - 스키마 형식
   - 숨은 참조 금지
   - 개인정보 등급 표시(필드마다: 공개·학교·교직원·민감)
   - 핵심 규칙(마감·정정)을 바꾸지 않는지
   - 이름 충돌
3. **미리보기**: 합성 자료로 화면·출력을 미리 본다.
4. **켜기**: 학교 관리자가 켠다. 켜는 것은 사람이고, AI는 초안까지만 만든다(자동 켜기는 범위 밖, 새 ADR 필요).
5. **기록**: 모든 정의 변경은 판이며 `base_version` 409를 따른다. 사용량·활동은 기존 기록에 남는다.

하지 않는 것:
- 에이전트의 DDL
- 코드·스크립트 업로드(RosarioSIS 원격 코드 실행 교훈)
- 핵심 표 열 추가형 사용자 필드
- 학교가 마감·정정 규칙 자체를 끄는 것

## 6. 출력 프로필 (국가·학교 서식)
- 하나의 원장에서 서식별 스냅샷을 낸다.
- 출력 프로필 판이 하는 일: 필드 매핑, 코드·척도 변환, 글자 수 검사, 가림 규칙.
  - 예: KR 학생부(인가), KR 대안학교 자체 학생부 + 교육과정 편제표, TH ปพ.1/ปพ.5, OPEC REGIS 명단, CLR 2.0/OB 3.0, Mastery 형식.
- 변환에서 정보가 빠지거나 규칙이 충돌하면 질문을 연다(지침 6).
- 국가 시스템(NEIS·DMC)의 원본은 국가 쪽이다. 우리 출력은 기본적으로 보조부·제출용 자료로 다룬다.

## 7. 다른 안
| 안 | 판단 |
| --- | --- |
| 오픈소스 SIS를 들여와 고치기(Gibbon·Frappe) | 외래키 없음·이름 PK·단일 학교 구조라 우리 경계(RLS·복합 FK·마감 판)를 덧대기 어렵다. 패턴만 가져온다 |
| Ed-Fi·CEDS를 내부 스키마로 그대로 | 초일반화·복합 자연 키·미국 제도 중심. 교차표로 정렬만 하고 어댑터로 내보낸다 |
| 학교별 스키마(학교가 표를 만듦) | RLS·마이그레이션·보안 검토가 학교 수만큼 늘어난다. E3 기록 유형 + E6 승격으로 대체 |
| 전면 이벤트 소싱 | 재생·스키마 진화 부담(ADR 0004 B1). 사건 원장은 업무 사실에만, 현재 상태는 관계형 + 마감 판 |

## 9. 위험과 대응
- **정의 엔진이 '두 번째 데이터베이스'가 될 위험**: E3 값이 많아지면 질의·통계가 어렵다. 대응은 셋이다.
  - 사람·수업 참조는 열로만 둔다.
  - 통계가 필요한 유형은 E6 승격 기준을 정한다(예: 3개 학교 이상 사용, 또는 마감 판 대상).
  - E3 값은 마감 판 대상에서 기본 제외하고 승격 후 포함한다.
- **AI가 만든 정의의 품질**: 검증기(형식·개인정보 등급·숨은 참조)와 합성 자료 미리보기를 통과해야 하고, 켜는 것은 사람이다.
- **관제 권한 집중**(ADR 0024): PowerSchool 2024 유출 교훈. 대응은 다음과 같다.
  - 점검 토큰 기한을 짧게 유지
  - 학교 입장·변경 기록
  - 전체 관리자 대시보드에 관제 활동 요약
  - 이상 활동 알림(다음 차시 후보)
- **표준·국가 규정 변경**: 출력 프로필과 규칙을 판으로 관리하고, 원문 재확인 목록(REA 5절)을 연 1회 점검한다.
