# 0019. 규모 설계: 학교 100곳·1,000곳까지 Vercel · Supabase · Cloudflare R2

- 상태: 제안(단계 A1은 채택·구현, 나머지는 단계마다 결정)
- 날짜: 2026-11-24
- 제안: 사용자 지시 — "나중에 학교가 100개, 1000개가 되더라도 이 Vercel, Supabase, Cloudflare 구조를 유지하면 되는가? 미리 설계를 탄탄히 하자."
- 결정: 사용자(단계별), 설계는 관제 세션(Claude)
- 관계: ADR 0004(데이터 모델)·0013(학교 AI 작업 공간)·0015(관제 센터)·0018(R2·사용량). 근거 자료 `docs/research/storage-cost-2026-11.md`.
- 표기: **사실**(출처) / **추정**(가정에 따른 계산) / **확인 필요**. 가격·한도는 2026-11 웹 확인값이고 바뀔 수 있다.

## 1. 결론
**세 서비스 구조는 1,000곳까지 유지할 수 있다.** 다만 지금 모습 그대로는 아니다. 서비스 자체의 한계보다 아래 여섯 가지가 먼저 막는다.

| # | 막히는 것 | 언제 | 이유(지금 코드·계약 기준) |
| --- | --- | --- | --- |
| 1 | **Vercel 약관** | 첫 유료 학교 전 | Hobby는 비상업 개인 용도만, 상업 이용은 Pro 이상(사실). 하루 배포 100회(Pro 6,000회)도 이미 한 번 걸림 |
| 2 | **공개 홈페이지가 방문마다 DB 조회** | 학교 수십 곳·방문 증가 | 공개 쪽이 모두 `force-dynamic` → 방문 1회 = 함수 실행 + DB 질의. 학교 1,000곳이면 비용·연결의 대부분이 여기서 나옴 |
| 3 | **DB 연결 수** | 동시 접속 증가 | 함수 인스턴스마다 pg 풀 5개. Supabase 풀러 클라이언트 한도는 Micro 200·Small 400·Medium 600·Large 800(사실) |
| 4 | **빌드 안에서 운영 DB 마이그레이션 + 미리보기가 운영 DB 공유** | 지금도 | 11-23 운영 배포 실패 2번이 모두 빌드 중 마이그레이션. 미리보기 DB 분리 전엔 운영 DB로만 시험 가능 |
| 5 | **학교 단위로 떼어 내기(내보내기·삭제·이전)** | 첫 학교 이탈·개인정보 요청 | DB는 모든 표에 school_id가 있어 가능. R2 키가 학교와 무관(`sha256/…`)하면 학교 파일만 지울 수 없음 → **지금 고침(A1)** |
| 6 | **운영 방식: 학교마다 Claude 세션** | 학교 수십 곳 | 세션 하나에 하루 수~수십 달러(사용량 기록 기준 추정). 1,000곳에 상주 세션은 불가. 학교 일은 학교의 에이전트·대화창으로, 관제는 공통 일만 |

## 2. 규모별 모습 (추정)
가정: 학교 1곳 = 계정 30명, 파일 2GB, 공개 홈페이지 월 2,000회 방문, 파일 제외 DB 50MB.

| | 지금(3곳) | 100곳 | 1,000곳 |
| --- | --- | --- | --- |
| 계정(Supabase Auth 포함 MAU 10만, 사실) | 수십 | 약 3,000 | 약 30,000 — 포함분 안 |
| DB(파일 제외) | 수십 MB | 약 5GB — Pro 포함 8GB 안 | 약 50GB — 초과 42GB ≈ $5/월 |
| R2 파일 | 0 | 약 200GB ≈ $3/월 | 약 2TB ≈ $30/월, 내려받기 무료 |
| 공개 방문 | — | 월 20만 | 월 200만 — **캐시가 없으면 함수 200만 회·DB 질의 수백만 회** |
| DB 컴퓨트 | Micro | Small~Medium($15~60) | Large($110) 이상, 필요하면 읽기 복제 |
| Vercel | Hobby | Pro $20/좌석 + 사용량 | Pro + 사용량(캐시 여부에 크게 좌우) |
| 월 합계(AI 제외) | $0~25 | **약 $60~110** | **약 $200~500** (학교당 $0.2~0.5) |

- 1,000곳 금액 폭이 큰 것은 대부분 2번(공개 페이지 캐시) 때문이다. 캐시를 하면 아래쪽, 안 하면 위쪽 또는 그 이상.
- AI(앱 안 대화형 편집 등)는 학교별 사용량으로 따로 잡는다(`usage_events`, ADR 0018). 학교별 한도 없이 열면 가장 큰 변수.

## 3. 단계별 설계

### 단계 A — 지금(학교 10곳 전, 무료·저비용)
| | 할 일 | 상태 |
| --- | --- | --- |
| A1 | **R2 키에 학교 경계**: `s/<school_id>/<sha256>`. 같은 학교 안에서만 중복 제거. 학교 이탈 때 접두어로 내보내기·삭제, 학교별 용량을 R2에서 바로 셈. R2에 아직 파일이 없어 지금 바꾸는 비용 0 | **이번에 구현** |
| A2 | **공개 홈페이지 캐시**: 공개 판 기준으로 페이지를 캐시하고, 공개·내림·설정 저장 때만 그 학교 캐시를 지운다(Next 캐시 태그 `site:<school_id>`). 방문은 DB를 거의 안 건드림 | 다음 차시 |
| A3 | **DB 연결**: 함수당 풀 크기를 줄이고(1~2) 유휴 연결을 빨리 닫음, 풀러(6543 트랜잭션 모드) 유지. 사용량 화면에 연결 수 표시 | 다음 차시 |
| A4 | **마이그레이션을 빌드 밖으로**: 병합 → GitHub Actions가 운영 DB에 적용(운영 조건 흉내 시험 통과 후) → 성공하면 배포. 미리보기용 DB(Supabase 무료 프로젝트 또는 브랜치) 분리 | 결정 필요(외부 설정) |
| A5 | **학교 떼어 내기 절차**: 학교 하나의 DB 행·R2 파일 내보내기(zip)와 삭제(되돌릴 수 없음 → 두 단계 확인). 한국 개인정보보호법·태국 PDPA 요청 대응 | 설계 후 구현 |

### 단계 B — 첫 유료 학교 전(약 10~30곳)
- **Vercel Pro 전환**(약관). $20/좌석/월. 관제 센터 결정 요청으로 올림.
- 백업: Pro 기본 일일 백업 7일 보관(사실). 시점 복구(PITR)는 $100/월(사실) — 학교 수·계약 조건 보고 결정.
- 오류 알림: Vercel 로그·관측 기능 먼저(결제처 늘리지 않음).
- 학교별 사용량 상한·경보(AI 월 한도, 파일 용량).

### 단계 C — 100곳 전후
- DB 컴퓨트 Small→Medium. 느린 질의 점검(학교 id로 시작하는 인덱스, RLS 함수 호출 횟수).
- 백그라운드 작업 줄(DB 표 + Vercel Cron): 메일·정리·사용량 집계를 요청 경로 밖으로.
- 학교 도메인(예: `www.학교.kr`): Vercel Pro는 프로젝트당 도메인 사실상 무제한(소프트 한도 10만, 사실) → Vercel로 처리. Cloudflare for SaaS(100개 무료, 이후 $0.10/개, 사실)는 Vercel로 안 될 때만.

### 단계 D — 1,000곳 전후
- DB 컴퓨트 Large 이상, 공개 읽기가 많으면 읽기 복제(유료 추가 기능, 가격 확인 필요).
- **셀 나누기 준비**: 모든 표에 school_id, 학교 간 참조 없음(복합 외래키) → 학교 묶음을 다른 Supabase 프로젝트로 옮길 수 있다. 앱에 '학교 → 셀' 표 하나를 두는 방식. 국가별 데이터 보관 요구(태국·한국)나 한 DB 한계가 보일 때 착수.

## 4. 바꾸지 않는 것 (지금 설계가 이미 버티는 부분)
- 학교 경계: 모든 표 school_id + RLS(AGENTS.md 1·3), 학교 간 참조 차단(복합 외래키). 셀 나누기·학교 떼어 내기의 바탕.
- 판으로 쌓기·발행본 스냅샷: 캐시하기 좋다(공개 판은 바뀌지 않으므로 공개 때만 지우면 됨).
- 파일은 R2(ADR 0018): 내려받기 무료가 규모에서 가장 큰 절약.
- 외부 에이전트는 범위 토큰(ADR 0012~0016): 학교가 자기 구독으로 일하므로 학교 수가 늘어도 플랫폼 AI 비용이 비례해 늘지 않는다.

## 5. 다른 안을 본 결과
| 안 | 판단 |
| --- | --- |
| AWS 등으로 직접 운영(RDS·S3·ECS) | 1,000곳 규모에서도 월 비용 차이는 수백 달러 안쪽(추정)인데 운영 부담이 큼. 1인 운영에 맞지 않음 → 기각, 셀 단계에서 다시 봄 |
| 학교마다 Supabase 프로젝트 | 격리는 최고지만 마이그레이션·요금·관리가 학교 수만큼 → 기각(셀 단위 묶음만 허용) |
| Supabase Storage로 파일 | 결제처는 줄지만 내려받기 $0.09/GB 초과 → 기각(ADR 0018) |
| Cloudflare Pages/Workers로 앱 이전 | Next 서버 기능 호환·이전 비용 대비 이득 불명확 → 보류 |

## 6. 확인 필요
- 지금 Supabase 프로젝트가 무료인지 Pro인지(점검 화면으로는 안 보임). 무료 요금제는 7일 비활성 시 일시 정지됨.
- 학생 개인정보의 국외 저장(DB: 도쿄 ap-northeast-1, R2: 위치 힌트) — 한국·태국 법률 검토는 전문가 확인 필요(이 문서는 법률 자문이 아님).
- 위 가격·한도는 공식 페이지에서 계약 전에 다시 확인.
