# 0002. 로그인: Supabase Auth(Google) 확인 후 앱 세션

- 상태: 채택 · 날짜: 2026-11-22 · 제안: Claude · 결정: 사용자(16차 "Google 로그인")

## 배경
14차는 로컬 테스트를 위해 자체 이메일·비밀번호 로그인을 만들었다. 16차에 Google 등 외부 계정 로그인이 필요해졌다.

## 고려한 안
| 안 | 내용 | 단점 |
| --- | --- | --- |
| A | Supabase Auth가 Google 인증 → 서버가 토큰을 Supabase에 확인 → 초대된 이메일만 앱 계정과 연결 → 앱 서명 세션 쿠키 | 세션이 두 곳(Supabase·앱)에 걸침 |
| B | 앱이 직접 OAuth(Auth.js) | 초대·재설정·시도 제한을 직접 구현 |
| C | 앱 전체를 Supabase 클라이언트·PostgREST로 전환 | 지금의 RLS 트랜잭션 구조를 크게 바꿔야 함 |

## 결정
A. 비밀 키 없이 공개 키로만 확인한다. 같은 이메일이라도 다른 외부 계정이면 연결하지 않는다. 세션 서명 키는 DB가 만들어 보관한다. 예시 계정의 비밀번호 로그인은 개발·검토용으로 남긴다.

## 다시 볼 조건
학교 수·사용자 수가 늘어 세션 철회·다중 기기 관리가 필요할 때, 또는 Supabase Realtime·Storage를 브라우저에서 직접 쓸 때(안 C 재검토).
