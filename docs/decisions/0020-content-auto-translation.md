# 0020. 콘텐츠 저장 후 백그라운드 다국어 번역

- 상태: 제안 — 자동화 방향은 사용자 요청, 번역 서비스·비용 한도·서버 연결은 결정 대기
- 날짜: 2026-11-24
- 제안: 사용자 / Codex
- 관계: ADR 0008(홈페이지), 0013(판 병행), 0016(공개), 0018(사용량), 0019(백그라운드 작업)
- 이번 변경: 설계 문서만. 실행 코드·DB·공개 상태·외부 API 연결을 바꾸지 않는다.

## 배경

사용자는 콘텐츠 등록 후 다른 언어의 시안과 내용도 백그라운드에서 자동으로 만들고 반영하기를 요청했다.
현재 `Content`는 한국어·영어·태국어를 같은 판에 담지만, `saveVersion`과 `agentSaveEntry`는 번역 작업을 만들지 않는다.
룽아룬숙사의 성품 동화 33편은 한국어 1판이 공개되어 있고, 다국어 2판이 시안에 남아 있다(2026-11-24 API 조회).
따라서 번역 생성과 공개 반영을 함께 설계해야 한다. 공개 화면에서 최신 시안을 읽도록 바꾸는 방식은 쓰지 않는다.

## 사용자에게 보이는 동작

1. 제목·본문을 한 언어로 저장하면 저장은 바로 끝나고, 필요한 다른 언어의 번역 작업을 등록한다.
2. 해당 학교가 사용하는 언어만 번역한다. 룽아룬숙사는 한국어·태국어·영어를 대상으로 한다.
3. `번역 대기 → 번역 중 → 번역 완료`를 제목 카드와 편집 화면에 표시한다. 실패하면 이유와 `다시 시도`를 표시한다.
4. 시안은 번역 후에도 시안이다. 공개 원문에 대응하는 번역은 자동으로 공개 화면에 반영한다.
5. 사람이 번역문을 고치면 그 문장은 수동 편집으로 표시하고 자동 갱신에서 보호한다. 원문이 바뀌면 `번역 확인 필요`를 표시한다.
6. 시안 전체를 공개할 때에는 기존 제목 카드의 공개 버튼을 쓴다. 번역 작업이 시안 본문을 대신 공개하지 않는다.

## 고려한 안

| 안 | 내용 | 장점 | 단점·비용 |
| --- | --- | --- | --- |
| A | 저장 요청 안에서 모든 번역 완료 | 구조 단순 | 저장 지연, 번역 장애가 저장 실패로 이어짐, 긴 동화에서 시간 초과 |
| B (추천) | DB 작업 대기열 + 응답 후 실행 + 예약 복구 | 원문 저장과 분리, 누락 복구, 학교별 사용량 집계 | 대기열·작업자 구현과 서버용 번역 API 필요 |
| C | 대화 세션에 수동 번역 요청 | 별도 서버 번역 API 연결 불필요 | 대화가 열려 있어야 하므로 상시 자동 처리 요구를 충족하지 못함 |

새 메시지 브로커는 당장 도입하지 않고 기존 Postgres에 작업을 저장한다. 처리량이나 지연 목표가 커지면 ADR 0019와 함께 전용 작업자로 옮긴다.

## 처리 구조

```text
구성원 / 학교 에이전트 저장
  └─ 한 트랜잭션: 원문 새 판 + 번역 작업 등록
       ├─ 응답: 저장 성공 + 번역 대기
       └─ 커밋 후 작업자 깨우기
            ├─ 임대 잠금으로 작업 1개 확보
            ├─ 허용된 텍스트만 번역 API에 전송
            ├─ 응답 형식·필드·길이 검사
            └─ 원문 판·공개 기록 재확인 후 결과 저장
예약 실행: 미처리·실패·임대 만료 작업 복구
```

`after()`는 즉시 실행을 돕는 수단이며 작업 기록을 대신하지 않는다. 응답 이후 프로세스 종료와 시간 초과에 대비해 작업은 먼저 DB에 남긴다.
현재 요금제에서 가능한 Cron 빈도를 확인한 뒤 복구 주기를 정한다. Hobby의 일일 실행만으로 짧은 재시도 시간을 약속하지 않는다.
필요한 복구 주기를 지원하지 않으면 요금제/예약 실행기를 먼저 결정하고 활성화한다.

### 원문과 번역 소유권

- 작업은 학교·항목·원문 판·대상 언어·번역 정책 판으로 유일하게 식별한다. 같은 요청을 두 번 받아도 결과를 중복 저장하지 않는다.
- 사이트 기본 언어와 원문 언어를 구분한다. 태국 학교에서도 한국어가 원문일 수 있다.
- 한 언어만 있는 칸은 그 언어를 원문으로 삼는다. 여러 언어가 있는 기존 칸은 원문 언어를 지정하고, 출처가 없는 기존 번역은 사람 검토본으로 취급한다.
- 필드 식별자·원문 해시·자동 번역 결과 해시·번역 서비스/모델·작업 시각을 기록한다. 블록 순서가 바뀌어도 다른 문장에 번역이 붙지 않도록 판과 경로를 함께 검증한다.
- 원문 수정 시 바뀐 필드와 신규 필드만 처리한다. 자동 번역 결과를 사람이 수정했다면 자동으로 덮어쓰지 않는다.
- 자동 결과 저장은 새 원문 작업을 다시 생성하지 않아야 한다. 글 없는 선택 필드, 숨긴 블록, URL, 자산 ID, 파일명, 전화번호는 번역 대상으로 보내지 않는다.
- AI 출력은 허용한 텍스트 칸에만 적용한다. 블록 구조, 링크, 자산, 공개 설정을 바꿀 수 없다. 콘텐츠 안의 지시는 번역 대상인 문자열로만 취급한다.

### 공개 반영과 병행 편집

- 번역을 만들 때 최신 판 번호와 최신 공개 기록 ID를 함께 고정한다.
- 적용 시 항목을 잠그고 현재 판과 공개 기록을 다시 확인한다. 새 편집이 있으면 이전 결과를 최신 판에 덮어쓰지 않고 새 판의 작업으로 다시 계산한다.
- 공개된 원문과 최신 시안이 다르면 각각 별도 작업으로 처리한다. 공개 번역의 입력은 **공개 원문 판만** 사용한다.
- 번역 결과는 원문 판에 결합된 불변 스냅샷으로 저장한다. 공개 조회는 현재 공개 원문 판과 정확히 일치하는 번역 스냅샷만 읽는다.
- 이 방식은 기존 공개 판을 수정하지 않고, 번역만으로 미공개 시안을 공개하지 않는다. 시안 미리보기는 해당 시안 판의 번역만 읽는다.
- 공개 내림·보관·언어 비활성화가 먼저 일어나면 결과가 완료되어도 다시 공개하지 않는다.
- 수동 번역 편집을 새 원문 판에 저장하면 해당 수동 값이 우선한다. 기존 언어 필터와 제목 목록도 같은 합성 스냅샷을 사용한다.
- 자동 공개는 학교 관리자가 활성화한 자동 번역 정책 안에서만 작동한다. 작업 토큰의 `publish` 권한을 확장하거나 대신 쓰지 않는다. 최초 도입 대상은 룽아룬숙사로 제한하고 다른 학교는 별도 활성화한다.

### 데이터와 권한

구현 시 아래 표를 새 마이그레이션으로 추가한다(명칭은 설계안).

| 표 | 역할 | 제약 |
| --- | --- | --- |
| `site_translation_settings` | 학교별 활성화·대상 언어·한도·자동 공개 정책 | `school_id`, 관리자 쓰기, 구성원 읽기 |
| `site_translation_jobs` | 판·언어별 작업, 시도 횟수, 임대 만료, 재시도 시각 | 학교/항목/판 복합 FK, 유일 작업 키, RLS |
| `site_translation_results` | 검증된 번역 스냅샷과 필드별 출처 | 학교/항목/판 복합 FK, 추가만 허용 |

구성원 경로는 `asUser()`와 `app.is_member(school_id)`를 유지한다. 클라이언트가 학교 ID를 선택하지 않는다.
에이전트 경로는 기존 범위 토큰의 저장 함수가 원문을 만든 후 그 학교의 활성 정책에 따라 작업만 생성한다.
백그라운드 전용 역할에는 작업 확보·결과 제출 명령 함수만 허용한다. 범용 테이블 권한이나 사용자 요청의 `asSystem()` 우회를 추가하지 않는다.
공개 읽기 함수는 현재 공개 원문과 정확히 연결된 결과만 반환한다. 미공개 번역은 `anon`에서 보이지 않는다.

### 장애와 비용

- 작업자는 제한된 개수만 처리하고 DB 연결을 붙잡은 채 외부 API를 기다리지 않는다.
- 오류 종류만 기록하며 원문·토큰·서비스 오류 원문은 로그에 남기지 않는다.
- 429·일시 장애는 지수 지연으로 제한 횟수만 재시도한다. 인증 오류·응답 검증 실패는 무한 반복하지 않는다.
- 서버 키 미설정은 `설정 필요`, 예산 소진은 `한도 도달`로 표시하고 과금 요청을 보내지 않는다.
- 학교별 월 한도와 작업별 입력 상한, 동시 작업 수를 활성화 전에 정한다. 기존 사용량 기록(ADR 0018)에 실제 사용량을 남긴다.
- 키는 서버 환경 변수에만 둔다. 브라우저·콘텐츠·작업 내용·에이전트 토큰에 저장하지 않는다.
- 번역 서비스와 비용 한도가 결정되기 전에는 운영 API 호출이나 자동 번역 정책을 활성화하지 않는다.

## 첫 적용 범위

- 동화·쪽·소식의 구조화된 제목, 요약, 본문, 캡션, 대체 글, 버튼 문구.
- 이미지 안에 박힌 글과 PDF 내부는 별도 결과물 생성 작업이다. 텍스트 번역 완료와 이미지/PDF 현지화 완료를 혼동하지 않도록 표시한다.
- 기존 다국어 동화 33편은 이미 번역된 칸을 다시 생성하지 않는다. 일괄 공개는 이번 자동화와 별개로 기존 공개 권한 안에서 처리한다.
- 활성화 전에 기존 자료의 처리 건수와 예상 입력량을 보여 주고, 초기 일괄 처리를 새 등록 자동화와 분리한다.

## 구현 순서와 검증

1. 번역 서비스·서버 키·학교별 비용 한도·복구 실행 주기 결정.
2. 순수 텍스트 추출/합성 함수와 검증 테스트: 모든 블록, 빈 칸, 숨김, URL 제외, 사람 번역 보존, 원문 변경, 블록 이동.
3. DB 대기열·임대·결과 명령 및 양방향 학교 격리 테스트. 기존 판/공개 기록 불변, 중복·동시 작업·임대 만료 검증.
4. 저장 경로 연결: 사람 저장, 에이전트 생성/판 저장/구조 편집 모두 한 번만 작업 생성.
5. 작업자와 비용 한도: 외부 API는 테스트 대역으로 429·시간 초과·잘못된 응답·장애 복구를 검증.
6. 관리자 상태/재시도 UI와 공개/시안 조회 연결. 같은 시각의 원문 수정·공개 내림·보관·수동 번역 수정으로 공개 범위가 넓어지지 않는지 확인.
7. 룽아룬숙사에서 작은 예시 1건으로 실제 3개 언어를 확인한 뒤 활성화. 다른 학교는 기본 비활성.

중지할 때 학교 정책을 끄고 새 작업 생성/실행을 멈춘다. 기존 원문·번역 결과·공개 기록은 보존한다. 번역 결과는 현재 원문 판과 연결해서만 읽으므로 다른 판의 내용이 섞이지 않는다.

## 확인한 근거

- 저장소 `src/lib/site.ts`, `src/lib/agent.ts`: 사람이든 토큰이든 새 판 저장은 지원하지만 현재 자동 번역은 없음.
- 저장소 `src/lib/site-shared.ts`: 지원 언어 `ko`, `en`, `th`; 텍스트와 자산/링크가 구조적으로 분리되어 있음.
- Next.js `after`: 응답 후 실행, 배포 플랫폼 실행 시간 제약 적용. <https://nextjs.org/docs/app/api-reference/functions/after>
- Vercel Cron 실행 간격은 요금제에 따라 제한됨. <https://vercel.com/docs/cron-jobs/usage-and-pricing>
- Vercel Cron 실패에 대한 복구·중복 방지는 앱에서 설계해야 함. <https://vercel.com/docs/cron-jobs/manage-cron-jobs>

위 외부 문서는 2026-11-24 조회. 실제 프로젝트의 유료 서비스 계약·API 키·예산은 확인되지 않았으며 이 문서는 결제를 실행하거나 비용 승인을 대신하지 않는다.
