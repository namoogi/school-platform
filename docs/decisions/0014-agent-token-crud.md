# 0014. 작업 토큰 권한 확장: 만들기 · 고치기(구조) · 보관, 기한 365일 · 무기한 · 연장

- 상태: 채택
- 날짜: 2026-11-23
- 제안: 사용자 지시(관제 세션·룽아룬숙사 세션 경유)
  - "지금 발급한 토큰 API로는 새 동화 항목을 만들 수 없다는데? 활동 권한을 생성과 수정, 삭제까지 넓혀 줘."
  - "또한 해당 페이지의 구조 변경까지 가능하도록."
  - "외부 작업 토큰 기한 선택지에 365일과 무기한을 추가", "기한 연장 버튼·만료 임박 표시"(학교마다 해마다 다시 발급하는 부담을 줄이려고)
- 결정: 사용자(2026-11-23), 구현 방식은 관제 세션이 정한 방향 + Claude
- 관계: ADR 0012(토큰·명령 함수)·0013(학교 AI 작업 공간)을 넓힌다. AGENTS.md '외부 에이전트'가 범위 확장은 새 ADR로 하라고 정했다.

## 배경
36차까지 토큰은 있는 항목에 새 판을 더하는 것만 했다. 새 동화를 만들거나, 다 쓴 항목을 치우거나, 항목 정보(성품 이름·주인공·순서)를 고칠 수 없었다. 기한도 최대 90일이라 학교가 자주 다시 발급해야 했다.

## 고려한 안
| 안 | 내용 | 장점 | 단점·위험 |
| --- | --- | --- | --- |
| **A. 권한을 발급 때 고름 + 보관은 소프트 삭제 (채택)** | 권한 read·upload·create·edit·archive 를 체크박스로. 삭제는 `archived_at`만 찍고 판·공개 기록·자산은 남김. 공개 중이면 보관 불가 | 필요한 만큼만 연다. 보존 원칙(AGENTS.md 4)을 지킨다. 되살릴 수 있다 | 보관함 화면이 하나 늘어남 |
| B. 실제 삭제 허용 | 토큰이 항목·판을 지움 | 단순 | 판 보존 원칙 위반, 되돌릴 수 없음, 토큰 유출 시 피해가 큼 |
| C. 현행 유지 | 새 항목·정리는 사람만 | 위험 없음 | 지시와 맞지 않음, 사람이 반복 작업 |

기한은 7·30·90에 365일·무기한을 더하고, 연장(값 그대로)을 둔다. 무기한을 아예 막는 안도 생각했지만, 선생님이 직접 원하셨다. 그래서 경고·미사용 표시·폐기로 위험을 줄인다.

## 결정
### 권한 (종류 story·page·news × 주소 × 권한)
| 권한 | 할 수 있는 일 | 함수·API |
| --- | --- | --- |
| read | 목록·최신 판 읽기 | `agent.entries`·`entry` |
| upload | 그림·PDF 올리기 | `agent.upload_asset` |
| create | 새 항목 + 첫 판(시안). 주소 목록이 있는 토큰은 그 목록 안의 주소로만(아직 없는 주소를 미리 정할 수 있음). 같은 주소가 있으면(보관함 포함) 409 | `agent.create_entry`, `POST /api/agent/entries/<kind>` |
| edit | 새 판 = 전체 내용(구조 포함), 구조 연산, 항목 정보(동화: virtue·character·text_in_image)·순서 | `agent.save_entry`, `POST …/edit`(ops), `PATCH …/<key>`(meta·sort) |
| archive | 보관(소프트 삭제). **공개 중이면 409**("학교 관리자가 공개를 내린 뒤 보관") | `agent.archive_entry`, `POST …/archive` |

- 36차의 `draft`는 `edit`로 옮겼다. 이미 발급한 토큰은 읽기·고치기(+파일 올리기)로 그대로 쓴다. 만들기·보관이 필요하면 새로 발급한다.
- 공개·공개 내림·되살리기·설정·구성원·다른 학교: 여전히 어떤 토큰으로도 할 수 없다(함수가 없다).
- **구조 바꾸기:** 블록의 순서를 바꾸고, 끼우고, 빼고, 숨길 수 있다(`hidden`). 블록 종류를 바꾸고(validateContent가 허용하는 모든 종류), 머리 모양·머리말·표지·요약도 고칠 수 있다.
  - 두 길이 있다. (1) 전체 내용을 새 판으로 저장하거나, (2) 화면 편집의 순수 함수(`src/lib/site-edit.ts`: moveBlock·insertBlock·removeBlock·toggleHidden·setAt)를 서버에서 그대로 쓰는 ops 경로를 쓴다.
  - 두 길 모두 같은 `validateContent`를 거치고 `base_version`이 필수다. 사람 편집과 같은 규칙이다(PLATFORM-PATTERNS 1 '편집 연산 계층').
  - 활동 기록에 블록 수 전후와 구조 변화 여부를 남긴다.

### 보관 (사람·에이전트 공통)
- `site_entries.archived_at`·`archived_by`(사람)·`archived_by_token`(토큰).
- 판·공개 기록·자산은 지우지 않는다. 보관 뒤에도 판 수는 그대로다.
- 방문자 함수(`private.live_versions`)는 보관한 항목을 내주지 않는다. 보관한 항목은 공개할 수 없다(먼저 되살린다).
- 학교 관리자는 /site 목록 아래 '보관함'에서 열어 '되살리기'를 하고, 편집 화면에서 '보관함으로'를 누를 수 있다(공개를 내린 뒤에만). 운영 기록에 남는다.

### 기한
- 7·30·90·365일 또는 무기한(`expires_at` null). 365일·무기한을 고르면 경고가 보인다.
- **연장:** 토큰 값(원문·해시)은 그대로 두고, 남은 기한 끝(지났으면 지금)부터 고른 만큼 늘린다. 무기한으로 바꿀 수도 있다. 학교 관리자만 하고, 폐기한 토큰은 안 된다. 운영 기록에 이전·새 기한을 남긴다.
- **알림:** /site 설정 위쪽에 '30일 안에 끝남'과 '180일 넘게 안 쓴 무기한'을 표시한다. 전체 관리 → 학교별 개발 연동에는 모든 학교 토큰 목록이 보인다(전체 관리자, 해시 없음). ROADMAP '연례 토큰 점검'.

## 위험과 대응
| 위험 | 대응 |
| --- | --- |
| 토큰 유출 시 피해가 커짐(만들기·보관) | 권한은 필요한 것만 체크. 보관은 되살릴 수 있고 판이 남는다. 공개·공개 내림은 여전히 사람만. 활동 기록·마지막 사용 표시 |
| 무기한 토큰이 잊혀 남음 | 발급 경고, 180일 미사용 표시(학교·전체 관리), 폐기 즉시 차단 |
| 에이전트가 사람 판을 덮음 | `base_version` 409 그대로 |
| 구조 연산으로 이상한 내용 저장 | 연산 결과도 validateContent·학교 자산 검사를 거침. `set`의 path에 `__proto__`·`constructor`·`prototype` 금지 |

| Supabase 권한 차이 | agent_writer 소유 함수는 `set local role agent_writer` 안에서 만든다. 비슈퍼유저 마이그레이션 사용자로 34→36→37 순서 적용을 확인 |
