# 0005. UI 구현 도구

- 상태: **채택(1단계)** · 날짜: 2026-11-22 · 제안: Claude · 결정: 사용자("UI·UX 구현 도구를 가져와 적용") — 2단계는 디자인 방향 결정 뒤
- 관련: [0003 디자인 시스템](0003-design-system.md), 전체 관리 → 디자인 방향(`/admin/design`)

## 배경
18차 디자인 기반은 토큰·공통 컴포넌트를 갖췄지만 아이콘, 접근성 있는 메뉴·대화상자, 한글 서체가 없어 "평범하고 세련되지 않다"는 평가를 받았다.

## 고려한 안
| 도구 | 하는 일 | 라이선스 | 판단 |
| --- | --- | --- | --- |
| lucide-react 1.70.0 | 일관된 선 아이콘 | ISC | **채택** — 메뉴·지표·버튼 아이콘 |
| @radix-ui/react-dropdown-menu 2.2.1 · react-dialog 1.3.1 · react-tooltip 1.4.1 | 키보드·화면낭독기 대응 메뉴·대화상자·툴팁(스타일 없음) | MIT | **채택** — 학교 전환기·확인 대화상자·행 동작 메뉴에 순서대로 적용 |
| Pretendard 1.3.9 (동적 부분 집합) | 한글 UI 서체 | OFL-1.1 | **채택** — 기본 서체. 쓰인 글자 묶음만 내려받음 |
| Tailwind CSS + shadcn/ui | 유틸리티 클래스 + 복사형 컴포넌트 | MIT | **보류** — 지금의 의미 토큰 CSS와 두 체계가 됨. 디자인 방향(특히 1·3)이 정해지면 토큰을 그대로 옮길 수 있는지 비교해 다시 결정 |
| Recharts / Tremor | 차트·대시보드 | MIT / Apache-2.0 | 후보 — 지표 화면이 늘면 |
| Storybook | 컴포넌트 목록·시각 검토 | MIT | 후보 — 디자인 방향 결정 뒤, 디자인 방향 화면이 당분간 그 역할 |
| axe-core | 자동 접근성 검사 | MPL-2.0 | 자동 개선 대기열에 있음 |

버전은 공개 2주가 지난 것만 고정했다(2026-11-22 기준).

## 결정
1단계: lucide·Radix·Pretendard 채택. 2단계(스타일 체계 전환, 차트·Storybook)는 사용자가 디자인 방향을 고른 뒤 새 결정 기록으로.

## 확인 방법
`npm audit --omit=dev` 0건, 빌드 통과, 디자인 방향 화면에서 육안 확인, E2E 흐름 유지.
