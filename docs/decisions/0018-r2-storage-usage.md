## 배경
그림·PDF·원본 파일이 Postgres `bytea`에 저장되고 Vercel 함수가 내보냈다. DB 디스크($0.125/GB)·Supabase egress($0.09/GB 초과)·Vercel 전송이 함께 들어 학교가 늘면 비용이 커진다.

## 고려한 안
| 안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. R2 비공개 버킷 + 앱이 판단 후 서명 주소(채택)** | 공개 판·소속 판단은 그대로, 바이트만 R2. 읽기는 302 → 10분 서명 주소 | 내려받기 무료, 공개 범위 그대로(시안 그림이 새지 않음), 도메인 불필요 | 302 한 번 더, 주소가 바뀌어 브라우저 캐시가 짧음 |
| B. R2 공개 버킷(r2.dev·사용자 도메인) | 공개 주소로 바로 | 가장 빠름 | 키만 알면 시안·비공개 그림도 열림(공개 범위 확대), 도메인 필요 |
| C. Vercel 함수가 R2에서 받아 전달 | 지금 주소 그대로 | 단순 | Vercel 전송·함수 비용이 그대로 |

## 결정
- A. 키는 `sha256/<hex>`(내용 주소, 같은 내용은 한 번, 지우지 않음). 행에는 `object_key`만 더하고, 트리거가 "비어 있을 때 자기 해시로 한 번 적기"만 허용한다.
- 설정이 없으면 DB에 저장(로컬·시험·되돌리기). 기존 파일은 전체 관리자 '복사'(DB 사본 유지). DB 사본 비우기는 확인 뒤 따로 결정.
- 작업 토큰 업로드: 토큰·권한을 먼저 확인(`agent.can_upload`)하고 R2에 올린 뒤 등록(`agent.register_asset`). 틀린 토큰은 R2에 아무것도 쓰지 못한다.
- 사용량·요금: 저장소는 표에서 바로 계산(sha256 겹침 제외), AI는 `usage_events`(호출한 쪽이 그때 단가로 남긴 추정 금액, 추가만), 외부 에이전트 작업은 `agent_token_uses` 개수. 단가는 `src/lib/usage-shared.ts` 한곳(확인일 포함). 학교별은 포함분 빼기 전, 전체는 R2 10GB·DB 8GB 뺀 뒤. USD 추정이며 청구서가 아니다.

## 영향
- 마이그레이션 `20261123001900_r2_storage.sql`, `20261123002000_usage_events.sql`. 의존성 `aws4fetch`.
- 화면: 전체 관리 → 사용량·저장소(`/admin/usage`), 학교 설정의 '우리 학교 사용량'.
- 되돌리기: Vercel 변수 4개를 지우면 새 파일은 DB로. R2에만 있는 파일은 503이 되므로 지우기 전 DB로 되돌려 받는 길이 필요(그때 새 작업).
- 아직: 학사 원본(`source_files.original`, 비공개·2MB)은 DB 그대로. 그림 줄이기(WebP), 방문자 내려받기 세기, 학교별 상한·경보는 다음.
