# 0052. 템플릿 세 축(메뉴 구조·첫 화면·내용)과 메뉴 구조 설정

- 상태: 채택
- 날짜: 2026-11-28
- 제안: Claude(홈페이지 세션)
- 결정: 사용자(2026-11-28) — "템플릿을 다양한 구조를 반영하는 형태로 카테고리를 나누는 것이 좋겠다 … 템플릿 검색에서 다양한 형태, 컨텐츠 등의 카테고리도 추출해서 사용자가 입맛대로 골라서". 선택: '웹 조사 후 분류', '틀 먼저 + 새 구조 4~6종'.
- 관련: ADR 0034(템플릿 = 완성 디자인), ADR 0046(두 단계 메뉴), `docs/research/site-structures-2026-11.md`, `docs/rounds/round-135.md`·`round-136.md`

## 원인
- 템플릿이 내용(학교 유형)으로만 나뉘어 있었다. 같은 내용이라도 메뉴 구조(위 메뉴·옆 메뉴·한 쪽)를 다르게 고를 길이 없었다.
- 조사 결과 마켓은 대부분 업종·스타일로만 거른다. 학교는 '모양(구조)'으로도 고르고 싶어 한다(선생님 지시).

## 결정
1. 템플릿마다 세 축을 단다(`src/lib/site-template-facets.ts`).
   - **메뉴 구조** `nav`: `top`(위 메뉴형) · `side`(옆 메뉴형) · `onepage`(한 쪽 스크롤형). 공개 화면의 동작이 실제로 다른 것만 값으로 둔다.
   - **첫 화면** `first`: `board` · `magazine` · `landing` · `gallery` · `hero` · `tiles`
   - **내용·목적** `contents`(여러 개): `notice` · `story` · `admission` · `project` · `mission` · `international` · `kinder` · `small`
2. 메뉴 구조는 학교 설정값이다: 홈 사이트 정보 `site.layout`(`side`·`onepage`, 비우면 위 메뉴). 템플릿을 적용하면 홈에 적힌다. 표·마이그레이션은 바꾸지 않는다(홈 내용 JSON).
   - 옆 메뉴형: 하위 쪽이 있는 묶음 안의 쪽(상위·하위)에서 형제 쪽 메뉴를 넓은 화면은 왼쪽 세로, 휴대폰은 본문 위 가로 띠로 그린다.
   - 한 쪽 스크롤형: 홈에서 메뉴 주소 구역 차례가 넓은 화면(1200px 이상) 오른쪽에 따라오고, 지금 구역을 표시한다. 좁은 화면은 머리글 메뉴의 '홈' 아래 차례를 쓴다.
   - campus·dawn 디자인은 지금처럼 한 줄 메뉴다(키트 테마만).
3. 고르기 화면(`/site/templates`)은 세 축을 링크 칩으로 거른다(주소 `?nav=&first=&content=`, 자바스크립트 없이 동작, 값마다 개수, 0개는 누를 수 없음).

## 고려한 안
| 안 | 판단 |
| --- | --- |
| **세 축 + 메뉴 구조는 공개 화면 동작으로(채택)** | 구조 이름이 실제 동작과 맞아 고른 뒤 실망이 없다 |
| 조사의 8가지 구조를 한 축으로 | 메가 메뉴·벤토처럼 아직 그리지 못하는 값이 섞여, 고른 템플릿이 이름과 다르게 동작한다 |
| 스타일 축도 두기 | 디자인(테마)이 이미 따로 있고 학교가 바꿀 수 있어 뒤로 미룸 |

## 영향·다시 볼 조건
- 메뉴 구조 값을 더할 때(예: 메가 메뉴) 이 기록을 고치지 않고 새 기록을 만든다. 값 목록·이름표·en·th 번역·SiteFrame 동작을 함께 더한다.
- 템플릿이 12종을 넘으면 검색어 칸을 검토한다.
