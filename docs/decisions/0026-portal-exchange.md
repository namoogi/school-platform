# 0026. 드리미포털과 정보를 주고받는 길

- 상태: 채택 (사용자 지시 2026-11-25 "드리미포털과 상호 정보를 주고 받는 길을 만들도록 하자")
- 날짜: 2026-11-25
- 관계: AGENTS.md 독립 인프라, ADR 0015(관제 센터)·0024(관제 = 전체 관리자). 첫 교류: 54차 학생부 분석(`docs/research/portal-gradebook-review.md`)

## 배경
54차에 관제 세션과 드리미포털 세션(사용자 Mac, 포털 저장소)이 세션 메시지로 학생부 분석을 주고받았다. 길은 통했지만 대화 안에서만 오가 흘러가기 쉽다. 또 무엇을 주고받아도 되는지가 적혀 있지 않았다.

## 결정
**새 토큰·새 API·저장소 동기화 없이, 이미 있는 두 장치를 묶는다.**
1. **나르는 길: 세션 메시지.** 관제 → 포털은 `send_message`, 포털 → 관제는 `SendMessage`(교차 세션). 두 세션이 서로의 id를 안다. 세션을 새로 열면 관제 센터의 세션 목록에서 id를 바꾼다.
2. **남기는 곳: 관제 센터.** 포털 세션을 '외부 협력' 세션으로 등록했다(`control_sessions`, 태그 `partner`).
   - 교류 한 건 = 관제 센터 요청 한 건.
   - 사용자 결정이 필요한 것은 결정 요청으로 올린다. 사용자가 `/admin/control`에서 답하면 관제가 포털에 전한다.
   - 본문이 큰 결과물(분석·개선안)은 이 저장소 `docs/research/`와 연구소 항목에 남기고, 요청에는 경로만 적는다.
3. **주고받는 것과 아닌 것.**
   - 주고받는 것: 표·열·규칙·흐름·파일 경로·개수, 설계 문서, 개선안, 결정 근거.
   - 오가지 않는 것: 학생·교직원 이름, 연락처, 성적 값, 실제 기록, 비밀 값(서비스 키·토큰·DB 주소), 로그인 세션.
   - 숫자는 보내는 쪽이 그 자리에서 잰 값으로 보내고, 잰 날짜를 붙인다.
4. **바꾸는 사람.** 각자 자기 저장소·자기 자료만 바꾼다.
   - 상대에게서 온 것은 제안이다. 반영 여부는 각 쪽의 관리자 결정과 규칙을 따른다.
   - 받는 쪽은 반영 전에 그 파일의 판 번호·관리자 결정('왜')을 먼저 읽는다. 사고에서 나온 규칙을 지키기 위해서다(포털 세션의 제안).

## 하지 않는 것
- 포털 저장소를 이 세션에 붙이거나 동기화하기
- 포털 DB에 접속하기
- 포털 자료를 이 DB로 옮기기(AGENTS.md 독립 인프라)
- 교류용 토큰 발급. 필요해지면 새 ADR로 한다.
