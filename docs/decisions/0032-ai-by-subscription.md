# 0032. AI 작업은 구독 계정으로 한다 — 플랫폼 서버의 유료 API 분석은 두지 않는다

- 상태: 채택
- 날짜: 2026-11-26
- 제안: 사용자
- 결정: 사용자 (2026-11-26)

## 배경
- 66차에서 학교 자료 자동 배치의 분석 주체를 세 가지로 나눴다.
  - ① 규칙 기반(내장)
  - ② 학교 AI(구독, 작업 토큰)
  - ③ 플랫폼 유료 API
- ③을 열지 사용자 결정을 받았다.

## 결정 (사용자 원문 요지)
> "유료 API는 가격도 비싸고 정작 성능은 떨어져. API로 맥락을 읽으니까 비용은 기하급수적으로 증가하는데 맥락을 다 읽지 않고 코딩을 짜니까 다시 짜야 하는 코드나 제대로 작동하지 않는 코드를 만들어내기 일쑤임. API는 대화 정도의 맥락 이해나 실시간 반응에는 도움이 되겠지만 토큰 기반으로 구독 계정이 대응하는 방식이 좋을 것 같아."

- 무거운 AI 작업은 **구독 계정의 AI**가 한다. 대상은 자료 분석, 쪽 채우기, 기존 사이트 이전, 정의·꾸러미 작성, 개발이다.
  - 학교 몫: 학교가 쓰는 Claude Code·Codex 구독이 범위 토큰(ADR 0012·0013)으로 들어와 한다.
  - 플랫폼 몫: 관제 세션(구독)이 한다.
- **플랫폼 서버가 유료 API로 문서·사이트를 분석하는 기능은 만들지 않는다.** 66차의 ③은 닫는다.
- 서버 안의 무료 보조(규칙 기반 제안 ①)는 그대로 둔다. 구독 AI가 없는 학교도 시작할 수 있게 하는 1차 배치다.
- 유료 API는 **대화 수준의 맥락·실시간 반응**이 꼭 필요한 곳에만 다시 검토한다(예: 대화창 즉답). 그때도 비용 추정과 사용자 확인을 먼저 받는다.

## 다시 볼 조건
- 구독 계정으로는 할 수 없는 실시간 기능이 학교 요구로 생길 때
- API 가격·성능이 크게 바뀔 때

## 영향
- 66차 문서의 ③은 '채택 안 함'으로 고친다.
- 학교 AI가 자료·옛 사이트를 직접 읽고 빈 칸을 채우는 길을 안내 문서(`docs/agents/README.md`)·AI 연결 글에서 분명히 한다.
- ADR 0011의 '2단계 대화형 편집(Claude API, 유료)' 계획은 이 결정을 따른다. 무거운 편집은 구독 AI가 맡고, API는 실시간 대화 보조로만 검토한다.
