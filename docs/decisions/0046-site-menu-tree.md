# 0046. 학교 홈페이지 두 단계 메뉴 — 쪽의 상위 메뉴 + 구역 메뉴 주소

- 상태: 채택
- 날짜: 2026-11-28
- 제안: Claude
- 검토: Codex(PR 검토)
- 결정: 사용자 (2026-11-28, "쪽과 구역 둘 다")

## 배경
선생님(2026-11-28): 학교 홈페이지는 메뉴가 많고, 상위 메뉴 아래 하위 메뉴가 있는 경우가 많다. 일반 학교 콘텐츠를 분류하고, 그것을 지원하는 틀을 만들어 템플릿까지 적용하자. 지금은 공개된 쪽을 순서대로 늘어놓은 한 줄 메뉴뿐이다(`app.public_site`의 `nav`).

## 고려한 안
| 안 | 내용 | 장점 | 단점·위험 | 비용 |
| --- | --- | --- | --- | --- |
| A 쪽 + 구역 (채택) | 쪽 내용에 `menu.parent`, 구역에 `anchor` | 짧은 하위는 구역으로 묶어 쪽 수가 덜 늘고, 긴 하위는 쪽으로. 판·공개 흐름을 그대로 탄다 | 구역 메뉴 주소를 학교가 정해야 한다 | 마이그레이션 1개(함수만) |
| B 모두 쪽 | 하위 메뉴 = 쪽 | 일반 학교 사이트와 같은 모양 | 템플릿마다 쪽 15~25개, 작은 학교는 빈 쪽이 많다 | 같음 + 예시 글 대량 |
| C 모두 구역 | 상위만 쪽 | 가장 가볍다 | 공지·가정통신문·갤러리가 많은 학교는 쪽이 너무 길다 | 같음 |
| D 메뉴 설정 따로(site_settings.menu) | 메뉴 나무를 설정 한 곳에 | 순서·이름을 자유롭게 | 쪽을 더하고 지울 때 메뉴와 어긋난다. 판·공개 흐름 밖이라 공개 전 메뉴가 바로 바뀐다 | 표 칸 추가 |

## 결정
A. 쪽 내용(`site_entry_versions.content`)의 `menu.parent`(다른 쪽 주소 이름 또는 `news`)와 블록의 `anchor`(메뉴 주소)로 메뉴 나무를 만든다.
- 공개된 판만 메뉴에 실린다(`app.public_site`가 `parent`·`sections`를 더해 낸다). 판·공개·되돌리기가 쪽과 함께 움직인다.
- 한 단계만. 없는 쪽이나 셋째 단계를 가리키면 상위로 올라온다.
- 키트 디자인만 두 단계로 그린다. campus·dawn은 한 줄 메뉴 그대로다.
- 분류와 템플릿 적용 계획: `docs/design/school-content-taxonomy.md`.

D는 메뉴 이름을 쪽 제목과 다르게 쓰고 싶다는 요구가 생기면 다시 본다.

## 영향
- DB: `app.public_site`만 새로 정의(`20261128001600_site_menu_tree.sql`). 표·권한·RLS 변화 없음. 학교 칸·데이터 경계(AGENTS.md 1~10) 변화 없음.
- 코드
  - `Content.menu`, `Block.anchor`, `NavEntry`, `buildNavTree`, `navEntriesOf`(`site-shared.ts`)
  - 검사(`validateContent`: 메뉴 주소 형식·중복, 상위 메뉴 형식)
  - `SiteFrame`(넓은 화면 하위 판, 휴대폰 펼침 묶음, 바닥글은 상위만)
  - `SiteRenderer`(메뉴 주소 구역에 id)
  - 편집기(상위 메뉴 고르기, 메뉴 주소 칸)
- 외부 에이전트: 같은 `content` 형식이라 `page` 토큰으로 상위 메뉴·메뉴 주소를 쓸 수 있다(권한 범위 변화 없음).
- 되돌리기: 함수를 이전 정의로 되돌리면 메뉴가 한 줄로 돌아간다. 저장된 `menu`·`anchor`는 남지만 무시된다.
