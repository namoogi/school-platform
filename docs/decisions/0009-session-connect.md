- 근거 자료: [세션 연결 조사](../research/session-connect-2026-11.md)

## 배경

이 저장소는 관제 세션(사용자와 대화), 매시간 개발 세션(자동 실행), Codex가 함께 일한다. 2026-11-22~23에 실제로 겪은 문제는 셋이다.

- 개발 세션이 관제 세션에 회신하지 못했다(신뢰된 기기 인증).
- 작업 목록(`QUEUE.md`)과 PR 상태를 이중으로 관리했다.
- 자동 실행 PR은 사람이 병합할 때까지 쌓인다.

대기열은 다음 두 가지를 결정하라고 요구한다.
- ① 작업 단위를 GitHub 이슈(라벨 `auto-ok`)로 옮길지
- ② 저위험 PR의 자동 병합 허용 여부

조사하면서 셋째 결정이 하나 더 드러났다.
- ③ 매시간 실행이 같은 세션을 이어 쓸지

## 근거

- 공식 문서: 세션 간 메시지 제약 [C1], 예약 작업·GitHub 트리거·한도 [C2], Projects 기능·한도·베타 [C3]. 자세한 내용은 조사 문서 2절.
- GitHub auto-merge·필수 검사, Codex 검토 범위(P0·P1만)는 검색 요약으로만 확인했다(본문 접근 차단) [G1·G2·O1].
- 관찰: 회신 실패(2026-11-22 22:47), 미리보기 = 운영 DB(PR #16), Codex 검토 무응답(PR #13, 2회 요청).
- 추정: C1의 실행당 비용 증가는 컨텍스트 크기에서 추정한 것이고 측정하지 않았다.

## 결정

(사용자 결정 대기.) Claude 추천은 **A2 + B2 + C2**다. 각각 다음 조건이 오면 다시 본다.
- A2: 이슈 관리가 번거로우면 A1로 되돌리고, 작업이 많아지면 A3로 넓힌다.
- B2: 자동 병합한 PR이 문제를 일으키면 즉시 B1로 되돌린다. Codex 검토가 안정적으로 오면 범위 넓히기를 검토한다.
- C2: 연속성이 깨지는 사례가 2회 이상이면 C1로 되돌린다.

## 영향

- A2: `.github/ISSUE_TEMPLATE/auto-task.md` 추가, session-start 스킬·RUN-PROMPT 1단계를 "라벨 `auto-ok` 열린 이슈 중 가장 오래된 것"으로 수정, `QUEUE.md` 항목을 이슈로 옮김. 라벨 생성·이슈 게시는 처음 한 번 사용자 승인.
- B2: `scripts/merge-gate.mjs`(바뀐 파일 경로·CI·Codex 지적 확인), AUTOPILOT 안전 규칙 1 수정. 데이터 경계에는 영향 없음(제외 경로).
- C2: 예약 작업 설정 변경(사용자 또는 사용자 지시를 받은 세션). RUN-PROMPT가 혼자서 출발할 수 있게 보강.
- 되돌리기: 셋 다 설정·문서 변경이라 이전 방식으로 되돌릴 수 있다. 자동 병합한 커밋은 revert PR로 되돌린다.
