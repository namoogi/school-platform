# 0010. Claude 점검 접근: 머리 토큰 + 읽기 전용 점검 계정

- 상태: 채택
- 날짜: 2026-11-23
- 제안: 사용자 — "구글 로그인이라도 Claude가 접근하고 화면을 스캔할 수 있는 길을 만들어 놔. 내가 계속 대신 로그인하고 체크해 줄 수는 없잖아."
- 결정: 사용자 지시(2026-11-23), 구현 방식은 Claude
- 번호: 0009는 자동 개발 PR(세션 연결 조사)이 쓰고 있어 0010을 쓴다.

## 결정
- **전용 계정 하나:** `inspector@onschools.internal`, 이름 'Claude 점검(읽기 전용)'.
  - 비밀번호가 없다.
  - 전체 관리자처럼 모든 화면을 볼 수 있다.
  - 앱이 이 계정의 DB 트랜잭션을 `read only`로 연다. 어떤 화면·API에서도 기록을 바꿀 수 없다(25006 → "읽기 전용" 403).
- **들어오는 길:** 요청 머리 `x-inspector-token: insp_<64 hex>`.
  - 세션 쿠키가 없을 때만 본다.
  - DB는 토큰의 sha256만 저장한다.
  - 기한은 7·30·90일이다. 폐기할 수 있고, 마지막 사용 시각을 남긴다.
- **발급·폐기:** 전체 관리자만 한다(점검 계정 자신은 못 한다). 전체 관리 → 학교별 개발 연동 → 'Claude 점검 접근'에서 한다. 원문은 발급 화면에 한 번만 보이고, 발급·폐기는 운영 기록에 남는다.
- **Claude 쪽 보관:** 사용자가 Claude 세션의 자격 증명 입력 창에 넣는다(호스트 onschools.vercel.app, 머리 x-inspector-token). 네트워크 프록시가 그 호스트로 가는 요청에만 붙인다. Claude는 원문을 보지 않고, 채팅·저장소·로그에도 남기지 않는다.
- **학교 들어가기:** 점검 계정은 쓰기가 막혀 있어 입장 기록(access_log)을 남기지 못한다. 대신 토큰의 마지막 사용 시각으로 추적한다.

## 위험과 대응
| 위험 | 대응 |
| --- | --- |
| 토큰 유출 시 모든 학교 화면이 읽힘 | 읽기 전용, 짧은 기한, 즉시 폐기, 마지막 사용 시각 표시. 실제 학생 정보가 들어오기 전에 학교별 범위 제한을 검토한다(다시 볼 조건) |
| 시드가 전체 관리자 권한을 내림 | 시드가 점검 계정은 제외한다 |
| 쓰기 경로가 남음 | DB 트랜잭션 자체를 read only 로 연다(앱 코드 실수와 무관) |
