- 제안: 사용자
- 검토: Claude (구현)
- 결정: 사용자 (2026-11-23) — "전체 관리자 모드는 4 분석 대시보드형을 기본으로 하고 화이트 반전 버튼 하나, 학교별 관리자 모드는 학사 업무형. 그걸 기본으로 하되 UI를 선택해서 바로 바꿀 수 있도록. DB는 어떤 UI를 선택하더라도 연동되게"

## 배경
ADR 0006은 학사 업무형 하나를 기본 틀로 정했다. 전체 관리자는 여러 학교의 지표를 보므로 분석 대시보드형이 맞고, 사용자마다 선호가 다를 수 있다.

## 결정
- **화면 형식과 데이터를 분리한다.** UI는 셸 배치와 토큰만 바꾼다. 조회·권한(RLS)·기록은 어떤 UI에서도 같은 서버 코드와 같은 표를 쓴다.
- **두 가지 형식 × 두 가지 명암**을 둔다.
  - `data-ui="campus"` 학사 업무형: 아이콘 레일 + 이름, 청록, 본문 16px
  - `data-ui="analytics"` 분석 대시보드형: 아이콘만 있는 얇은 메뉴와 이름 풍선, 파랑, 본문 14px, 고정폭 숫자
  - `data-mode="light"` 흰 화면 / `"dark"` 어두운 화면
- **기본값**
  - 전체 관리 = 분석형 + 어두운 화면. 상단 막대의 '화이트' 버튼 하나로 반전한다.
  - 학교 화면 = 학사 업무형 + 흰 화면.
- **사용자별 저장**
  - `public.user_preferences`(사용자당 한 행: platform_ui·mode, school_ui·mode)에 저장한다. 다른 기기에서 로그인해도 같다.
  - 본인 행만 읽고 쓴다(RLS). 학교 자료가 아니어서 school_id가 없다(데이터 경계 규칙 1의 대상이 아님).
- **즉시 전환:** 누르면 브라우저가 바로 바꾸고(낙관적 갱신) 저장한 뒤 서버 화면을 새로 그린다.
- **토큰 구조:** 의미 토큰을 `:root, .app`에서 계산한다. 그래야 `.app[data-ui]`가 바꾼 원시 토큰이 의미 토큰에 반영된다. 발행본 종이는 명암과 무관하게 인쇄물 색을 유지한다.
- **분석 패널:** 전체 관리 첫 화면에 기간 선택(7·14·30일), 운영 기록 추이 막대 차트, 학교별 좌석 사용 막대를 더했다. 모든 형식에서 공용이다.
