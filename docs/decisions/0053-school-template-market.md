# 0053. 학교 제작 템플릿 올리기와 이용 보상(크레딧) — 설계

- 상태: 제안(구현 전, 결제·지급은 사용자 확인 뒤)
- 날짜: 2026-11-28
- 제안: Claude(홈페이지 세션)
- 요청: 사용자(2026-11-28) — "추후에는 각 학교에서 자신들이 만든 웹사이트 템플릿도 업로드 하도록 하고, 해당 템플릿을 사용하는 학교들은 일정부분 이용료를 차감해 주거나 특정 사용자에게 비용이나 크레딧을 줄 수 있는 방향으로도 설계하자."
- 관련: ADR 0027(관제 영역·학교 영역, 보고 계약), ADR 0034(템플릿 = 완성 디자인), ADR 0052(템플릿 세 축 — 메뉴 구조·첫 화면·내용, PR #244, 이 기록보다 먼저 병합), `supabase/migrations/20261122000400_platform_admin_licenses.sql`(라이선스 판)

> **요약** 학교가 자기 홈페이지를 '템플릿 제출본'으로 올리면 관제가 검수해 템플릿 목록에 싣습니다. 다른 학교가 그 템플릿을 쓰면 만든 학교(또는 지정한 사람)에게 크레딧이 쌓이고, 크레딧은 다음 이용료에서 차감합니다. 현금 지급은 세금·계약 문제가 있어 두 번째 단계로 미루고 따로 확인받습니다.

```terms
제출본 | 학교가 올린 템플릿 한 판. 올린 뒤 고치지 않고 새 판으로 올린다 | 햇살숲 유치원 템플릿 v1
검수 | 관제가 개인정보·저작권·품질을 보고 목록에 싣거나 돌려보내는 일 | 학생 얼굴 사진이 있어 돌려보냄
이용 | 다른 학교가 그 템플릿으로 홈페이지를 시작한 일(한 학교 한 번) | 새솔학교가 v1 적용
크레딧 | 이용료에서 빼 주는 점수. 원장(기록)에 쌓이고 고치지 않는다 | 이용 1건 = 다음 달 이용료 n원 차감
```

## 1. 흐름
```
학교 관리자: 내 홈페이지 → '템플릿으로 내보내기'
   └ 서버: 학교 사본에서 제출본 스냅샷 만들기(글 → 안내 자리, 사진 → 뺌 또는 재사용 허락받은 사진만, 연락처·이름 지움)
관제: 검수(개인정보·저작권·품질·세 축 값) → 싣기 / 돌려보내기(이유)
다른 학교: 템플릿 고르기에 '학교가 만든 템플릿' 묶음 → 미리보기 → 적용
   └ 이용 기록(학교·템플릿·판·때, 복사한 쪽·사진 목록) — 이때는 보상하지 않는다
   └ 기한(예: 30일) 안에 그 학교가 홈페이지를 공개하면 그때 보상 규칙에 따라 크레딧 원장에 한 줄(쓸 수 있는 크레딧은 이때부터)
청구: 라이선스 월 예상액 − 크레딧(한도 안) = 청구 예상액 → 쓴 크레딧은 청구서와 함께 차감 기록(`credit_debits`)
```

## 2. 데이터(관제 영역, 학교 내부 표를 직접 읽지 않음)
| 표 | 내용 | 규칙 |
| --- | --- | --- |
| `template_submissions` | 제출 학교, 판, 세 축 값, 스냅샷(JSON: 쪽·블록·디자인·메뉴 구조), 상태(검수 중·실림·돌려보냄·내림) | 스냅샷은 고치지 않음(새 판). 학교는 자기 제출본만 읽음 |
| `template_uses` | 쓴 학교, 제출본 판, 적용 때 | 학교·템플릿마다 한 번만 보상 대상(다시 적용해도 1건) |
| `template_rewards` | 받는 쪽(학교 또는 사람), 크레딧, 근거(이용 id·규칙 판) | 원장: 추가만, 정정은 반대 줄(정정 줄은 원래 적립 줄을 가리킴). **이용 1건에 적립 줄은 하나**: DB 유일 제약(이용 id, 적립 종류)으로 막고, 적립 만들기는 `on conflict do nothing`으로 여러 번 불러도 한 번만 생긴다(공개 재시도·동시 공개) |
| `credit_debits` | 청구서(정산 판) 1건에 쓴 크레딧을 **적립 줄마다 나눠** 적는다(적립 id·금액) | 청구서와 같은 트랜잭션에서 만든다. 유효 기간이 먼저 끝나는 적립부터 쓴다. 적립 줄마다 남은 크레딧 = 적립 − 정정 − 그 줄에 나눠 적은 차감. 기간이 지난 적립의 남은 값은 쓰지 않는다. 같은 크레딧이 두 번 쓰이지 않고, 지난 차감이 새 적립을 깎지 않는다 |
| `template_asset_grants` | 제출본에 넣을 사진 한 장마다 재사용 허락(누가·언제·어떤 범위로, 사진 속 사람·저작권자 확인) | 고치지 않음(철회는 새 줄). 이 허락 없는 사진은 제출본에 들어가지 않는다 |
| `reward_rules` | 보상 규칙 판(이용 1건당 크레딧, 상한, 유효 기간) | 판으로 쌓음, 관제가 바꿈 |

- 제출본 스냅샷은 '보고 계약'처럼 학교 사본에서 정해진 함수로만 만든다(ADR 0027). 다른 학교에는 스냅샷만 복제한다.
- 학교 이름·주소·연락처·사람 이름은 내보내기에서 안내 자리로 바꾼다.
- 사진은 기본으로 뺀다. 122차의 '공개 확인'은 한 번의 공개에 대한 확인일 뿐 다른 학교로의 재배포 허락이 아니므로 근거로 쓰지 않는다(`docs/rounds/round-122.md`: 사진마다 허가 표시를 두지 않음). 사진을 넣으려면 사진마다 재사용 허락(`template_asset_grants`)을 새로 받는다. 1단계는 사진 없이(플랫폼 예시 그림 자리) 시작한다.
- 허락받은 사진은 검수 때 **플랫폼 소유 템플릿 사진 보관소**로 복사하고, 다른 학교가 적용할 때 그 학교 `site_assets`로 다시 복사해 스냅샷 속 사진 번호를 새 번호로 바꾼다. 학교 사진은 학교 범위라(RLS) 원래 학교의 번호를 그대로 쓰면 다른 학교에서는 보이지 않는다.

## 3. 보상 방식 — 선택지
| 안 | 내용 | 장점 | 주의 |
| --- | --- | --- | --- |
| **A. 학교 크레딧(추천, 1단계)** | 이용 1건마다 만든 학교에 크레딧. 다음 이용료에서 차감 | 돈이 학교 밖으로 나가지 않아 세금·계약이 단순. 지금 라이선스 판과 바로 연결 | 차감 상한(예: 월 이용료의 일부) 필요 |
| B. 쓰는 학교 할인 | 학교 제작 템플릿을 쓰면 첫 달 할인 | 학교 템플릿 사용을 늘림 | 플랫폼 수입 감소, 남용 방지 필요 |
| C. 사람에게 현금·상품권 | 템플릿을 만든 교사·학생에게 지급 | 만든 사람에게 직접 보상 | 사업소득 원천징수·지급 서류·학생 미성년 동의 등. 별도 확인 필수(2단계 이후) |

## 4. 안전장치
- 같은 학교 묶음(같은 법인·같은 관리자)끼리의 이용은 보상하지 않는다(자기 거래 방지).
- 적용 뒤 일정 기간(예: 30일) 안에 홈페이지를 공개해야 보상한다(적용만 하고 버리는 남용 방지).
- 내리기는 두 가지로 나눈다.
  - **목록에서 내림**(만든 학교의 뜻, 품질 등): 새 이용만 막는다. 이미 쓴 학교의 홈페이지는 그대로 둔다(학교 사본).
  - **회수**(사진 재사용 허락 철회, 개인정보·저작권 문제 발견): 이용 기록의 복사 목록(쪽·구역·사진마다 어느 제출본 판에서 왔는지)으로 그 제출본에서 복사된 것을 모든 학교에서 찾는다. 문제가 사진이면 그 사진을 공개 화면에서 내리고(자리 그림으로), 글·코드(개인정보, 베낀 글·코드)면 해당 구역을 공개 화면에서 바로 가리고, 쪽 전체가 문제면 그 쪽 공개를 내린다. 각 학교 관리자에게 알리고 회수는 사건으로 남긴다. 학교는 가려진 자리를 자기 글로 바꿔 다시 공개할 수 있다.
    - 복사한 구역·사진에는 출처 표시(제출본 판·구역 번호, 사진 번호)를 판 안에 남긴다. 회수한 출처는 **회수 목록**에 넣고, 공개할 때(`publish`) 이 목록을 확인하고, 이미 공개된 판에 회수 대상이 있으면 가린 새 공개 판을 만들어 공개 표시를 옮긴다(4-1). 그래서 학교가 그 뒤에 고친 판이라도 회수된 구역·사진이 그대로 남아 있으면 가려지고, 예전 판을 다시 공개해도 되살아나지 않는다. 학교가 그 구역을 자기 글로 바꾸면(출처 표시가 빠지면) 보인다. 회수 대상이 쓰인 발행본이 있으면 같은 방식으로 표시한다.
- 상업 템플릿 코드·사진·글을 베낀 제출본은 싣지 않는다(검수 기준).

## 4-1. 구현 때 지킬 것(Codex 검토에서 나온 조건)
- **크레딧 차감은 동시에 두 번 일어나지 않게**: 청구서를 만들 때 그 학교의 쓸 수 있는 적립 줄을 `select … for update`로 잠근 뒤 나눠 적는다. 또는 적립 줄마다 남은 값을 DB 검사(남은 값 ≥ 0)로 막는다. 두 청구서가 같은 적립을 동시에 쓰지 못한다.
- **보상 조건은 '실제로 그 템플릿을 쓴 공개'**: 기한 안의 공개 중 공개된 판에 그 제출본의 출처 표시가 남아 있는 쪽이 있을 때만 적립한다. 적용만 하고 내용을 다 바꾼 뒤 공개하면 보상하지 않는다.
- **회수된 사진은 주소로도 열리지 않게**: 공개 사진 길(`app.public_asset`)이 회수 목록을 확인해 404를 낸다. 사진 응답의 캐시는 회수 때 무효화하거나 캐시 시간을 짧게 둔다.
- **발행본은 스냅샷 그대로**: 회수를 그리기 때 덮어 바꾸지 않는다. 가린 내용으로 **새 공개 판(스냅샷)**을 만들고 공개 표시를 그 판으로 옮긴다(데이터 경계 5: 발행본은 스냅샷만 읽음). 회수 목록은 앞으로의 공개를 막는 데 계속 쓴다.

## 5. 결정이 필요한 것(구현 전에 확인)
1. 보상 방식: A만 / A+B / A+B+C
2. 크레딧 값과 상한(예: 이용 1건 = 월 이용료의 n%, 월 차감 상한)
3. 학교 템플릿 목록 공개 범위: 플랫폼 전체 / 같은 지역·연합만
4. 사람(교사·학생) 보상을 할 경우 지급 주체·세금 처리

## 6. 단계
1. 내보내기·검수·목록(보상 없이) — 되돌릴 수 있음
2. 이용 기록 + 크레딧 원장 + 청구 예상액 차감(실제 결제 없음)
3. (확인 뒤) 실제 결제 연동·사람 지급
