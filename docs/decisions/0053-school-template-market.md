# 0053. 학교 제작 템플릿 올리기와 이용 보상(크레딧) — 설계

- 상태: 제안(구현 전, 결제·지급은 사용자 확인 뒤)
- 날짜: 2026-11-28
- 제안: Claude(홈페이지 세션)
- 요청: 사용자(2026-11-28) — "추후에는 각 학교에서 자신들이 만든 웹사이트 템플릿도 업로드 하도록 하고, 해당 템플릿을 사용하는 학교들은 일정부분 이용료를 차감해 주거나 특정 사용자에게 비용이나 크레딧을 줄 수 있는 방향으로도 설계하자."
- 관련: ADR 0027(관제 영역·학교 영역, 보고 계약), ADR 0034(템플릿 = 완성 디자인), ADR 0052(템플릿 세 축), `supabase/migrations/20261122000400_platform_admin_licenses.sql`(라이선스 판)

> **요약** 학교가 자기 홈페이지를 '템플릿 제출본'으로 올리면 관제가 검수해 템플릿 목록에 싣습니다. 다른 학교가 그 템플릿을 쓰면 만든 학교(또는 지정한 사람)에게 크레딧이 쌓이고, 크레딧은 다음 이용료에서 차감합니다. 현금 지급은 세금·계약 문제가 있어 두 번째 단계로 미루고 따로 확인받습니다.

```terms
제출본 | 학교가 올린 템플릿 한 판. 올린 뒤 고치지 않고 새 판으로 올린다 | 햇살숲 유치원 템플릿 v1
검수 | 관제가 개인정보·저작권·품질을 보고 목록에 싣거나 돌려보내는 일 | 학생 얼굴 사진이 있어 돌려보냄
이용 | 다른 학교가 그 템플릿으로 홈페이지를 시작한 일(한 학교 한 번) | 새솔학교가 v1 적용
크레딧 | 이용료에서 빼 주는 점수. 원장(기록)에 쌓이고 고치지 않는다 | 이용 1건 = 다음 달 이용료 n원 차감
```

## 1. 흐름
```
학교 관리자: 내 홈페이지 → '템플릿으로 내보내기'
   └ 서버: 학교 사본에서 제출본 스냅샷 만들기(글 → 안내 자리, 사진 → 뺌 또는 공개 허가 사진만, 연락처·이름 지움)
관제: 검수(개인정보·저작권·품질·세 축 값) → 싣기 / 돌려보내기(이유)
다른 학교: 템플릿 고르기에 '학교가 만든 템플릿' 묶음 → 미리보기 → 적용
   └ 이용 기록(학교·템플릿·판·때) → 보상 규칙에 따라 크레딧 원장에 한 줄
청구: 라이선스 월 예상액 − 크레딧(한도 안) = 청구 예상액
```

## 2. 데이터(관제 영역, 학교 내부 표를 직접 읽지 않음)
| 표 | 내용 | 규칙 |
| --- | --- | --- |
| `template_submissions` | 제출 학교, 판, 세 축 값, 스냅샷(JSON: 쪽·블록·디자인·메뉴 구조), 상태(검수 중·실림·돌려보냄·내림) | 스냅샷은 고치지 않음(새 판). 학교는 자기 제출본만 읽음 |
| `template_uses` | 쓴 학교, 제출본 판, 적용 때 | 학교·템플릿마다 한 번만 보상 대상(다시 적용해도 1건) |
| `template_rewards` | 받는 쪽(학교 또는 사람), 크레딧, 근거(이용 id·규칙 판) | 원장: 추가만, 정정은 반대 줄 |
| `reward_rules` | 보상 규칙 판(이용 1건당 크레딧, 상한, 유효 기간) | 판으로 쌓음, 관제가 바꿈 |

- 제출본 스냅샷은 '보고 계약'처럼 학교 사본에서 정해진 함수로만 만든다(ADR 0027). 다른 학교에는 스냅샷만 복제한다.
- 학교 이름·주소·연락처·사람 이름은 내보내기에서 안내 자리로 바꾼다. 사진은 기본으로 빼고, '공개 허가' 표시가 있는 사진만 학교가 골라 넣는다(122차 사진 공개 허가).

## 3. 보상 방식 — 선택지
| 안 | 내용 | 장점 | 주의 |
| --- | --- | --- | --- |
| **A. 학교 크레딧(추천, 1단계)** | 이용 1건마다 만든 학교에 크레딧. 다음 이용료에서 차감 | 돈이 학교 밖으로 나가지 않아 세금·계약이 단순. 지금 라이선스 판과 바로 연결 | 차감 상한(예: 월 이용료의 일부) 필요 |
| B. 쓰는 학교 할인 | 학교 제작 템플릿을 쓰면 첫 달 할인 | 학교 템플릿 사용을 늘림 | 플랫폼 수입 감소, 남용 방지 필요 |
| C. 사람에게 현금·상품권 | 템플릿을 만든 교사·학생에게 지급 | 만든 사람에게 직접 보상 | 사업소득 원천징수·지급 서류·학생 미성년 동의 등. 별도 확인 필수(2단계 이후) |

## 4. 안전장치
- 같은 학교 묶음(같은 법인·같은 관리자)끼리의 이용은 보상하지 않는다(자기 거래 방지).
- 적용 뒤 일정 기간(예: 30일) 안에 홈페이지를 공개해야 보상한다(적용만 하고 버리는 남용 방지).
- 제출본을 내리면 새 이용은 막고, 이미 쓴 학교의 홈페이지는 그대로 둔다(학교 사본).
- 상업 템플릿 코드·사진·글을 베낀 제출본은 싣지 않는다(검수 기준).

## 5. 결정이 필요한 것(구현 전에 확인)
1. 보상 방식: A만 / A+B / A+B+C
2. 크레딧 값과 상한(예: 이용 1건 = 월 이용료의 n%, 월 차감 상한)
3. 학교 템플릿 목록 공개 범위: 플랫폼 전체 / 같은 지역·연합만
4. 사람(교사·학생) 보상을 할 경우 지급 주체·세금 처리

## 6. 단계
1. 내보내기·검수·목록(보상 없이) — 되돌릴 수 있음
2. 이용 기록 + 크레딧 원장 + 청구 예상액 차감(실제 결제 없음)
3. (확인 뒤) 실제 결제 연동·사람 지급
