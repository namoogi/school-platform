# 0011. 학교 자율 운영: 실시간 화면 편집 + 대화형 편집 + 학교별 생성형 개발

- 상태: 채택(1단계) · 제안(2·3단계)
- 날짜: 2026-11-23
- 제안: Claude
- 검토: (PR 링크)
- 결정: 사용자 (2026-11-23) — 방향과 1단계 착수. 2단계는 비용 추정을 본 뒤 따로 승인.

## 배경
룽아룬숙사 홈페이지를 플랫폼으로 옮기면서(ADR 0008, 31차), 옛 사이트(rungarunsuksa.vercel.app)에 있던 관리자 모드와 화면 편집(글 바로 고치기, 사진 바꾸기, 레이아웃 가이드로 구역 순서 바꾸기·숨기기, 블록 팔레트, 게시·되돌리기, 자동 번역 표시)이 대부분 빠졌다. 디자인도 그대로 옮기지 못했다.

사용자가 밝힌 목적(2026-11-23, 원문 요약):
> 각 학교에도 관리 기능이 있지만, 가장 좋은 것은 **실시간 실제 화면에서 수정 가능한 관리자 모드**이고, **생성형 대화로도 고칠 수 있어야** 한다. 내가 만드는 시스템은 중앙 관제가 모든 것을 해 주는 것이 아니라, **각 학교가 생성형 대화를 통한 개발과 실시간 화면 편집으로 최대한 자유롭게, 쉽게** 운영해 관리 소요를 줄이는 것이다.

따라서 이 결정은 "중앙이 대신 해 주는 플랫폼"이 아니라 "학교가 스스로 하는 플랫폼"으로 방향을 정한다. AGENTS.md의 '사용자가 새로 밝힌 목적을 구현 기준으로 삼는다'에 따라, 종전 관리 화면(목록·편집기 3단 작업함)은 기본값으로 남기고 새 편집 방식을 더한다.

## 결정
안 A. 세 단계로 나눠 차례로 만든다. 공통 원칙:
- **같은 경로·같은 검사:** 화면 편집과 AI 편집 모두 지금의 내용 검사(`validateContent`)·RLS·판(버전) 모델을 그대로 쓴다. 새 쓰기 경로를 따로 만들지 않는다(AGENTS.md 1~6 유지).
- **시안이 먼저, 공개는 사람이:** 편집은 새 판(시안)으로 저장되고, 공개는 학교 관리자가 버튼으로 한다. AI는 공개하지 않는다.
- **학교 경계:** 편집기·AI는 로그인한 학교의 항목만 다룬다. 학교 ID는 서버가 정한다.
- **되돌리기:** 모든 공개는 판 기록이라 예전 판을 다시 공개해 되돌린다.

### 1단계: 실시간 화면 편집 (관리자 모드) — 착수
- 공개 화면(`/s/<학교>/…`)과 같은 그리기 코드로 그린 **편집 화면**에서, 학교 구성원이 '편집 모드'를 켜면:
  - 글을 그 자리에서 고친다(언어별, 빈 언어 표시).
  - 사진을 눌러 바꾼다(사진함에서 고르기·올리기).
  - 구역(블록)을 끌어서 순서를 바꾸고, 숨기고, 지운다.
  - 블록 팔레트에서 새 구역을 끼워 넣는다.
  - 바뀐 내용은 시안(새 판)으로 저장되고, 관리자는 '공개'를 누른다.
- 옛 사이트의 레이아웃 가이드·블록 팔레트·번역 표시(자동 번역 점선, 원문이 바뀌면 물결)를 참고한다(옛 사이트 세션이 정리한 ADMIN-FEATURES.md).
- 관제(전체 관리자)는 학교에 들어가 같은 편집 화면을 쓴다(입장 기록은 지금처럼).

### 2단계: 대화형 편집 (생성형 AI) — 제안, 비용 승인 뒤 착수
- 편집 화면 옆 대화창: "소개 글을 짧게", "이 쪽을 태국어로", "행사 소식 하나 만들어 줘" → AI가 **바꿀 블록과 내용**을 제안하고, 사람이 보고 '시안으로 저장'.
- 구현 방향: Claude API 도구 사용(tool use)으로 플랫폼의 블록 형식만 출력하게 하고, 서버가 같은 내용 검사를 거쳐 시안 판으로만 저장한다.
- 비용: 학교별 라이선스 기능(`ai_editor`)과 월 사용 한도. **착수 전에 공식 가격표로 요청당·학교당 추정액을 계산해 사용자 승인을 받는다**(유료 호출 전 과금 게이트). 이 기록의 숫자는 그때 채운다.
- 개인정보: 학생 자료(성적·학적 등)는 보내지 않는다. 홈페이지 내용만 보낸다.

### 3단계: 학교별 생성형 개발 — 제안
- 22차 '학교별 개발 연동'(GitHub 저장소·세션 요청 문구)을 넓혀, 학교가 자기 Claude 세션으로 자기 화면·기능을 개발하도록 한다. 학교 코드가 플랫폼 데이터 경계를 넘지 않는 방법(확장 지점·모듈 계약)을 따로 설계한다.

## 영향
- 코드: `src/app/(app)/site/`(편집 모드 화면), `src/components/site/`(편집 가능한 렌더러), API는 기존 `/api/site/**` 재사용. DB 변경은 1단계에서 없을 것으로 예상(필요하면 새 마이그레이션 + 이 기록 갱신).
- 세션 분담: 1·2단계 플랫폼 기능은 별도 개발 세션, 룽아룬숙사 디자인 충실도는 룽아룬숙사 세션, 조정은 관제 세션(docs/NEXT.md).
- 되돌리기: 편집 모드는 화면 기능이라 꺼도 기존 관리 화면이 그대로 동작한다.

## 확인 방법
- 1단계: 편집 모드에서 글·사진·순서·블록 추가 → 시안 저장 → 공개 → 방문자 화면 반영(E2E), 다른 학교 항목 편집 거부(양방향), 교사는 시안만·공개는 관리자만.
- 2단계: 비용 추정 문서 승인, AI 제안이 내용 검사를 통과하지 못하면 저장 거부, 학교 경계 시험.
