# 0001. 학교 간 데이터 경계는 DB(RLS)에서 강제

- 상태: 채택 · 날짜: 2026-11-22 · 제안: Claude · 결정: 사용자(14차 요구 "두 학교 접근 분리")

## 배경
한 앱·한 DB에 여러 학교가 있다. 화면이나 API 코드의 실수로 다른 학교 기록이 보이면 안 된다.

## 고려한 안
| 안 | 내용 | 단점 |
| --- | --- | --- |
| A | 모든 학교 표에 `school_id` + Postgres RLS, 요청마다 `authenticated` 역할과 사용자 클레임을 설정한 트랜잭션 | 정책·함수를 DB에 관리해야 함 |
| B | 앱 코드에서 `where school_id = ?`만으로 거름 | 한 곳만 빠뜨려도 유출 |
| C | 학교별 DB·스키마 | 운영·마이그레이션 비용, 전체 관리 기능이 어려움 |

## 결정
A. 표 사이 참조는 `(id, school_id)` 복합 외래키로 묶어 다른 학교 기록을 가리킬 수 없게 한다. 확정 규칙·양식·발행본·원본 행은 트리거로 수정·삭제를 막는다. 전체 관리자는 `app.is_platform_admin()`으로 모든 학교에 접근하되 입장을 `access_log`에 남긴다(16차).
