# 0024. 관제 세션 = 전체 관리자

- 상태: 채택 (ADR 0010의 '읽기 전용'을 대체)
- 날짜: 2026-11-24
- 결정: 사용자 — "관제 세션은 전체에 대한 작업권한이 있어야 해." · "전체 관리자에게 토큰을 발행하고 그걸 기반으로 작업하는 방식은 불필요한 작업이지. 이런 작업들을 없애고 설계를 단순 명료하게 가야 한다."

## 배경
점검 계정(ADR 0010)은 전체 관리자 계정이었는데, 앱이 이 계정의 DB 트랜잭션만 읽기 전용으로 열었다. 그래서 관제 세션은 학교 일을 하려면 학교 관리자에게 작업 토큰을 받아야 했고, 같은 일을 위한 우회 경로(토큰 발급 함수 등)가 늘어날 참이었다.

## 결정
- 점검 계정 = **관제 세션 = 전체 관리자**. 읽기 전용 제한을 걷는다(`src/lib/db.ts`). 관제는 사람 전체 관리자와 **같은 화면·같은 API·같은 RLS·같은 기록**으로 일한다.
- 학교에 들어가면 입장 기록이 남고(`enterSchool`), 바꾼 내용은 사람과 같은 판·발행 기록에 남는다. 표시 이름은 'Claude 관제 세션'.
- 들어오는 길은 그대로: 전체 관리자가 발급한 점검 토큰(요청 머리 `x-inspector-token`, 해시 저장·기한·폐기). 점검 계정 스스로는 점검 토큰을 발급·폐기하지 못한다.
- 따로 만들지 않는 것: 관제 전용 쓰기 함수, 관제용 학교 토큰. 학교 작업 토큰(ADR 0012~)은 학교 밖 에이전트용으로만 남는다.

## 사용
- API: 학교를 고르고(`POST /api/context { schoolId }`, 학교 쿠키를 받음) 사람이 쓰는 `/api/site/*` 등을 그대로 부른다. 로그인 쿠키는 보내지 않는다.
- 공개처럼 되돌리기 어려운 일은 사용자 지시가 있을 때 한다(AGENTS.md 변경 원칙).

## 위험과 대응
- 점검 토큰 하나가 전체 관리자 권한이다 → 발급·폐기는 사람 전체 관리자만, 기한 7~90일, 클라우드 환경 보안 칸에만 둔다. 모든 학교 입장·변경이 기록된다.
