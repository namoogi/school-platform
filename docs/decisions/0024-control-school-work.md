# 0024. 관제 세션의 학교 작업 권한

- 상태: 채택
- 날짜: 2026-11-24
- 결정: 사용자 — "관제 세션은 전체에 대한 작업권한이 있어야 해. 전체 관리자가 서브 관리자에게 권한을 받아야 하고 … 뭐하는거지?"
- 관계: ADR 0010(점검 토큰)·0012~0016·0021(학교 작업 토큰)·0015(관제 센터)

## 배경
관제 세션은 점검 토큰으로 운영 화면을 읽고 관제 센터 함수만 쓸 수 있었다. 학교 홈페이지 내용을 고치려면 학교 관리자가 작업 토큰을 발급해 넘겨줘야 했다. 전체 관리자의 일꾼인 관제가 학교 관리자에게 권한을 받는 구조는 맞지 않는다.

## 결정
- 관제 세션은 점검 토큰으로 **어느 학교든 학교 작업 토큰을 발급**한다: `POST /api/control/school-token { slug, kinds, perms, days(1~30, 기본 7), label }` → DB 함수 `control.issue_school_token`.
- 쓰기는 발급한 토큰으로 기존 AI 작업 API(`/api/agent/*`)를 쓴다. 새 쓰기 경로를 만들지 않으므로 판 쌓기·`base_version`(409)·활동 기록·학교 경계가 그대로 적용된다.
- 권한: read·upload·create·edit·archive·publish·autopublish. 공개는 사용자 지시가 있을 때.
- 기록: 학교 접근 기록(`agent.token_create_control`, 행위자 '관제 세션'), 그 학교 'AI 작업 공간' 목록에 '관제 세션 · …'으로 보인다(학교 관리자가 폐기 가능).
- 토큰 원문은 기록·커밋·대화에 남기지 않는다. 작업이 끝나면 기한(짧게)으로 끝난다.

## 범위 밖 (그대로 사람 또는 다음 결정)
- 사이트 설정·구성원·라이선스 변경. 필요하면 같은 방식(관제 함수 + 기록)으로 넓힌다.

## 위험과 대응
- 점검 토큰 하나로 모든 학교 홈페이지를 고칠 수 있다 → 점검 토큰은 전체 관리자만 발급·폐기, 기한 7~90일, 클라우드 환경의 보안 칸에만 둔다. 발급할 때마다 학교 접근 기록에 남는다.
