# 0016. 작업 토큰 '공개' 권한: AI에게 공개를 지시하면 바로 공개

- 상태: 채택
- 날짜: 2026-11-23
- 제안·결정: 사용자 (2026-11-23)
  - "AI를 통한 공개 지시는 바로 공개로 이어지도록 하자. 자동으로 생성 후 바로 공개되지는 않더라도 말이지."
  - "사이트에서 공개를 누르지 않더라도 AI를 통해 공개 지시를 하면 공개하도록."
- 관계: ADR 0012·0013·0014의 "공개는 사람이 한다"를 바꾼다(그 기록들은 고치지 않고 이 기록이 대체한다). 되살리기·설정·구성원은 그대로 사람.

## 배경
Claude가 공개 요청·좁힌 공개·지연 공개·현행 유지를 비교해 '공개 요청'을 추천했다. 사용자는 사이트에서 다시 누르는 단계 없이 AI 지시만으로 공개되기를 택했다. 다만 만들기·고치기가 저절로 공개로 이어지지는 않게 했다.

## 결정
- 새 권한 `publish`(공개). 발급할 때 체크하고, 체크하면 패널에 안내가 보인다.
- `POST /api/agent/entries/<kind>/<key>/publish {version?}`: 지정한 판(비우면 최신 판)을 바로 공개한다. `…/unpublish`: 공개를 내린다.
- 만들기·고치기·구조 바꾸기·보관은 여전히 시안·정리까지만 한다. 공개는 `publish`를 따로 불러야 한다. 스크립트도 `--publish`를 붙일 때만 공개한다.
- 범위(학교·종류·주소)는 그대로다. 보관한 항목은 공개할 수 없다.
- 공개 기록은 추가만 한다. 책임자(published_by)는 토큰을 발급한 관리자이고, 활동 기록에 '공개'·'공개 내림'이 남는다.
- 되살리기·홈페이지 설정·구성원·다른 학교는 어떤 토큰으로도 할 수 없다.

## 위험과 대응
| 위험 | 대응 |
| --- | --- |
| 토큰이 새면 공개 화면이 바로 바뀜 | 공개 권한은 체크한 토큰에만 준다. 주소 지정과 짧은 기한을 권한다. 폐기하면 바로 막힌다. 활동 기록과 마지막 사용을 보여 주고, 사람은 언제든 공개를 내릴 수 있다 |
| AI 결과물의 오류(그림·사실)가 바로 공개됨 | 에이전트 안내에 '공개는 사람이 지시했을 때만, 공개 전에 무엇을 공개하는지 사람에게 보여 준다'를 넣었다. 잘못 공개했으면 이전 판을 골라 다시 공개(`version`)하거나 내린다 |
| 만들기와 공개가 한꺼번에 일어남 | 함수를 나눴다. 만들기·고치기 함수는 공개 기록을 쓰지 않는다(시험으로 확인) |

## 확인 방법
- 통합 `tests/round40.test.ts`
  - 만들기·고치기는 공개되지 않고, 공개를 지시하면 바로 공개된다. 판을 골라 공개하고 공개 내림도 된다. 책임자와 기록을 확인한다.
  - 권한 없음·범위 밖·보관한 항목·다른 학교(양방향)는 거부되고, 표에 직접 쓰기도 거부된다.
  - 되살리기·설정은 여전히 거부된다.
- E2E 40차: 공개 권한 발급 → 만들기(아직 404) → 공개 지시(방문자에게 보임) → 활동 기록 → 공개 내림.
