# 0022. AI 연결 글: 지시문과 토큰을 한 덩어리로 붙여 넣기

- 상태: 채택
- 날짜: 2026-11-24
- 제안·결정: 사용자 — "각 관리자가 자신의 AI에 넣을 지시문과 토큰을 통합하여 사용자가 간편하게 자신의 AI를 연동할 수 있도록 만들자. 너무 복잡하면 사용자가 사용하기에 어렵다."
- 관계: ADR 0012·0013(토큰은 환경 변수로만)의 **전달 방법**을 넓힌다. 토큰 범위·권한·기한·서버 검사는 바꾸지 않는다.

## 배경
지금까지는 ① 토큰을 Codex·Claude Code 환경 변수 `SCHOOL_AGENT_TOKEN`에 넣고 ② 지시문은 `docs/agents/`를 읽고 따로 만들어야 했다. 학교 관리자 대부분에게 두 단계 모두 어렵다.

## 고려한 안
| 안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 연결 글(지시문 + 토큰) 한 번에 복사 (채택)** | 발급 직후 AI 종류를 고르면 학교·범위·권한에 맞춘 글을 만들고, 그 안에 토큰을 `export SCHOOL_AGENT_TOKEN='…'` 한 줄로 넣는다 | 붙여 넣기 한 번으로 끝남 | 토큰이 AI 대화 기록(그 AI 회사 서버 포함)에 남음 |
| B. 지금처럼 환경 변수 + 지시문 따로 | 토큰이 대화에 남지 않음 | 어렵다(사용자 지시와 어긋남) | |
| C. 짧은 연결 코드 → AI가 교환해 토큰 받기 | 대화에 남는 값이 곧 쓸모없어짐 | 서버·흐름이 늘고, 교환 전 코드 자체가 같은 위험 | 지금 규모에 과함 |

## 결정
- A를 기본으로 한다. B는 보조로 남긴다: '토큰만 복사'(환경 변수용), 이미 발급한 토큰은 원문이 없으므로 '지시문만 복사'(토큰 자리에 환경 변수 안내).
- 글은 순수 함수 `src/lib/agent-connect.ts`가 만든다. 토큰은 정확히 한 번 들어가고, 글은 AI에게 그 뒤로 `$SCHOOL_AGENT_TOKEN`으로만 쓰고 값을 출력·로그·커밋·다른 대화에 다시 쓰지 말라고 시킨다.
- 서버는 토큰 원문을 저장하지 않는 규칙 그대로(해시만). 연결 글은 브라우저에서만 만든다.

## 위험과 대응
- 토큰이 AI 대화 기록에 남는다 → 화면 한 줄 안내(필요한 범위만, 기한 7일 권장, 끝나면 폐기), 기본 기한 7일.
- 대화 기록이 새어 나감 → 폐기하면 바로 401, 범위 밖은 403, 마지막 사용·활동 기록으로 이상한 사용을 본다.
- 자동 공개 토큰 → 글에 '저장하면 바로 공개'와 '저장 전에 사람에게 보여 주고 답을 받는다' 규칙을 넣는다.

## 다시 검토할 조건
학교가 많아져 대화 기록 유출 사례가 생기거나, AI 쪽에 비밀 저장 기능이 쉬워지면 안 C(교환 코드)를 다시 본다.

## 확인 방법
- `tests/agent-connect.test.ts`: 토큰 정확히 한 번, 토큰 없을 때 원문 없음, 권한별 문장, 자동 공개 경고, 주소 지정 범위·공개 경로, AI 종류별 한 줄.
- E2E 34차 단계: 연결 글에 토큰 한 번, '연결 글 한 번에 복사'가 클립보드와 같음, '지시문만 복사'에 토큰 없음.
