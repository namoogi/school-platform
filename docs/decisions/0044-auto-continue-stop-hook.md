# 0044. 멈춤 방지: 차례를 끝내는 글의 표시 + Stop 훅으로 다음 단계 자동 진행

- 상태: 채택
- 날짜: 2026-11-28
- 제안: Claude(관제)
- 결정: 사용자(2026-11-28, 선택지 중 '멈춤 방지 훅 + 규칙 (추천)')
  - "추천 프롬프트의 대부분이 사람의 판단이 꼭 필요하다기보다는 다음 프로세스로 넘어가면 되는 것들인데 멈춰있는 경우가 많이 있다. … 다음 프로세스를 진행하는 문구는 자동입력해 줄 수 있나?"
- 관련: AGENTS.md '승인을 기다리며 멈추지 않는다'(2026-11-23), ADR 0015(결정 요청), `docs/automation/SCHOOL-SESSIONS.md`

## 원인
- 세션은 차례를 끝내면 사람 입력이 올 때까지 깨울 것이 없다.
- "다음엔 X 하겠습니다"로 끝내면, 규칙상 X는 되돌릴 수 있어 해도 되는 일이라도 그대로 멈춘다.
- 앱의 '추천 프롬프트'를 대신 눌러 주는 기능은 없다. 그래서 세션이 스스로 끝내지 않게 하는 쪽으로 풀었다.

## 고려한 안
| 안 | 판단 |
| --- | --- |
| **멈춤 방지 훅 + 규칙(채택)** | 저장소의 `.claude/settings.json` Stop 훅이 이 저장소의 모든 세션(클라우드 포함)에 적용된다. 추가 비용은 원래 하려던 일만큼이다 |
| 관제 순찰 예약 | 훅이 못 잡는 경우까지 잡지만, 순찰마다 사용량이 든다. 필요해지면 더한다 |
| 규칙만 강화 | 비슷한 규칙이 이미 있는데 멈추고 있었다. 효과가 약하다 |

## 결정
1. 차례를 끝내는 글에 표시를 붙인다.
   - `[결정 필요]`: 사람 판단이 꼭 필요한 일이다(AGENTS '변경 원칙'의 되돌리기 어려운 일, 범위가 갈리는 선택). 결정 요청을 올린 뒤 쓴다.
   - `[대기]`: CI·배포·다른 세션을 기다린다. 깨울 장치(백그라운드 감시·`send_later`·PR 구독)를 걸어 둔 뒤 쓴다.
   - `[완료]`: 맡은 일이 끝났거나, 질문에 답만 하는 차례였다.
2. Stop 훅 `.claude/hooks/auto-continue.mjs`(Claude Code 공식 Stop 훅 입력 `last_assistant_message`·`stop_hook_active`·`background_tasks`·`session_crons`)
   - 막는다(`decision: block`): 표시가 없고, 백그라운드 작업·예약도 없을 때. 이유 문구가 '다음 단계를 지금 진행하라'와 표시 안내를 세션에 준다.
   - 멈춤 허용: 표시가 있음, 백그라운드 작업이나 예약이 있음, 이미 이 훅 때문에 이어서 일하는 중(무한 반복 방지), 빈 글, `SP_AUTO_CONTINUE=off`
   - Claude Code 자체 상한: 훅으로 8번 연속 막으면 다음은 끝낸다.
3. 사람과 대화하는 세션에도 적용된다. 질문에 답만 하고 끝내는 차례면 `[완료]`를 붙인다. 훅이 막더라도 한 번뿐이다.

## 위험과 대응
- 세션이 사람 판단이 필요한 일까지 밀고 갈 위험: 훅 문구가 '사람 판단이 필요한 일만 멈춘다'와 그 목록을 함께 준다. 되돌리기 어려운 일의 기준은 AGENTS.md 그대로다.
- 토큰이 늘 위험: 막는 것은 차례마다 한 번뿐이다. 늘어나는 것은 원래 하려던 다음 단계만큼이다.
- 끄기: 세션 환경 변수 `SP_AUTO_CONTINUE=off`

## 확인 방법
- `tests/auto-continue.test.ts`(`test:unit`): 표시 없으면 막음, 표시 셋, 이어서 일하는 중, 백그라운드·예약, 끄기·빈 글·이상한 입력
- 운영 확인: 병합 뒤 새로 여는 세션부터 적용된다(이미 열린 세션은 설정을 다시 읽을 때)
