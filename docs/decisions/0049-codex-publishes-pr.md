# 0049. Codex 구현 작업은 실제 GitHub PR 게시까지가 완료

- 상태: 채택
- 날짜: 2026-11-28
- 제안: Codex(#232), 검토·정리: Claude(홈페이지 세션)
- 결정: 사용자(2026-11-28) — "앞으로 작업이 끝나면 자동으로 PR을 올리도록"
- 관련: `docs/COLLABORATION.md` 8절 'PR 게시 완료 기준', AGENTS.md '변경 원칙', 이슈 #197 → PR #231

## 원인
- Codex 클라우드 작업은 구현·검사를 마쳐도 결과를 작업 안에만 두고 'Create PR' 단추 앞에서 멈춘다.
- #197은 02:11 UTC에 끝났는데 PR(#231)은 06:27 UTC에 올라왔다. 그동안 Claude의 검수·통합 시험·병합이 4시간 넘게 기다렸고, 선생님께 단추 클릭을 부탁해야 했다.

## 고려한 안
| 안 | 판단 |
| --- | --- |
| **Codex가 PR 게시까지 하는 것을 완료 기준으로(채택)** | 사람 중계가 사라진다. 클라우드에서 막히면 결과를 회수해 로그인된 로컬에서 게시한다 |
| 선생님이 매번 'Create PR' 클릭 | 지금까지의 방식. 사람이 병목이 된다 |
| Claude가 초안 PR을 먼저 만들고 그 PR에서 `@codex` | 8절 기록상 PR 댓글의 `@codex`도 브랜치에 올리지 않아 해결되지 않는다 |

## 결정
1. Codex 구현 작업은 검사 → 작업 브랜치 커밋·push → `main` 대상 PR 게시 → PR URL 확인까지 해야 완료다. 같은 작업의 PR이 있으면 갱신한다. 읽기 전용 질문·검토에는 빈 PR을 만들지 않는다.
2. 게시가 끝내 막히면 완료로 표시하지 않고 정확한 오류와 남은 단계를 보고한다.
3. Claude는 `@codex` 요청 글에 "PR 게시까지 직접 하고 PR 번호를 댓글로 남겨 주세요. 게시하지 못하면 이유를 적어 주세요"를 넣는다. 완료 댓글이 왔는데 PR이 없으면, 선생님께 단추 클릭을 부탁하기 전에 같은 이슈에서 게시를 다시 청한다.
4. 디자인 작업의 독립 검토·통합 시험·병합은 Claude가 맡는다(사용자 별도 지시 우선).
5. 규칙 본문은 `docs/COLLABORATION.md` 8절 한 곳에 두고, AGENTS.md에는 가리키는 한 줄만 둔다.

## 영향·다시 볼 조건
- 이 규칙은 도구 권한을 새로 주지 않는다. 클라우드에서 push가 실제로 되는지는 작업마다 확인한다.
- Codex 클라우드가 스스로 PR을 만들게 되거나, 게시 실패가 반복되면 다시 본다.
