# 0027. 관제 기본판 · 학교 복제 · 보고 계약 (느슨한 결합)

- 상태: 채택 (2026-11-25)
- 결정: 사용자
  - 지시 원문: "관제는 가장 기본적인 학사시스템과 홈페이지 등의 얼개를 가지고 있지만 학교를 생성할 때는 해당 내용을 복제하여 생성한 후, 그 후에는 각 학교의 AI 개발 작업 등을 통해 구조가 변경될 수 있으므로 관제와 각 학교가 DB 상으로 연결되어 있으면 문제가 생길 수 있다. 다소 느슨하면서도 유동적으로 대응할 수 있는 구조여야 해. 관제에서는 각 학교별 기본적인 정보는 파악할 수 있어야 하기에 각 학교에 통일되어 나가고 정보를 수집하는 길과 각 학교가 자체적으로 구조 변경을 통해 최적의 학사시스템을 맞춤형으로 제작할 구조가 필요해."
  - 선택: **논리 분리 먼저**, 기본판 갱신은 **제안으로 보내고 학교가 수락**.
- 관계: ADR 0019(규모·셀), 0024(관제 = 전체 관리자), 0025(학사 토대 — 확장 사다리 E1~E6)

## 결정
1. **두 영역**
   - **관제 영역**: 기본판(`baselines`), 학교별 기본판 기록(`school_baselines`), 갱신 제안(`baseline_offers`), 보고 스냅샷(`school_reports`). 학교·라이선스·구성원·관제 센터도 이 영역이다.
   - **학교 영역**: 학교가 가진 사본과 학교 자료(코드 목록·척도·성적 정책·학사·홈페이지…). 학교와 학교 AI는 자기 영역만 바꾼다.
2. **학교 생성 = 최신 기본판 복제**
   - `schools`에 학교가 생기면 트리거가 기본판의 코드·척도·성적 정책을 학교 사본으로 만들고, 몇 판에서 갈라졌는지 남긴다.
   - 학교는 기본판을 실시간으로 읽지 않는다. 예전에 플랫폼 기본 코드를 `school_id` 없이 공유하던 방식은 지웠다.
3. **기본판 갱신 = 제안**
   - 관제가 새 판을 내면(`app.publish_baseline`, base_version 409) 학교마다 제안이 생긴다. 제안에는 '추가할 것'과 '부딪치는 것'(학교가 고친 항목)이 담긴다.
   - 학교 관리자(학교 AI를 쓰는 관리자 포함)가 수락·거절·보류한다(`app.decide_baseline_offer`).
   - 수락하면 추가할 것만 반영한다. 부딪치는 항목은 학교 값을 유지한다. 자동 덮어쓰기는 없다.
4. **관제의 정보 수집 = 보고 계약**
   - 관제는 학교 내부 표를 직접 읽지 않는다. 판 번호가 붙은 계약 함수 `app.school_report_v1(학교)`만 부른다.
   - 계약 항목:
     - 학교 기본 정보, 관할·인가, 기본판 판, 모듈
     - 인원 수: 구성원·사람·재학·교직원·개설·마감·홈페이지 항목
     - 저장소 사용량, 30일 활동(에이전트·AI 호출·토큰·비용)
   - 모은 것은 `school_reports`에 스냅샷으로 남는다(`app.collect_school_reports`).
   - 학교 내부 구조가 바뀌어도 계약 모양은 지킨다. 바꿔야 하면 `school-report/2`를 새로 만들고 한동안 둘 다 낸다.
   - 사용량 화면(`src/lib/usage.ts`)도 이 계약을 거친다.
5. **학교 맞춤 구조**: ADR 0025 확장 사다리(E1 값 → E2 규칙 → E3 기록 유형 → E4 화면·출력 → E5 흐름)는 학교 영역 안에서 일어난다. 관제와 공유하는 것은 보고 계약뿐이다.
6. **나중에 셀로**: 학교 하나가 큰 구조 변경이나 큰 규모가 필요해지면, 그 학교만 별도 스키마나 DB(ADR 0019 셀)로 옮긴다. 관제와는 같은 계약(그때는 API)으로 이어지므로 관제 쪽은 바뀌지 않는다.

## 예외 (관제가 학교 영역에 닿는 경우)
- **플랫폼 기반 시설 작업**: 파일을 R2로 옮기는 일(`copyToStorage`)과 마이그레이션은 학교 정보를 모으는 일이 아니라 기반 시설 관리라서 예외로 둔다.
- **학교 일 처리**: 관제 세션이 전체 관리자로 학교 일을 처리할 때(ADR 0024)는 그 학교에 '입장'해 학교 권한으로 일하고, 입장 기록이 남는다.

## 하지 않은 것 (다음)
- 홈페이지 템플릿을 기본판에 넣는 일은 홈페이지 템플릿 차시에서 한다(사용자 대기열).
- 관리 화면(기본판 제안 목록·수락, 학교 보고 대시보드)은 다음 차시에 만든다. 지금은 API·함수까지다.
- 학교별 스키마나 DB 분리는 필요가 생길 때 한다(위 6).
