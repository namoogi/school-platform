# 0038. 학교별 격리 등급 배정: 공용·확장·전용·독립을 학교마다 고르고 판으로 남긴다

- 상태: 채택
- 날짜: 2026-11-27
- 제안: Claude(관제)
- 결정: 사용자(2026-11-27) "각 4단계 모두 승인하고 학교별로 선택 및 배정이 가능하도록 설계 및 구현 진행하자는거지."
- 관련: ADR 0019(규모·셀), 0035(공용 기본·이전 가능), `docs/research/system-tiers-2026-11.md`(등급·원가), `docs/SCHOOL-MOVE.md`

## 결정
1. **등급 판** `school_placements`
   - 학교마다 등급(공용·확장·전용·독립)·진행 상태·옮긴 주소·이유·월 원가를 판으로 쌓는다.
   - 진행 상태: 정함 → 옮기는 중 → 옮김 / 운영 중
   - 판은 고치지 않는다. 쓰기는 전체 관리자의 명령 함수뿐이고, `base_version`이 낡으면 409로 거부한다.
   - 학교 구성원은 자기 학교 판만 읽는다.
   - 판이 없으면 공용·운영 중이다.
2. **화면**: 전체 관리 → **등급**(`/admin/placements`)
   - 등급별 설명·원가 범위표
   - 학교마다 지금 등급, 새 판 쓰기, 이력
   - 처음부터 여러 언어로 만들었다(ADR 0037).
3. **옮김 안내**: 마지막 판이 '옮김'이면 공용 앱의 그 학교 화면 위에 새 주소 안내 띠가 뜬다.
4. **등급마다 사는 곳** [판단]: 공용 앱 안에서 학교마다 다른 DB로 요청을 나눠 보내는 방식(셀 연결)은 쓰지 않는다. 대신 **전용·독립은 같은 코드를 따로 배포한 앱 + 따로 만든 DB**로 돌린다.

   | 등급 | 앱 | DB | 운영 |
   |---|---|---|---|
   | 공용 | 공용 앱 | 공용 DB | 우리 |
   | 확장 | 공용 앱(핵심) + 학교 별관 앱 | 공용 DB + 학교 별관 프로젝트 | 우리(별관 코드는 학교 AI) |
   | 전용 | 그 학교 전용 배포(우리 Vercel 팀) | 그 학교 전용 Supabase 프로젝트(우리 조직) | 우리 |
   | 독립 | 학교·기관 명의 배포·서버 | 학교·기관 명의 DB | 학교 |

   - 따로 배포하면 앱 코드에 학교→DB 분기를 넣지 않아도 된다. 마이그레이션·시험·보안 문이 그대로 통한다.
   - 대가: 배포·마이그레이션을 학교 수만큼 돌려야 한다. GitHub Actions 행렬로 묶는다(다음 단계).
   - 관제가 학교 정보를 모을 때는 보고 계약(`app.school_report_v1`)을 원격 주소로 부르는 방식으로 넓힌다(다음 단계).
5. **학교 화면 기본 언어**(ADR 0037 5항 보충): 사용자가 화면 언어를 고르지 않았으면 쿠키 다음으로 학교 기본 언어(`schools.locale`)를 쓴다. 영어 학교는 처음부터 영어로 열린다. 학교를 옮겨도(전용·독립) 같은 규칙이다.
6. **비용이 생기는 일**(새 Supabase 프로젝트·Vercel 프로젝트 만들기)은 등급을 '정함'으로 둔 뒤, 실제로 만들기 전에 사용자 확인을 받는다. 등급 판을 쓰는 것만으로는 비용이 생기지 않는다.

## 고려한 안
| 안 | 판단 |
| --- | --- |
| 공용 앱이 학교마다 DB 연결을 골라 쓰는 셀 연결 | 보류: `asUser`·로그인·학교 문맥 전체를 바꿔야 한다. 셀(여러 학교 묶음)이 필요해질 때(ADR 0019 단계 D) 다시 본다 |
| **전용·독립은 따로 배포(채택)** | 코드 분기 없음, 이전 도구(ADR 0035)로 데이터만 옮김 |
