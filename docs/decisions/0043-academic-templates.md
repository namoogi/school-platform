# 0043. 학사 관리 템플릿 · 학년 체계 · 시연 학교

- 상태: 제안(1단계는 되돌릴 수 있어 추천안으로 진행·병합, 2단계 이후는 이 설계로 진행하되 결정 요청으로 확인)
- 날짜: 2026-11-27
- 제안: Claude(학사 시스템 개발 세션)
- 검토: Codex(PR 검토)
- 결정: 사용자 지시(2026-11-27 관제 대화) — "가상의 학교를 하나 만들고 초1~고3 학생을 가명으로", "학교마다 학교급 생성, 학년은 한국식·미국식·커스텀", "학사 관리 템플릿 여러 개, 고른 뒤 학교 AI 작업", "우수 SIS UI·UX를 참고해 템플릿 설계"
- 관련: ADR 0025(F1 학년 서수·학교급), 0027(기본판 → 학교 사본), 0035(공용 기본 + 설정값 맞춤), 0040·0041(계산식 견본), 0042(마감 연결), F5 기능 꾸러미·`package` 토큰
- 조사: `docs/research/sis-ux-2026-11.md`(UI·UX), `docs/research/sis-rea-2026-11.md`(구조)

## 배경
F1~F6과 학사 화면(71~76차)은 있지만, 새 학교가 학사 시스템을 쓰려면 학교급·학년·학기·척도·정책·출력을 하나씩 만들어야 한다. 또 들어가 보면 학사 흐름이 보이는 학교가 없다(예시학교 A·B는 시험용 빈 골격). 확인한 빈틈:
- 학년 행(`grade_levels`, 서수)은 있지만 **부르는 방식(한국식·미국식)을 학교가 고르는 자리**가 없었다.
- 학생의 학년은 반(`homerooms.grade`, 학교급 안 순번)으로만 알 수 있었고, **반이 학년 행을 가리키지 않아** 정규 서수와 이어지지 않았다.
- 학교 유형별 기본 묶음(템플릿)이 없다. 기본판(ADR 0027)은 하나뿐이다.

## 조사에서 가져온 원리 (`sis-ux-2026-11.md` 요약, 판단)
1. 상용 SIS는 '학교 유형 템플릿 고르기' 화면이 거의 없다. 교육과정 유형 선택(Toddle)·작은 척도 프리셋(Google Classroom)·의존 순서 점검표(Blackbaud·Infinite Campus)·지난해 복사 마법사로 나눠 푼다 → 우리는 이 넷을 **템플릿 → 학교 사본 → 남은 점검표 → AI 맞춤 → 사람 확정** 한 흐름으로 묶는다.
2. 교사 화면은 수업 중심, 관리자 화면은 학생·설정 중심. 출결은 기본 출석 + 예외만, 성적부는 격자 + 빈 칸만 채우기, 마감은 검토 → 잠금 → 발행(잠금 해제 없이 정정 새 판).
3. 4세대 나이스 출결(학생 한 명씩 입력)은 일괄 경로를 없앤 실패 사례다. 기능 수보다 일괄·기본값·예외 우선이 중요하다.
4. 켠 구획만 보인다(Toddle): 템플릿에 따라 석차·평점 같은 구획을 아예 숨긴다.

## 결정

### 1. 학교급·학년 체계 모델 (1단계, 구현)
- 학년 행의 **서수가 기준**이다(PK=-1, K=0, 1~12 — F1 그대로). 학년 체계는 그 서수를 부르는 방식이고, 학교 관할 판(`school_profiles.grade_scheme`)에 판으로 쌓는다(체계를 보내지 않은 판은 직전 값을 잇는다).

  | 체계 | 학교급(코드) | 학년 표기 |
  | --- | --- | --- |
  | `kr` 한국식 | 초등 `elementary` 1~6 · 중등 `middle` 7~9 · 고등 `high` 10~12 | 초1~초6 · 중1~중3 · 고1~고3 |
  | `us` 미국식 | 초등 K~5 · 중등 6~8 · 고등 9~12 | K · Grade 1~12 |
  | `custom` | 한국식 자리에서 시작 | 학교가 학년마다 적은 표기(`grade_levels.label`) |

- 표기는 kr·us면 서수에서 정한다. custom은 학교 관할 판의 표기(`grade_labels`, 서수 → 글)를 쓰고, 없으면 학년 행 표기를 쓴다. 체계에 없는 서수(PK 등)는 학년 행 표기다(`src/lib/grade-schemes.ts` `gradeLabel`). 그래서 체계를 바꾸거나 표기를 고쳐도 학년 행(바꿀 수 없는 기록)을 고치지 않는다.
- 학년의 정체는 **서수**다. '학교급·학년 만들기'는 이미 있는 학교급(같은 코드)과 학년(같은 서수)은 두고 빠진 것만 더한다. 한국식 e1과 미국식 g1은 같은 학년이라 체계를 바꿔도 학년 행이 늘지 않는다(Codex #172 P1). 학교급 경계는 처음 만든 때를 따른다(한국식으로 만든 뒤 미국식으로 바꾸면 6학년은 초등에 남는다). 쓰기는 기존 명령 함수(`app.add_school_level`·`add_grade_level`·`set_school_profile`)만 쓴다(새 쓰기 경로 없음).
- 반은 학년 행을 가리킨다: `homerooms.grade_level_id`(복합 외래키) + `app.add_grade_homeroom(학교, 학년도, 학년, 이름)`. 학교급·학교급 안 순번은 DB가 학년 행에서 정한다. 옛 반(빈 값)은 그대로 쓴다.
- 수업(개설)도 학년을 가리킨다(110차, 관제 승인 #26): `course_offerings.grade_level_id`(빈 값 = 학교급 전체). 학기 시작 자동 수강은 학년이 있으면 그 학년도 반 배정의 학년 서수가 같은 학생만 넣는다.
- 다음에 볼 것(이 ADR 범위, 2단계 이후): 무학년·혼합 연령 학교급, 학년 넘기기 규칙(해마다 한 칸, 졸업 다음 보관, 유급·월반 예외).

### 2. 학사 관리 템플릿 (2단계, 113차 구현)
템플릿 = **관제 기본판의 한 갈래**(ADR 0027). 학교가 고르면 그 내용을 학교 사본으로 복제하고, 이후 학교 AI(`package` 토큰)·학교 관리자가 사본만 고친다. 기본판 갱신은 템플릿별 제안으로 가고, 학교가 고친 항목은 학교 값을 유지한다. 계산식은 **견본 이름만 참조**한다(ADR 0040·0041, 관제 몫).

| 템플릿 | 학교급·학년 | 학기 | 척도·계산식 견본 | 출결 | 출력 프로필 | 숨기는 구획 |
| --- | --- | --- | --- | --- | --- | --- |
| 한국 일반 초·중·고 | kr 초1~고3 | 2학기 | 초 서술, 중 `kr_elective`, 고 `kr_achievement`(공통)·`kr_elective` + 기재요령 2026 견본 | 하루 + 교시(고) | 자체 학생부 | — |
| 한국 대안학교(프로젝트·P/F) | kr 또는 custom, 무학년 선택 | 2학기 + 프로젝트 마디 | `pass_fail` + 역량 틀 + 서술 중심(드리미 방식 견본) | 하루 | 자체 학생부·학업 기록 | 석차·평점 |
| 미국 K-12 | us K~12 | 2학기 + 4분기 성적 기간 | `us_letter`·`us_plus_minus` + GPA·Carnegie 학점 견본 | 하루 + 교시 | 성적증명서·학교 소개서 | 석차등급 |
| 국제학교(IB·AP 혼합) | us 또는 custom(PYP·MYP·DP) | 2학기 | `us_letter` + IB 1–7(척도 판 추가) | 교시 | 성적증명서·영어권 학업 기록 | 석차등급 |
| 홈스쿨 공동체 | custom, 무학년 | 학기 1~3 | `pass_fail` + 서술 | 하루(가정 기록) | 영어권 학업 기록 | 석차·평점·교시 출결 |

113차 구현: 관제 표 `academic_templates`(키·판, 추가만, 학교는 `app.academic_templates()`로 최신 판만), 적용 `applyTemplate`(학교급·학년 → 학기 구조(없을 때만) → 척도(없는 코드만)), 관할 판 `template_key`·`template_version`. 계산식은 견본 이름만.

123차 구현(새 판 제안): 열린 제안은 저장하지 않고 계산한다(학교가 쓰는 템플릿의 최신 판 > 학교 판 → '지금 판 → 최신 판'). 참은 학교 관할 판 하나이고, 학교의 결정(수락·보류·거절)만 `academic_template_decisions`에 추가로 쌓는다. 수락은 기존 적용 길로 최신 판을 적용한 뒤 같은 트랜잭션에서 기록한다. 같은 템플릿의 판을 옮기는 길은 제안 수락 하나다. 제안을 표로 저장해 학교 판과 맞추던 첫 설계는 되돌아오기·동시 공개·학교 이전마다 어긋나 버렸다(Codex 199번 PR 검토).

118차 구현(숨기는 구획): 템플릿 `hide`는 학교가 처음 템플릿을 고를 때만 관할 판 `hidden_sections`로 복사하고, 그 뒤에는 학교 값(템플릿 화면 '우리 학교가 숨기는 구획')을 쓴다. 읽는 길은 `hiddenSections()` 하나. 지금 실제로 빠지는 곳은 발행본의 평점(GPA: 미국 성적증명서·학교 소개서·태국 GPAX)이다. 석차·석차등급·교시 출결은 아직 보여 주는 화면이 없어 값만 둔다.

묶음 내용은 기존 구조의 설정값뿐이다: 학교급·학년 체계, 학기 구조 규칙 판, 척도 판, 성적 정책 판, 계산식 견본 이름, 출결 정책 판·코드 사본, 출력 프로필 판, 기능 꾸러미(F5) 켜기 목록. 새 표가 필요하면 `templates`(관제 표, 판으로 쌓음)만 두고 학교 쪽은 기존 사본 표를 쓴다. 에이전트 DDL·코드 업로드는 없다(ADR 0025 E6).

### 3. 화면 흐름 (2~3단계, 설계)
```
[1 템플릿 고르기: 카드 5장 '고르면 생기는 것'] → [2 나란히 비교] → [3 학교 사본 만들기: 바뀌는 것/안 바뀌는 것/되돌리기]
   → [4 남은 설정 점검표: 템플릿이 채운 단계는 접고, 학년도 날짜·수업일·교직원만 펼침]
   → [5 AI 맞춤: 학교 AI가 성적표·규정을 분석해 새 판 초안 = 변경 묶음 + 전후 미리 계산] → [6 사람 확정] → [7 시연 학생으로 둘러보기]
```
- 학교 화면 곳곳에 '견본 그대로 / 학교가 바꿈' 표시(ADR 0027 학교 값 유지가 보이게).
- 5는 `docs/agents/grade-intake.md` 절차를 그대로 쓴다. 플랫폼 서버의 유료 분석은 만들지 않는다(ADR 0032).

### 4. 시연용 가상 학교 (1단계, 구현)
- `온누리 시연학교 (가상)`, 주소 `demo-academy`, 한국식 체계, 관할 KR·대안. 전체 관리 → '시연 학교 만들기'(`POST /api/admin/demo-school`, 전체 관리자만).
- 학생: 학년마다 4명 × 초1~고3 = 48명. 이름은 모두 **'가상 ○○'**(성 '가상' + 자연 낱말), 로마자 `Demo Student 01`~. 실제 사람 정보는 없다.
- 2026 학년도, 1·2학기(날짜 포함), 3월 수업일 10일. 학년마다 반 1개(`초1 1반` …).
- 수업 36개(학년 × 3과목, 학년 칸 + 분반 = 학년 표기, 학기 시작에 그 학년만 자동 수강 — 110차부터. 109차 운영 시연 학교는 승인 갈래로 만들어졌다). 초등: 국어·수학·마을 탐구 프로젝트(P/F + 의견), 중등: 국어·수학·과학(수행·지필 → 성취도), 고등: 국어·수학·영어.
- 평가 결과(같은 씨앗의 난수라 실행마다 같음), 과목 서술 예시, 결석·지각 몇 건, 1학기 수업 마감 36개, 고3 행동특성·증거물·학년도 기록 마감 4개·자체 학생부 발행본 1개.
- 모든 쓰기는 화면·API와 같은 라이브러리·명령 함수로 한다(표 직접 쓰기 없음). 다시 불러도 두 번 만들지 않는다.
- **되돌리기**: 기록은 지우지 않는 설계(지침 4·8)라 시연 학교는 학교 상태를 '정지'로 내려 감춘다. 학교 이전 도구(`school-move`)로 통째로 떼어 낼 수도 있다.
- 2단계 뒤에는 시연 학교를 템플릿별로(한국 일반·한국 대안·미국 K-12) 만들 수 있게 넓혀 '같은 화면이 템플릿에 따라 구획만 달라지는 것'을 보여 준다.

## 고려한 안
| 안 | 내용 | 판단 |
| --- | --- | --- |
| **A. 서수 기준 + 체계는 관할 판(채택)** | 학년 행은 그대로, 부르는 방식만 판으로 | 체계를 바꿔도 학년 행을 고치지 않음. 기존 쓰기 경로 재사용 |
| B. 체계마다 학년 행을 새로 | 체계를 바꾸면 학년 행을 다시 만듦 | 학년을 가리키는 반·기록이 갈라짐 |
| C. 학년 표기를 화면 코드에만 | 학교가 고르는 자리 없음 | 커스텀 학교(대안·홈스쿨)를 못 받음 |
| 시연 학교: **앱 라이브러리로 생성(채택)** / 시드 SQL / 시드 스크립트가 표에 직접 | 운영에도 같은 경로로 넣을 수 있고 쓰기 규칙(관리자·409·마감)을 그대로 거침 | 직접 쓰기는 지침 2 경로 밖 |

## 영향
- DB: 마이그레이션 `20261128000900_grade_schemes.sql` — `school_profiles.grade_scheme`(빈 값 허용)·`grade_labels`(커스텀 표기, 기본 `{}`), `homerooms.grade_level_id`(복합 외래키, 빈 값 허용), `app.set_school_profile` 교체(체계 잇기), `app.add_grade_homeroom` 추가. 기존 행·함수 서명은 그대로다.
- 데이터 경계: 새 학교 표 없음. 반 → 학년은 `(grade_level_id, school_id)` 복합 외래키, 다른 학교 학년은 함수가 거부(시험 있음). 학교 ID는 로그인 소속에서.
- 화면: `/academics` 학교급 카드에 학년 체계 고르기·학년 칩, 전체 관리에 '시연 학교 만들기'.
- 되돌리기: 열 두 개는 빈 값 허용이라 앱을 되돌려도 남아 있어도 된다. 시연 학교는 정지.
