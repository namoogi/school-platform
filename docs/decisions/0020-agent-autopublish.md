# 0020. 작업 토큰 '자동 공개' 권한: 저장하면 바로 공개

- 상태: 채택
- 날짜: 2026-11-24
- 제안·결정: 사용자 — "룽아룬숙사 성품동화에 대한 Codex 토큰에 자동 공개 기능까지 넣어서 주도록 하자."
- 관계: ADR 0016(공개 권한, "만들기·고치기는 저절로 공개되지 않음")을 **토큰 단위로 넓힌다**. 0016은 고치지 않고 이 기록이 덧붙인다. 0016의 기본은 그대로(자동 공개를 고르지 않은 토큰은 저장해도 시안).

## 고려한 안
| 안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 권한 `autopublish` (채택)** | 발급 때 고르면 만들기·새 판 저장 즉시 서버가 그 판을 공개 | 에이전트가 잊어도 확실, 패널·기록에 보임, 토큰마다 켜고 끔 | 잘못된 내용이 바로 공개될 수 있음 |
| B. 에이전트 지시문에 '저장 뒤 공개 호출' | 서버 변경 없음 | 간단 | 에이전트가 빠뜨리면 공개 안 됨, 학교 설정에 드러나지 않음 |
| C. 학교 설정 '에이전트 저장은 모두 공개' | 한 번에 | 사람 시안까지 섞일 위험, 범위가 너무 넓음 |

## 결정
- 권한 `autopublish`는 `publish`와 함께만(DB CHECK·발급 함수·화면). 공개는 지금과 같은 `agent.publish_entry`로 같은 트랜잭션 안에서 한다 — 공개가 실패하면 저장도 되돌린다.
- 범위(학교·종류·주소)·보관·되살리기·설정 규칙은 그대로. 공개 기록 책임자는 발급 관리자, 활동 기록에 '공개'가 남는다.
- 권한은 발급 뒤 바꾸지 않는다. 자동 공개가 필요하면 새로 발급하고 예전 토큰은 폐기한다.

## 위험과 대응
- 잘못된 내용이 바로 공개: 주소를 정하고 기한을 짧게 권함(패널 안내), 에이전트 안내에 '저장 전 확인·저장 뒤 알림', 사람은 언제든 이전 판 재공개·공개 내림.
- 토큰 유출: 폐기하면 즉시 멈춤, 마지막 사용·활동 기록 표시.

## 확인 방법
- `tests/round45.test.ts`: 공개 없이 자동 공개 발급 거부(함수·CHECK), 만들기·새 판 즉시 공개(판 번호·책임자·기록), 공개 권한만이면 시안, 학교·주소 경계 양방향, 보관한 항목은 저장도 공개도 안 됨.
