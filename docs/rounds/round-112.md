# 112차: 번역 묶음 갱신 규칙 · 홈페이지 편집기 블록·칸 이름 영어 (ADR 0037)

> **요약** 코드에서 고친 영어 문구가 운영에 들어가도록 번역 묶음 넣기 규칙을 바꿨다(사람이 고친 번역은 그대로). 홈페이지 편집기의 블록 이름·팔레트 설명·칸 이름도 관리 화면 언어로 보인다.

> **왜** 사용자 결정(2026-11-27): "그렇게 바꿔 줘. 편집기 블록 이름도 옮기고". 묶음은 빈 칸만 채워서, #149처럼 기존 영어를 고쳐도 운영에는 예전 글이 남았다.

```terms
용어 | 쉬운 설명 | 예시
번역 묶음 | 코드에 함께 두는 기본 번역 파일. 배포 때 DB 사전에 넣는다 | i18n/en.json
사람이 고친 번역 | 관리 화면(언어·번역)에서 사람이 저장한 번역. 누가 고쳤는지 남는다 | 'Log in'을 관리자가 고친 것
```

## 한 일
- `scripts/i18n-packs.mjs`: 빈 칸은 채우고, **묶음이 넣은 번역(`updated_by` 없음)** 은 묶음 글이 바뀌면 새 글로 바꾼다. 사람이 고친 번역(`updated_by` 있음)은 덮지 않는다. 마이그레이션 없음(이미 있는 칸으로 구분).
  - 시험: `tests/i18n-db.test.ts` — 묶음 행은 바뀌고 사람이 고친 행은 그대로.
  - ADR 0037 6항 고침.
- 편집기(`LiveEditor`)
  - 구조 목록·구역 막대의 블록 이름: `blockLabel`(장면 캐릭터 PNG·잡지형 구역 모양 포함).
  - 팔레트 칸 이름·설명: `paletteText`(이름표 `site.pal.hint.*` 19개).
  - 화면에서 고칠 때 보이는 칸 이름(예: '머리 링크 이름' → 'Header link label', '3번 카드 제목' → 'Card 3 title'): 공개 렌더러가 넘기는 한국어 이름을 `site.field.*` 기준 문구와 맞춰 바꾼다(`fieldLabel`). 공개 홈페이지는 학교 언어를 따르는 별도 영역이라 렌더러는 그대로 둔다.
  - 시험: 렌더러의 편집 칸 이름이 모두 이름표를 갖는지(새 칸을 더하면 알려 줌).
