# 84차: UI 점검 루프 들이기(ADR 0033) + 첫 기계 검사로 찾은 휴대폰 화면 결함 고침

- 날짜: 2026-11-26 · 세션: 관제
- 사용자: 드리미포털용 `UI_REVIEW.md`를 올리고, 적용 범위로 '문서 + 자동화'를 골랐다.

> **요약** 'Claude 구현 → 화면 캡처·기계 검사 → Codex 점검 → Claude 선별·수정' 절차를 저장소 규칙으로 들였다. 처음 돌린 기계 검사가 휴대폰 화면 결함을 실제로 찾아냈고, 고쳐서 등록된 16개 화면 × 3가지 폭(54장) 모두 통과했다.

> **왜** 에이전트는 화면을 보지 못한다. 코드로는 멀쩡해도 휴대폰에서 화면이 옆으로 밀리는 것을 이번에도 아무도 몰랐다. 기계 검사가 사람보다 먼저 잡았다.

- **자동화(모델 호출 없음)**
  - `npm run ui:review -- <페이지…|--all>`(`scripts/ui-review.mjs`)
    - 3가지 폭 × 상태로 캡처한다.
    - 콘솔 오류, 같은 출처 HTTP 4xx·5xx(주소 포함), 가로 스크롤, axe serious 이상을 검사한다.
    - 결과는 `.ui-review/<페이지>/`에 쌓인다(커밋하지 않음).
    - 로컬 주소와 합성 예시 계정만 쓴다.
  - 페이지 목록: `scripts/ui-review.pages.mjs`(16개)
  - `npm run lint:colors`(`scripts/lint-colors.mjs`, CI 단계 추가)
    - 토큰 밖 색·인라인 px를 잡는다.
    - 지금 있는 24개는 기준 목록으로 묶고, 새로 생긴 것만 실패로 본다.
- **첫 기계 검사에서 찾아 고친 것** (처음 58건 → 0건)

| 찾은 것 | 원인 | 고침 |
|---|---|---|
| 모든 화면에서 HTTP 404 | 사이트 아이콘(favicon)이 없음 | `src/app/icon.svg`(學) 추가 |
| 휴대폰·태블릿(≤768px)에서 화면 전체가 옆으로 1,108px 밀림 | 메뉴가 15개로 늘어 한 줄을 넘침. 메뉴 줄 가로 스크롤을 분석형 화면의 툴팁용 규칙이 덮어씀 | 휴대폰에서는 메뉴 줄만 옆으로 넘긴다(규칙 순서를 뒤로) |
| 휴대폰에서 위 막대가 543~603px | 단추가 많음 | 600px 이하: 화면 형식 단추 숨김, 대화 단추는 아이콘만(읽기용 이름 유지), 학교 이름 줄임표 |
| 관리 화면 본문이 넘침 | 본문 격자 열이 가장 넓은 항목에 맞춰짐 | `.content-inner` 열을 `minmax(0, 1fr)`로 |
| 연구소 빠른 추가 | 긴 선택지 글이 상자를 427px로 늘림 | 선택 상자가 폭을 넘지 않게 |
| 학교 관리 '기능별 가격' 줄 | 한 줄 고정 | 휴대폰에서 줄바꿈 |
| 기본판 화면 넓은 표 | 키보드로 스크롤 불가(axe) | 표 상자에 초점·이름 |
