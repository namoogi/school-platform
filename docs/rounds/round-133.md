# 133차: 여러 쪽 템플릿의 하위 메뉴는 별도 쪽으로 (2026-11-28)

> **요약** 템플릿 7종(알림·이야기·입학 모집·프로젝트·사명·국제·유치원)의 하위 메뉴가 같은 쪽 안 구역으로 내려가던 것을, 하위 메뉴마다 따로 쪽을 만들어 그 쪽으로 이동하게 바꿨습니다. 한 쪽 소개형(single)만 구역 차례를 그대로 씁니다.

> **왜** 선생님(2026-11-28): "서브 메뉴별로 다른 페이지가 아니라 한 페이지 안에서 내려가는 구조군. 이상하다. 서브 메뉴는 그냥 서브 메뉴로 이동하도록 하고." 선택: '여러 쪽 템플릿은 모두 별도 쪽으로(추천)'.

```terms
하위 쪽 | 상위 메뉴 아래에 매달린 쪽. 하위 메뉴를 누르면 이 쪽으로 간다 | 학교 소개 > 인사말(/p/about-greeting)
상위 쪽 | 하위 쪽을 묶는 쪽. 맨 앞에 하위 쪽 바로 가기 카드가 있다 | 학교 소개(/p/about)
메뉴 주소 | 구역에 붙이는 영문 이름. 이제 한 쪽 구조에서만 하위 메뉴가 된다 | single의 #contact
```

## 바뀐 것
- `src/lib/site-template-split.ts`의 `splitSubmenuPages`가 템플릿 원본에서 메뉴 주소가 있는 구역마다 하위 쪽(`menu.parent` = 원래 쪽)을 만든다.
  - 하위 쪽 주소는 늘 `상위-메뉴주소`다(예: `about-greeting`). 한 학교가 여러 템플릿을 쓸 때 `history` 같은 메뉴 주소가 다른 묶음의 쪽과 겹치지 않게 한다(Codex 검토). 같은 상위·같은 주소면 같은 자리라서 이미 있는 쪽을 그대로 쓴다.
  - 하위 쪽 제목은 구역 제목이다. 구역 제목은 데이터에 남기고(제목 구조·표 설명), 하위 쪽(상위 메뉴가 있는 쪽)에서만 쪽 제목과 같은 첫 구역 제목을 보이지 않게 감춘다(`SiteRenderer`, 화면 낭독기는 읽음). 신청 칸은 제목을 떼어 기본 제목을 쓴다.
- 상위 쪽에는 메뉴 주소 없는 구역이 남고, 맨 앞에 '하위 쪽 바로 가기' 카드(quicklinks)가 붙는다. 원래부터 하위였던 쪽도 카드에 들어간다(원래 하위 쪽만 있는 프로젝트형 '프로젝트' 쪽도).
- 홈과 이미 하위인 쪽(한 단계만)은 나누지 않고 메뉴 주소만 뗀다.
- 옛 `/p/쪽#구역` 링크는 새 쪽 주소로 바뀐다(이야기형 '학교의 하루' → `/p/community-day`).
- 빈 칸(자료로 채우기 자리)과 예시 사진 자리는 나눈 뒤 위치로 옮긴다. 예시 글은 원본 순서대로 채운 뒤 같은 방식으로 나눈다(`SiteTemplate.source`). 그래서 같은 안내 자리의 예시 값 순서가 바뀌지 않는다.
- 프로젝트형 '이번 학기 프로젝트'는 하위 메뉴가 아니라 '프로젝트' 쪽 본문이라 메뉴 주소를 뗐다.
- 템플릿 판: notice 6, story 7, admissions 6, project 8, mission 6, international 6, kinder 7. single은 4 그대로.

## 이미 템플릿을 쓰는 학교
- 템플릿은 적용할 때만 쪽을 만든다. 이미 만든 학교 쪽은 바뀌지 않는다(구역 하위 메뉴도 그대로 동작한다).
- 같은 템플릿을 다시 적용하면 없는 주소(새 하위 쪽)만 시안으로 더한다. 공개는 사람이 한다.
- 다만 학교에 이미 있는 상위 쪽의 최신 판이나 공개 판이 아직 구역 하위 메뉴(메뉴 주소)를 쓰거나, 그 쪽이 이미 다른 쪽의 하위면 그 아래 새 하위 쪽은 만들지 않는다(공개 뒤 같은 하위 메뉴가 두 번 보이거나 엉뚱한 상위로 올라오지 않게, Codex 검토). 학교가 상위 쪽을 새 구조로 옮긴 뒤 다시 적용하면 만들어진다.
