# 133차: 관제가 세션에 직접 지시하는 길 + '지시 이행 과정도 지시' 원칙 (ADR 0050)

- 날짜: 2026-11-28 · 세션: 관제
- 사용자: "너가 관제인데 왜 하위 세션을 관리를 못하는거지?" / "내 지시가 프로세스 상에서 막힌다면 그건 나의 의지가 아닐 것이고."

> **요약** 관제가 `POST /api/control/direct`로 세션 앞에 지시를 남기면 그 세션이 다음 차례 `/mine`에서 받는다. 세션 메시지가 막힌 세션(신뢰 기기 확인)에도 닿는다. AGENTS.md에 '관제 지시와 그 이행 과정 전체가 사용자의 지시'를 넣었다.

> **왜** 결정 카드 알림을 룽아룬숙사 세션에 보내지 못하자 관제가 선생님께 붙여 넣기를 넘겼다. 막힌 것은 39차 설계(당겨 오기는 사람 글만)였다. 선생님의 뜻이 아니었다.

## 시험
- `tests/control-pull.test.ts`: 관제 지시가 그 세션에만 나온다 → 답하면 빠진다 → 덧붙이면 다시 나온다. 다른 세션 요청에 덧붙이기·빈 본문·세션 없음은 거부한다.

## 남은 일
- 지시와 세션 보고가 같은 순간에 들어오면 글 순서(id)가 커밋 순서와 달라, 지시가 '답함'으로 보일 수 있다(Codex 지적). 39차부터 사람 답에도 같은 문제가 있다. 따로 고친다: `control.post`·`control.direct`·사람 답이 같은 요청 행 잠금을 쓰거나, 지시마다 '받음' 표시를 둔다.
