### 열람·수정 요청 (ADR 0030, 모든 학교 기본 켬)
- 표 구성
  - `record_requests`: 학생·보호자 요청. 종류는 열람 / 수정, 대상과 내용을 적는다.
  - `record_request_events`: 결정 사건. 상태는 접수 → 검토 → 열람 허락 / 수정함 / 거부 / 대상 아님 / 청문 제안 / 끝남.
- 기한: 기본 45일. 학교 성적 정책 판의 `policy.requests.due_days`로 더 짧게 정할 수 있다.
- 결정 규칙
  - 결정은 학교 관리자가 하고, `from_status` 409로 동시 결정을 막는다.
  - 거부·대상 아님은 이유가 필요하다.
  - 수정함은 정정 판(새 마감 판·새 기록) id를 가리켜야 한다.
  - 끝난 요청은 바꾸지 않는다.
  - 거부한 뒤에는 청문 제안·수정·끝냄만 할 수 있다.
- **이의 의견서** `record_annotations`
  - 거부된 수정 요청에 학생·보호자가 한 번 붙이고, 원 기록은 바꾸지 않는다.
  - 이후 발행본(F4)에 함께 실린다(`content.annotations`). 블라인드 발행본에서는 이름 가림이 의견서에도 적용된다.
- 학생·보호자 쪽은 계약 함수로만 들어온다: `app.portal_request`, `app.portal_annotate`, `app.portal_requests_v1`.

### 보존 규칙 · 파기 (ADR 0028, 가림 판)
- `retention_rules`: 판으로 쌓는다(409). 재적이 끝난 뒤 n년, 비우면 영구.
- 파기 미리보기 `app.redaction_preview`
  - 보여 주는 것: 가능 여부와 이유, 가림 대상 건수, 남는 것
  - 파기를 막는 조건: 규칙 없음, 영구, 재적 중, 기간 안, **끝나지 않은 요청이 있음**(34 CFR 99.10)
- 파기 `app.redact_person`
  - 사유가 필요하다. 미리보기 건수가 지금과 다르면 409로 막는다.
  - **파기 사건**(`destruction_events`)을 남긴 뒤, 같은 트랜잭션에서만 가림 값으로 덮는다.
    - 서술 → `[파기됨]`, 증거물 → `[파기됨]`, 출결·평가 메모 → 지움, 학교 정의 기록 자료 → `{}`
    - 요청·의견서 내용 → `[파기됨]`
    - 학년도 기록 판: 서술·증거를 빼고 `redacted` 표시
    - 발행본: 서술 칸을 가리고 `redacted` 표시
  - 남는 것: 이름, 학적, 수업 마감 판의 학점·최종 성적, 학년도 기록의 과목·출결 수치.
- 가드(`private.guard_columns`)
  - 파기 사건과 **같은 트랜잭션**의 가림만 허락한다. id·school_id·person_id는 그대로여야 한다.
  - 다른 트랜잭션에서 사건 id를 흉내 내면 거부하고, 삭제는 여전히 막는다.
