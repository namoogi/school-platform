# 138차 — 새 구조 템플릿 4종 (바로가기 포털·한 쪽 유치원·한 쪽 후원·배움 안내)

- 날짜: 2026-11-28
- 요청: 사용자(2026-11-28) — "템플릿을 다양한 구조를 반영하는 형태로 카테고리를 나누고… 템플릿 수를 늘이더라도 추가 작업을 하자." 선택: '틀 먼저 + 새 구조 4~6종'(136차가 틀, 이번이 새 구조)
- 관련: ADR 0052(세 축·메뉴 구조), 135차(하위 메뉴 = 별도 쪽), 136차(옆 메뉴·따라오는 차례), `docs/research/site-structures-2026-11.md`

> **요약** 136차의 세 축(메뉴 구조·첫 화면·내용)에서 비어 있던 조합을 채우는 템플릿 4종을 더해 12종이 되었습니다. 고르기 화면에서 '한 쪽'을 누르면 3종, '바로가기 타일'을 누르면 포털형이 나옵니다.

## 1. 더한 템플릿

| 키 | 이름 | 디자인 | 메뉴 구조 | 첫 화면 | 내용 | 비어 있던 자리 |
| --- | --- | --- | --- | --- | --- | --- |
| `portal` | 바로가기 포털형 | 맑은 하늘 | 옆 메뉴 | 바로가기 타일 | 알림 | '타일' 첫 화면이 하나도 없었음 |
| `kinder-one` | 유치원 한 쪽형 | 놀이터 | 한 쪽 | 큰 사진 | 유치원·작은 학교 | 한 쪽 구조가 '작은 모임'(single) 하나뿐 |
| `mission-one` | 후원 한 쪽형 | 등불 | 한 쪽 | 큰 사진 | 사명·작은 학교 | 후원 단체의 '한 쪽 이야기' 랜딩 |
| `guide` | 배움 안내형 | 아이보리 편집 | 옆 메뉴 | 잡지형 | 이야기·프로젝트 | 옆 메뉴가 '알림'에만 있었음 |

- 포털형 타일은 아홉 개다. 큰 첫 타일(2×2) + 작은 타일 여덟 = 넓은 화면 4칸×3줄, 휴대폰 2칸×6줄을 빈칸 없이 채운다.
- 한 쪽 템플릿은 쪽을 나누지 않는다(`nav === 'onepage'`이면 하위 쪽 나누기를 건너뜀, 종전 `ONE_PAGE` 목록 대신).
- 예시 내용은 모두 가상 학교(푸른들초·꽃잎마을 어린이집·빛나무 배움터·너른숲 중고)다. 메일은 `example.org`, 전화는 0, 사진은 기존 예시 사진을 다시 쓴다(새 그림 생성 없음).
- 자료로 추천(SIGNALS): 포털형은 '바로가기·자주 찾는', 배움 안내형은 '교육과정·커리큘럼'. 한 쪽 2종은 낱말 없이(같은 내용의 기존 템플릿보다 앞서지 않게) 고르기 화면 거르기로 찾는다.

## 2. 바꾼 규칙

- 시험 '템플릿 디자인이 서로 다르다' → '디자인 + 메뉴 구조 + 첫 화면 조합이 서로 다르다'. 같은 디자인을 다른 구조로 다시 쓰는 것이 이번 차시의 목적이라서다(새벽빛·학사 기본은 여전히 템플릿에 쓰지 않음).
- 옆 메뉴 제목(`.site-localnav-title`)에 항목과 같은 안쪽 여백을 주었다. 상위 쪽이 지금 쪽일 때 배경 끝에 글자가 붙어 보였다.

## 3. 확인

- 단위 시험(`npm run test:unit`), DB 시험(`npm test`), 브라우저 흐름(`npm run test:e2e`, 템플릿 카드 12개·썸네일 12개).
- 썸네일 4장: `npm run templates:thumbs -- portal kinder-one mission-one guide`.
- 확인하지 못한 것: 운영 학교에 새 템플릿을 실제로 적용한 결과(운영 자료는 건드리지 않음).
