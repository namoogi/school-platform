# 123차: Radix Themes 도입 + 양식 배치 규약 (ADR 0045)

- 날짜: 2026-11-28 · 세션: 관제
- 사용자: "스타일이 정돈되어 있지 않군. … input box와 버튼 등을 어떻게 배치할지 스타일 시트 가이드를 만들어서 … 실제 들어갈 자료와 리스트의 길이 등을 고려하여 그에 맞게 설계하고 배치되도록 하자. 또는 … git에 올려진 도구들이 있다면 가져와서 적용하도록." → 선택: 외부 UI 라이브러리 → 토큰 충돌을 알린 뒤 'Radix Themes 그대로 도입'

> **요약** Radix Themes(MIT)를 들였다. 입력 칸 너비가 들어갈 내용 길이에 맞게 정해지고(날짜 좁게, 이유는 줄 전체), 단추는 마지막 칸 옆 바닥선에 붙는다. 공통 양식 부품 하나를 바꿨으므로 46곳이 한 번에 새 규칙을 따른다.

> **왜** 공통 양식 부품에 배치 규칙이 없어 화면마다 칸 너비·단추 위치가 제각각이었다(선생님 화면 캡처: 날짜가 넓게, 단추가 따로, 기록 줄 옆에 양식이 끼임).

```terms
용어 | 쉬운 설명 | 예시
Radix Themes | 입력 칸·단추 같은 화면 부품을 미리 다듬어 둔 공개 모음(MIT) | 날짜 칸, '학적 등록' 단추
칸 너비 = 내용 길이 | 들어갈 글자 수만큼만 칸을 그린다 | 날짜 11rem, 학년 7rem, 이유 줄 전체
토큰 | 색·간격처럼 화면 전체가 같이 쓰는 이름 붙인 값 | --ds-space-4 = 16px
```

## 한 일
- `@radix-ui/themes@3.3.0`(정확한 판), `layout.tsx`에서 CSS를 싣고, `Shell.tsx`를 `<Theme>`로 감쌌다(명암·형식 따라감).
- 이름 충돌 11개를 정리했다: `--space-*`·`--shadow-1~3`·`--radius-full` → `--ds-*`. Radix 색·서체·높이를 우리 토큰으로 다시 정의했다(`.app`).
- `ActionForm`: Radix `TextField`·`TextArea`·`Button`으로 바꾸고, 칸 너비 규칙 `fieldSize`, 한 줄·위아래 배치(`form-grid`)를 넣었다.
- 사람·학적 화면: 구획(`detail-section`)·기록 목록(`record-list`)·검색 줄(`search-row`)
- 규약 문서 `DESIGN-SYSTEM.md` '양식 배치', ADR 0045, 대기열에 나머지 화면 옮기기 안내

## 시험
- `tests/form-layout.test.ts` 3개(`test:unit`)
- 사람·학적 캡처(학사형 밝게·분석형 다크), e2e 전체(양식 46곳)

## 확인하지 못한 것
- 나머지 화면의 직접 늘어놓은 입력(`<input>` 묶음)은 대기열로 옮긴다.
- 선택 칸은 브라우저 기본 모양이다(Radix Select는 키보드·시험 동작이 달라 보류).
