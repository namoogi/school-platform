# 14차 결과: 학교별 자료 → 근거 질문 → 확정 규칙 → 발행본 보존

## 바뀐 기준과 이유

| 13차까지 (시안) | 14차 (앱) |
| --- | --- |
| 브라우저 저장, 버튼 동작은 UX 설명용 | Postgres에 저장. 로그인·권한·저장·발행을 실제로 구현 |
| 학교 선택을 화면에서 전환 | 학교별 관리자 계정. 소속 학교만 열람·수정 (RLS) |

## 구현 범위

1. **로그인과 학교 분리**: `private.app_users` + 서명 세션 쿠키. 모든 요청은 `authenticated` 역할과 사용자 클레임을 설정한 트랜잭션에서 실행되고, 표마다 RLS가 `school_id` 소속을 검증합니다. 표 사이의 참조는 `(id, school_id)` 복합 외래키로 묶어 다른 학교 기록을 가리킬 수 없습니다.
2. **자료 누적 등록**: 파일을 여러 개 끌어 놓거나 선택해 언제든 추가할 수 있습니다. 시트 주소는 + 버튼으로 여러 개 등록합니다. 상태는 세 가지로 구분합니다: `내용을 읽음`(CSV·TSV·TXT), `주소만 등록 · 내용 미열람`(시트 권한 미연결), `파일 보관 · 판독기 미연결`(PDF·XLSX·DOCX). 목록에서 빼도 원문은 남습니다.
3. **근거와 질문**: 규칙 기반 분석기(`rule-based/period-structure@1`, AI 미연결 표시)가 학기·평가 기간 관계를 추정하고, 어느 파일 몇 행에서 읽었는지 보여 줍니다. 관리자는 그대로 확인하거나, 이름·소속을 고치고 근거 메모(필수)를 남겨 확정합니다. 같은 자료로 다시 분석하면 질문을 새로 만들지 않습니다. 새 자료가 확정 규칙과 다르거나 서로 충돌하면 규칙은 그대로 두고 새 질문을 엽니다.
4. **발행과 보존**: 확정 규칙과 현재 양식으로 문서 한 장을 발행합니다. 발행본은 학교명, 규칙 값·판, 양식 문구·판, 근거 자료 해시를 스냅샷으로 담고, 화면은 스냅샷만 읽어 그립니다. 수정본은 앞선 발행본과 연결되고(갈래 금지), 발행본마다 해시로 무결성을 표시합니다.

## 구현하지 못한 부분과 사유

- **Vercel·Supabase 연결**: 이 프로젝트 전용 자격 증명이 세션에 없어 로컬에서만 검증했습니다. 필요한 설정과 미검증 항목은 [SETUP-CLOUD.md](../SETUP-CLOUD.md).
- **Google Sheets 내용 읽기**: 시트 권한 연결이 없어 주소 등록 상태까지만 구현했습니다.
- **PDF·XLSX·DOCX 판독, AI 분석**: 판독기·AI 연결이 없어 파일 보관과 규칙 기반 분석으로 첫 흐름을 완성했습니다. 분석기 이름이 질문에 저장되므로 나중에 다른 분석기를 붙여도 출처를 구분할 수 있습니다.
- **인증 방식**: Supabase Auth 대신 자체 최소 인증을 썼습니다. 로컬 테스트를 Docker 없이 실행하기 위해서입니다. RLS는 Supabase와 같은 `request.jwt.claims`의 `sub`를 읽으므로 Supabase Auth로 옮겨도 정책은 그대로 쓸 수 있습니다. 로그인 시도 횟수 제한, 비밀번호 변경, 초대는 아직 없습니다.
- **서체 설정 저장(13차 서체 스튜디오)**: 이번 범위 밖입니다. 13차 웹폰트 자산만 가져와 화면과 문서에 적용했습니다.
