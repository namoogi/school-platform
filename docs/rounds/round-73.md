# 73차: 학사 화면 3 — 성적(/grades)

- 날짜: 2026-11-26 · 세션: 관제
- 사용자 지시: 71차와 같음("추가로 해야 할 작업들은 하도록 하자", 구독 토큰 안에서).
- 판단: F2(57차) 평가·마감 DB 명령 함수에 화면·API를 붙인다. 새 표·새 권한 경로는 없다. 결과·서술은 사건으로 추가만, 마감 판은 DB가 계산해 얼린다(ADR 0004·0025).

## 한 일
- **화면** `/grades?o=<개설>` 성적(레일 '성적', 수업 상세의 '성적 입력·마감'에서 들어감)
  - 평가 항목: 목록(코드·종류·가중·만점), 추가(과목 총괄 축), 보관(마감 전, 확인 창)
  - 점수 입력 표(`ResultGrid`): 학생 × 평가 항목. 바뀐 칸만 모아 한 번에 저장(한 트랜잭션, 각 칸이 새 결과 사건). 마감한 수업은 정정 사유 칸이 나오고 DB가 '학교 관리자 + 사유'만 받는다.
  - 과목 서술(세부능력·특기사항): 학생마다 글 칸, 저장할 때마다 새 사건(최신 것이 보임)
  - 수업 마감: 척도 고르기 → 마감 판(원점수·최종·등급·이수·취득 학점·통계 모집단 n·평균·표준편차). 이미 마감했으면 '정정 마감(새 판)'에 사유 필수, 이전 판은 남음. 요청 키로 두 번 눌러도 한 판.
  - 담당이 아닌 교사에게는 입력 칸을 보이지 않는다(DB도 거부).
  - 관리자: 척도(미리 만든 한국 성취평가제·미국 글자·P/F 넣기, 띠 보기), 성적 정책 새 판(원점수·최종 자릿수, 표준편차 종류, 근거 필수). 화면에 없는 정책 칸(GPA·석차·서술 한도)은 이전 판 값을 잇는다.
- **API** `POST /api/grades` (scale-preset·policy·assessment·archive-assessment·results·narrative·close)
- **읽기** `src/lib/gradebook.ts`: `listScales`·`latestPolicy`·`assessmentsOf`·`narrativesOf`·`offeringContext`(입력 권한 `can_grade` 포함)
- `ActionForm`에 `keep`(저장 뒤에도 쓴 글 유지)을 더했다.
