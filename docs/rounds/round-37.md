# 37차: 관리 화면 입력 정리 — 파일 첨부는 끌어 놓기, 입력 칸은 최신 모양

## 지시
- 사용자(2026-11-23, 관제 세션 경유): "전체든 학교별 관리 페이지든 파일 첨부나 이런 것들은 드래그 앤 드랍 방식으로 하고 input box도 최신화된 스타일로 넣자. 스타일이 적용되지 않은 기본 형태들이 많이 보인다."
- 대상: 전체 관리(`/admin/**`), 학교 관리(`(app)/**`). 공개 홈페이지(`/s/**`)·시안(`/preview/*`)은 대상이 아니다.

## 바꾸기 전 점검 (로컬, 합성 자료)
관리 화면 11곳을 1440·390 폭, 분석형 다크·화이트, 학사형으로 찍고 화면 속 입력을 자동으로 훑었다.
- 브라우저 기본 파일 선택("Choose File") 3곳: 홈페이지 묶음 zip, 동화 표지·쪽 그림. 그 밖에 화면 편집 사진함(35차)도 같았다.
- 기본 체크박스 21개, 기본 select 화살표 17개, number 11·date 1·search 1(브라우저 스피너·달력·지우기 단추 그대로).
- 전체 관리 가격 칸은 화면별 규칙(140px)이 전역 입력 규칙의 특이성에 져서 칸·이름·저장 단추가 세로로 쌓였다.

## 남은 것 (→ 아래 '37차 후속'에서 처리)

- 표 안 작은 select(28px)는 터치 기기에서도 28px — 표 밀도와 함께 다시 본다.

- 실제 터치 기기·화면낭독기 청취는 하지 못했다.

## 37차 후속 (2026-11-27, 사용자: "남은 것들도 이어서 진행해줘")
main(110차)에서 관리 화면 27곳(전체 관리 9 · 학교 18)을 다시 훑었다(1440·390, 손가락 기기 흉내 iPhone 13).
- **390px 가로 넘침**: 0곳 — 그 사이 해결돼 있었다. PLATFORM-PATTERNS 4절을 '해결 확인'으로.
- **새로 생긴 날 파일 입력 1곳**: 홈페이지 템플릿 '학교 자료로 채우기'(66차) → `FileDrop`(PDF·DOCX·TXT·MD, 5개·8MB, 서버 한도와 같음). 끌어 놓으면 바로 읽고, '자료 읽기' 단추는 다시 읽기로 남겼다.
- **손가락 기기에서 34px**: 분석형(전체 관리)의 `--control-h: 34px`가 37차의 `pointer: coarse` 44px 규칙보다 특이성이 높아 이겼다 → 특이성을 올려 화면 형식·밀도와 관계없이 44px. 표 행 동작 select(28px)도 44px, 라벨 없이 놓인 체크(연구실 카드 등)는 24px, 스위치는 46×28.
- **필수 표시**: 날 `<label>`에 `required`만 있어 화면에 `*`가 없던 11칸을 `Field`로(홈페이지 주소·새 항목 제목·주소, 배치 이유·옮긴 주소, 언어 코드·이름·JSON, 내 기록 요청·진술, 학년 체계·바꾼 이유, 가족 계정 사람·메일, 연구실 지시). `Field`는 라벨이 입력을 감싸게 바꿔 기존 `label:has-text(..) input` 선택자와도 맞는다. 로그인 칸은 그대로(두 칸 모두 필수인 관례 화면).
- 남은 것: 실제 터치 기기·화면낭독기 청취(장비 필요).
