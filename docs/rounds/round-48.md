# 48차: 공개 화면에서 바로 편집 — 교직원 로그인 → 그 쪽 화면 편집 (ADR 0011 1단계 남은 일)

- 날짜: 2026-11-24 · 세션: 관제
- 사용자 지시: "관리자가 화면에서 직접 수정하는 기능이 이전되지 않은 것 같은데 그 부분을 체크해 줘."

## 점검 결과
- 화면 편집(35차, `/site/edit/<id>`)은 있었지만 **들어가는 길이 홈페이지 관리 안에만** 있었다.
- 공개 화면의 '교직원 로그인'은 로그인 뒤 학사 첫 화면으로 갔고(보던 쪽으로 돌아오지 않음), 학교 주소(rungarunsuksa.vercel.app)에서는 플랫폼 로그인으로 넘어가 버렸다.
- 옛 사이트: "로그인하면 글·사진 수정, 공지 추가, 개선 요청판을 이 페이지에서" — 이 흐름이 끊겨 있었다.

## 한 일
- 공개 화면 바닥의 **'교직원 로그인' = 이 화면 편집**: 보고 있는 쪽(첫 화면·쪽·소식·동화)을 알려 주는 링크(`staffEditHref`).
- `/site/open?slug&kind&key&back`: 로그인 확인 → 그 학교 관리자인지 확인(전체 관리자는 입장 기록) → 작업 학교를 그 학교로 → **그 쪽의 화면 편집**으로. 목록 화면이면 홈페이지 관리로.
- 로그인 화면·비밀번호 로그인·Google 로그인 모두 `next`로 돌아온다(이 사이트 안 경로만, `safeNext`). Google은 돌아올 곳을 탭 안(sessionStorage)에만 잠깐 둔다.
- 편집 화면에 **'공개 화면으로'**(`back`, 공개 경로나 등록된 학교 주소만 — `safeBack`).
- 학교 주소에서는 로그인·편집을 플랫폼 주소에서 하고 학교 주소로 돌아온다(로그인 쿠키는 주소마다 따로).

## 시험
- `tests/staff-edit.test.ts`(돌아갈 곳 검사·링크), 전체 `npm test` 36파일 275개.
- E2E 48차 단계: 공개 쪽 → 교직원 로그인 → 로그인 → 그 쪽 화면 편집 → 공개 화면으로, 이미 로그인했으면 바로 편집, **다른 학교 관리자는 들어가지 못함**. 33/33(접근성 axe 포함 — 숨은 쪽 바닥 링크 대비·밑줄 맞춤).

## 아직 (옛 사이트와 비교)
- 공개 화면 위에 바로 뜨는 관리 막대(로그인한 채로 공개 화면을 볼 때) — 지금은 바닥 링크로 들어간다.
- 화면 편집 안에서 '공지(소식) 추가'·대화창(개선 요청) 바로가기, 가이드 창 끌기·위치 기억, 홈 머리·바닥 정보 화면 편집.
