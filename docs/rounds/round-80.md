# 80차: RLS 문 — 정책 없는 표가 생기면 운영 배포가 서지 않게

- 날짜: 2026-11-26 · 세션: 관제
- 계기: 드리미포털 교류 확인(2026-11-26).
  - 공유 DB의 위험은 두 번째 담(RLS)이 없을 때 생긴다.
  - 규칙은 글로 두면 지켜지지 않는다. 그러니 정책 없는 표가 생기면 배포를 세우는 문을 처음부터 두라.
  - 학교별 커스텀 백엔드 검토 문서는 `docs/research/backend-tenancy-2026-11.md`(8절)다.
- 사용자 지시와의 관계: 백엔드 구조 검토의 일부다. 추천안(계층형)이 공용 핵심을 지키는 전제가 '모든 표 RLS'이기 때문이다.

## 한 일
- `tests/rls-gate.test.ts` — 아래가 하나라도 깨지면 CI가 실패한다. 운영 배포는 main CI가 통과해야만 서므로(79차), 이 시험이 배포를 세운다.
  1. public·agent·control·app 스키마에 RLS가 꺼진 표가 없다.
  2. `school_id`가 있는 표는 모두 정책이 있다. 사람 역할에 그냥 `true`로 열린 정책은 없다. 예외는 내부 역할과 공개 기능 목록 하나뿐이다.
  3. `school_id`가 없는 public 표는 목록에 있는 관제·플랫폼 표 6개뿐이다. 이유를 적어 두었고, 새로 더하면 검토 대상이 된다.
  4. private·_migrations 스키마에는 사람·에이전트 역할 권한이 없다.
