# 25차: 학사 업무형 기본 틀 + 3단 작업함 적용

## 목적 (사용자 결정)
"디자인은 학사 업무형을 기본으로, 세부 분리가 필요하면 3단 등의 작업함 형식"으로 정한다. 결정 기록은 [ADR 0006](../decisions/0006-design-direction-campus.md).

## 한 일
- **앱 셸**
  - 왼쪽 아이콘 레일(88px): 홈·자료·확인·문서·설정 / 전체 관리의 학교·연동·연구소·디자인. 확인 대기 건수를 배지로 보인다.
  - 상단 막대(64px): 학교 전환 · 확인 대기 알림 · 계정.
  - 레일 이름은 짧게 쓰고, 화면 이름은 `title`과 접근 가능한 이름으로 함께 제공한다. 보이는 글자가 이름에 들어가도록 맞췄다.
- **토큰:** 따뜻한 회색 + 청록, 본문 16px, 행 48px, 반경 6/8/12. 의미 토큰 구조는 그대로이고 원시 값만 바꿨기 때문에 기존 화면 전체에 적용된다.
- **홈** `/home` (`/`는 홈으로 보낸다)
  - 업무 카드: 자료 첨부 · 관리자 확인 · 학사 문서실 · 학교 설정. 카드마다 상태 배지, 실제 숫자, 바로가기가 있다.
  - 오른쪽 열: 할 일(지금 · 다음 · 끝낸 일)과 최근 기록(자료 · 규칙 · 발행 시간순).
  - 모든 값은 이 학교의 실제 기록(RLS 범위)에서 계산한다.
- **관리자 확인 = 3단 작업함**
  - 함: 확인 대기 · 답변함 · 새 자료로 대체됨 · 확정한 판.
  - 목록 → 상세 구조이고, 선택 상태는 주소(`?box=&id=`)에 담긴다. J/K로 이동한다.
  - 확인 대기 상세에서는 '지금 확정된 규칙'과 질문을 나란히 놓는다. 상세 칸이 좁으면(컨테이너 960px 미만) 위아래로 쌓는다.
  - 답변한 질문에서 그 답으로 만든 판으로, 판에서 그 판을 만든 질문으로 서로 이동할 수 있다.
- **조회 추가:** `listQuestions`는 이 학교의 확인 질문 전체를 돌려준다. school_id로 거르고 RLS를 적용한다.

## 확인하지 못한 것
- 좁은 화면(≤768px)에서는 레일이 가로 띠로 바뀌는 CSS만 넣었고, 화면으로 확인하지는 않았다.
- 화면 판독기(스크린 리더) 실사용과 axe 자동 점검은 하지 않았다(대기열의 기존 과제).
- 자료 첨부 · 문서실 · 설정은 새 토큰과 셸만 적용됐다. 화면 배치는 18차 그대로이다. 표가 많은 화면은 ADR 0006의 '다시 볼 조건'에 따라 데이터 그리드형을 검토한다.
