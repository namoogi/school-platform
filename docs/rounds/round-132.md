# 132차: 템플릿 척도에도 바닥 띠 필수 (2026-11-28)

> **요약** 학사 템플릿으로 척도를 만들 때도 0점까지 덮는 '바닥 띠'가 있어야 저장됩니다. 화면 길(131차)과 템플릿 길, 관제가 템플릿 판을 낼 때의 DB 검사가 같은 규칙을 씁니다.

> **왜** 바닥 띠가 없으면 그 아래 점수는 `app.band_for`가 등급을 못 찾고(null), `app.close_offering`이 등급 없이 '이수(학점 인정)'로 마감 판을 굳힙니다. 마감 판은 고칠 수 없어 정정 판을 새로 내야 합니다. 131차(PR #228)는 화면·API 길만 막았고 템플릿 길이 남아 있었습니다.

```terms
용어 | 쉬운 설명 | 예시
바닥 띠 | 하한이 0 이하인 가장 낮은 등급 구간. 모든 점수가 어느 등급엔가 들어가게 함 | A≥90 … E≥40 아래의 I≥0(미이수)
템플릿 판 | 관제가 내는 학사 기본 설정 묶음(학교급·학기·척도). 학교가 고르면 사본이 생김 | '국제학교' 1판의 IB 1–7 척도
```

## 바꾼 것
- 새 마이그레이션 `20261128001900_academic_template_band_floor.sql`: `private.academic_template_ok`에 "직접 정한 척도(프리셋이 아닌 것)는 숫자 하한이 0 이하인 띠가 있어야 한다"를 더함. 함수만 바꾸면 CHECK 제약이 기존 행을 다시 보지 않으므로 제약을 다시 걸어 모든 판을 다시 검사한다.
- `applyTemplate`의 직접 정한 척도 저장이 `saveScale(..., { floor: true })`. DB 검사 이전에 들어간 판이 있어도 학교 사본에 바닥 없는 척도가 생기지 않는다.
- 규칙은 `checkBands({ floor: true })`와 같다: 하한이 모두 비어 있어도(`min: null`만) 거부한다.

## 운영 확인 (적용 전)
- 관제 점검 경로로 운영 `/academics/templates`를 열어 확인: 템플릿 5종 모두 1판(시드 그대로). 직접 정한 척도는 `international`의 `ib_1_7` 하나이고 `1`(min 0) 바닥 띠가 있다. 나머지는 프리셋(모두 min 0 띠 있음). → 기존 판은 새 규칙을 지나므로 새 판을 낼 필요가 없었다.
- 한계: 화면은 키마다 최신 판만 보여 준다. 최신이 모두 1판이므로 옛 판은 없다고 판단했다. 만약 어긋난 판이 있으면 마이그레이션의 제약 재설정이 멈추고 배포가 서지 않는다(조용히 통과하지 않음).
