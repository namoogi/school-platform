# 93차: 언어는 데이터로 — 언어 목록·번역 사전·전환 단추 (ADR 0037) + 메뉴 이름 풍선 정리

- 날짜: 2026-11-27 · 세션: 관제
- 사용자
  - "모든 기능들은 영/한 공통으로 언어전환이 가능하도록 제작하자."
  - "언어를 추가할 때마다 코드와 구조를 바꾸지 말고, 그냥 언어를 추가하면 바로 해당 언어로 작업이 가능하도록 하자."
  - "영어로 전환하는 작업은 미리 진행해 두도록 하고"
  - "왼쪽의 표는 마우스를 가져가면 어떤 항목인지 글자가 뜨면 좋을 것 같다."

> **요약** 언어 목록과 번역 사전을 DB에 두었다. 관리 화면에서 언어 한 줄을 더하면 코드를 바꾸지 않고 바로 그 언어로 쓴다. 셸·메뉴·로그인·화면 설정·언어 관리 화면은 이미 영어로 옮겼고, 나머지 화면은 전담 세션이 화면 묶음별로 옮긴다.

> **왜** 영어권 학교와 외국인 교사도 같은 시스템을 쓰게 하려면 언어가 코드에 고정되면 안 된다. 그리고 앞으로 늘어날 화면이 다시 한국어로 박히지 않도록 CI가 막는다.

```terms
용어 | 쉬운 설명 | 예시
번역 사전 | 화면 문구 이름표마다 언어별 글자를 적은 표 | login.submit → "로그인" / "Sign in"
대체 언어 | 그 언어 번역이 없을 때 대신 보여 줄 언어 | 베트남어 번역이 없으면 영어로
기본 묶음 | 배포 때 사전의 빈 칸만 채우는 번역 파일 | i18n/en.json
하드코딩 | 문구를 화면 코드 안에 직접 적어 둔 것 | 단추 코드에 "저장"이 그대로
```

## 한 일
- 마이그레이션 `20261128000500_languages.sql`
  - `languages`: 코드 · 그 언어로 쓴 이름 · 글 방향 · 대체 언어 · 사용 여부. ko·en·th를 넣었다.
  - `ui_messages`: 언어 × 이름표 → 글자.
  - 둘 다 누구나 읽는다(로그인 화면 포함). 쓰기는 전체 관리자의 명령 함수 `app.save_language` · `app.save_ui_messages`만 한다.
  - `user_preferences.ui_lang`
- `src/lib/i18n/`
  - `catalog.ts`: 이름표 + 한국어 기준 문구(121개)
  - `format.ts`: `{이름}` · 복수형(`Intl.PluralRules`) · 대체 순서 · 브라우저 언어 고르기
  - `server.ts`: 언어 고르기(사용자 → 쿠키 → 브라우저 → 한국어), 사전 읽기(30초 기억, 프로세스 전역)
- `I18nProvider`(브라우저 `useI18n`), `LanguageSwitcher`(위 막대·로그인 화면), `/api/preferences/lang`
- 화면 옮김
  - 앱 셸(건너뛰기·배너·알림·로그아웃), 메뉴(학교·전체 관리), 학교 전환, 화면 형식·명암, 로그인, Google 단추, 역할 이름
  - `.app`에 `lang`·`dir`을 단다.
- 전체 관리 → **언어·번역**(`/admin/languages`)
  - 언어 목록과 번역 비율
  - 언어 더하기·고치기
  - 번역 JSON 내보내기·넣기(덮어쓰기 선택)
- 기본 묶음 `i18n/en.json`(121개)과 `scripts/i18n-packs.mjs`: 시드·배포 때 빈 칸만 채운다.
- `npm run lint:i18n`(CI): 화면 파일(TSX)의 한글 줄 수가 기준선보다 늘면 실패한다. 지금 기준선은 1,508줄(파일 75개).
- 메뉴 이름 풍선(#144로 먼저 병합)
  - 브라우저 기본 풍선 겹침을 없앴다.
  - 마지막 입력이 마우스면 가리킨 항목, 키보드면 초점 항목의 풍선만 보인다.
- AGENTS.md: '화면은 여러 언어로' 규칙. 시험 목록: RLS 문·열람 계정 전수 점검에 두 표를 이유와 함께 넣었다.
