# 16차 결과: 전체 관리자 · 학교 라이선스 · Google 로그인

기준: 사용자 결정(2026-11-22). 학교 단위로 생성하고, 학교 관리자가 좌석 수와 사용할 기능을 등록하면 그에 맞춰 과금한다. 전체 관리자는 모든 학교에 접근한다. Google 로그인과 다른 계정 로그인을 지원한다.

## 구현

| 영역 | 내용 |
| --- | --- |
| 역할 | 전체 관리자 · 학교 관리자 · 교사. 교사는 자료 등록·열람만, 규칙 확정·발행·양식·설정은 학교 관리자 (RLS로 강제) |
| 전체 관리자 | `PLATFORM_ADMIN_EMAILS` 환경 변수로 지정(저장소에 이메일을 두지 않음). `app.is_member` 가 모든 학교를 허용. 학교에 들어가면 `access_log` 에 남고 그 학교 관리자가 볼 수 있음 |
| 라이선스 | 학교별 버전 기록(좌석, 기능, 월 예상액, 계산에 쓴 가격). 필수 기능(제도 분석)은 항상 포함, 준비 중 기능은 선택 불가, 사용 중 좌석보다 줄일 수 없음 |
| 좌석·초대 | 좌석 = 구성원 + 대기 중 초대. 좌석 안에서만 초대. 초대받은 이메일로 첫 로그인하면 구성원이 됨. 마지막 학교 관리자는 뺄 수 없음 |
| 기능 켜기·끄기 | 메뉴와 API가 라이선스 기능을 따름. 꺼진 기능은 안내 화면 |
| 과금 | 전체 관리자가 기능별 좌석 단가를 정함. 월별 **청구 예정액 확정 기록**(수정 불가)까지. 실제 결제 연동은 결제 대행사 결정 후 |
| 전체 관리 화면 | 학교 현황(좌석·기능·예정액·자료·문서·대기 질문), 학교 만들기(시범 상태·라이선스·양식·첫 관리자 초대), 상태 변경(시범·운영·이용 중지), 가격, 청구, 운영 기록 |
| Google 로그인 | Supabase Auth로 Google 인증 → 서버가 Supabase에 토큰을 확인 → 초대된 이메일 또는 전체 관리자만 연결. 같은 이메일이라도 다른 외부 계정이면 거부. 비밀 키를 쓰지 않음 |

다른 계정(Microsoft, Apple, 카카오 등)은 Supabase에서 공급자를 켜면 같은 흐름으로 동작하도록 만들었다(로그인 버튼 추가 필요). 연결 시점에 Supabase 지원 목록 확인 필요.

## 검증

- `npm test` 53개 통과 (16차 18개 추가): 라이선스 판·가격 보존, 좌석 초과·축소 거부, 다른 학교 라이선스·구성원 차단(양방향), 학교 관리자의 전체 관리 기능 차단, Google 로그인(미초대·미인증·토큰 오류·계정 가로채기 거부, 초대 수락, 전체 관리자), 교사 권한, 마지막 관리자 보호, 전체 관리자 입장 기록, 학교 생성, 청구 기록 불변, 이용 중지
- `npm run test:e2e` 13단계 통과: 학교 설정(좌석·초대·좌석 초과 안내), 전체 관리 화면·학교 입장·입장 기록, 학교 관리자의 전체 관리 화면 접근 404

## 미구현·미검증

- 실제 Google 로그인은 Supabase·Google 설정이 끝난 뒤 배포 주소에서 확인해야 한다(이 세션은 Google·Supabase에 접속할 수 없음).
- 실제 결제, 청구서 발송, 세금계산서.
- 초대 메일 발송(지금은 관리자가 직접 알림). 로그인 시도 제한은 Supabase Auth가 담당.
