# 91차: 공용 DB 기본 + 설정값 맞춤 + 언제든 이전 (ADR 0035)

- 날짜: 2026-11-27 · 세션: 관제
- 사용자
  - "대안학교는 각 학교별로 교육과정이 조금씩 다 다르고 성적을 산출하는 방식도 다 다르다. … 공용으로 하되 AI로 개별 수정이 되도록 지원은 되지 않을까?"
  - "기본정보는 최대한 확장형태로 … 공용 DB를 쓰다가 전용이나 독립으로 이전할 수도 있겠지? 그렇게 한다면 미리 설계를 해 놓아서 DB 이전이 쉽게 이루어지도록 하고."

> **요약** 공용 DB를 기본으로 둔다. 학교 맞춤은 학교 사본·규칙 판·정의·계산식 같은 설정값으로 한다. 학교는 언제든 전용·독립 DB로 옮길 수 있게, 꺼내기·넣기·확인 도구를 두고 CI에서 매번 연습 이전을 돌린다.

> **왜** 대안학교는 교육과정과 성적 산출이 학교마다 다르다. 그런데 여러 학교가 한 DB에서 각자 표·코드를 만들면, 한 학교의 실수가 모든 학교로 번진다. 설정값으로 맞추면 번지지 않는다. 그리고 옮길 수 있다는 것을 시험으로 계속 지키면, 큰 학교나 특수한 요구가 생겼을 때 그 학교만 옮기면 된다.

```terms
용어 | 쉬운 설명 | 예시
설정값 맞춤 | 표·코드를 새로 만들지 않고 규칙·정의 값을 바꿔 학교에 맞추는 것 | 이수 기준 "역량 5/6 도달"을 규칙으로 적기
연습 이전 | 시험 DB에서 매번 학교를 옮겨 보는 것 | 소방 대피 훈련
UUID | 어디로 옮겨도 겹치지 않는 긴 번호 | 전국 단위 학생 고유 번호
복합 외래키 | "같은 학교의 그 행"만 가리키게 묶는 연결 | 같은 반 학생끼리만 짝 짓기
```

## 한 일
- ADR 0035(채택): 공용 기본, 학교 맞춤은 설정값(다음 차시에 계산식 판), 이전 가능성. 포털식 '공용 DB 안 학교별 표·코드'는 기각했다.
- `scripts/school-move.mjs`
  - `export`: 학교 한 곳의 모든 학교 표 행 + 관련 계정·기본판. 연구소 연결은 끊는다.
  - `import`: 같은 마이그레이션 판인지 확인하고, 이미 있는 학교는 거부한다. 트리거를 끄고 넣은 뒤 고아 연결이 있으면 되돌린다. 순번 칸 다음 값도 맞춘다.
  - `verify`: 표마다 행 수·md5 지문을 비교한다.
- `tests/school-move.test.ts` (CI)
  - 예시학교 A에 사람·학년도·학기·과목·개설·마감 판을 합성으로 채운 뒤 빈 DB로 옮긴다. 확인하는 것:
    - 92개 학교 표 지문 동일
    - 고아 연결 0
    - B학교 행 0
    - 옮긴 DB에서 RLS로 A 관리자 읽기 가능
    - 마감 판 수정 거부
    - 같은 학교 두 번 넣기 거부
  - 구조 문: 새 학교 표의 UUID 번호와 학교 표끼리 연결의 `school_id` 묶음을 본다. 지금 예외(순번 번호 9개, 학교 칸 없는 연결 10개)는 이유와 함께 목록에 둔다.
  - 일부러 깨 보기: 순번 번호에 학교 칸 없는 연결을 단 표를 만들면 문이 잡는지 확인한다.
- `docs/SCHOOL-MOVE.md`(절차·주의), AGENTS.md 데이터 경계 1·확장 사다리 문구, `.gitignore`에 `.school-move/`, 연구소 문서 2개에 결정 반영
