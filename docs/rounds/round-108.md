# 108차: 마감 연결 — 수업 마감이 계산식 판 결과로 굳힌다 (ADR 0042)

- 날짜: 2026-11-27 · 세션: 관제
- 사용자: 마감 연결 방식으로 '앱 계산 + DB 대조 (추천)'을 골랐다.
- 계기: Codex #166 P1. 마감이 척도만 봐서 보장지도를 마친 40% 미도달 학생이 미이수로 굳었다.

> **요약** 학기 마감 때 학교가 고른 계산식으로 성취도·이수·학점을 정한다. DB는 계산에 쓴 자료가 지금 원장과 같은지 대조하고, 식·자료·결과를 함께 얼린다. 보충지도·추가학습 이수를 기록하는 칸도 생겼다.

> **왜** 학교마다 이수 기준이 다른데, 지금까지 마감은 계산식을 보지 않았다. 보충지도를 마친 학생도 미이수로 남았다. 앞으로는 식과 자료를 함께 얼려 두므로 나중에 누구든 같은 결과가 나오는지 다시 확인할 수 있다.

```terms
용어 | 쉬운 설명 | 예시
마감 연결 | 학기 마감이 학교가 고른 계산식으로 결과를 확정하는 것 | '공통과목' 식으로 1학기 국어 마감
DB 대조 | 앱이 계산에 쓴 자료가 지금 원장과 같은지 DB가 다시 맞춰 보는 것 | 계산 뒤 점수를 고쳤으면 마감을 거부하고 다시 계산하게 함
보충 이수 | 최소 성취수준 보장지도·추가학습을 마쳤는지의 기록 | 39점 학생 보장지도 6차시 마침 → E·이수
중간값 순서 | 식 안에서 먼저 계산할 값의 순서 | 합계 → 원점수 → 성취도
```

## 운영 마이그레이션 실패와 수정 (병합 뒤)
- 증상: 운영 DB 마이그레이션이 `must be owner of function close_offering`으로 실패했다. 파일 단위 트랜잭션이라 되돌려졌고, 배포 단계도 건너뛰었다. 운영은 이전 상태 그대로였다.
- 원인: `close_offering`은 F2 때부터 `app_writer` 소유다. 운영의 마이그레이션 역할은 슈퍼유저가 아니라서 남의 함수를 다시 정의할 수 없다. 로컬·CI는 슈퍼유저라 잡지 못했다.
- 수정: 45차 `agent_autopublish`와 같은 방식을 썼다. `grant create on schema app to app_writer; set local role app_writer;`로 다시 정의한 뒤 `reset role`.
  - 적용되지 않은 파일이라 그 파일을 고쳤다.
- 확인: 슈퍼유저가 아닌 역할을 스키마·표 소유자로 둔 연습 DB에서 시험했다. 옛 파일은 운영과 같은 오류가 났고, 고친 파일은 통과했다.
- 교훈(할 일): CI에 '슈퍼유저 아닌 역할로 새 마이그레이션 적용' 단계를 더하면 같은 사고를 미리 잡는다.
