# 76차: 학사 화면 6 — 기본판 제안 수락(학교 설정) · 기본판·보고(관제)

- 날짜: 2026-11-26 · 세션: 관제
- 사용자 지시: 71차와 같음("추가로 해야 할 작업들은 하도록 하자", 구독 토큰 안에서).
- 판단: ADR 0027(58차) DB 함수에 화면을 붙여 71~76차 학사 화면을 마친다. 새 표·새 권한 경로는 없다. 관제는 학교 내부 표를 읽지 않고 보고 스냅샷만 본다.

## 한 일
- **학교 설정 → '기본판 갱신 제안'**(학교 관리자)
  - 지금 사본 판과 받은 제안을 보인다.
  - 제안마다 '더할 것'과 '학교 값 유지(부딪침)'의 개수·이름을 보인다.
  - 수락·보류·거절을 메모와 함께 남긴다.
  - 수락하면 DB가 이 학교에 없는 것만 더하고, 학교가 고친 값은 그대로 둔다.
- **전체 관리 → '기본판·보고'** `/admin/baseline`(전체 관리자)
  - 요약 지표: 보고한 학교, 재학생 합, 개설·마감 합, 기본판이 뒤처진 학교
  - '지금 모으기'(`app.collect_school_reports`)
  - 학교별 최신 보고 표: 상태, 기본판 판(뒤처짐 표시), 재학, 교직원, 개설, 마감, 홈페이지 항목, 모은 때
  - 관제 기본판: 지금 판, 코드·척도·정책 수, 판별 제안 상태 수
  - 새 판 내기: JSON 편집, 제목·이유 필수, 확인 창, `base_version` 409
- **API**
  - `POST /api/baseline`(학교 결정)
  - `POST /api/admin/baseline`(publish·collect, `handlePlatform`)
- **읽기**(`src/lib/baseline.ts`)
  - `latestReports`: 학교별 최신 보고 스냅샷
  - `offerCounts`

## 시험
- `tests/baseline-screen.test.ts`
  - 관제가 새 판을 내면 제안 수가 생긴다.
  - 학교 A의 제안에 새 코드가 들어 있다.
  - 교사·다른 학교는 결정할 수 없다.
  - A가 수락하면 1개가 반영되고 사본 판이 오른다. B는 보류한다.
  - 보고 모으기는 관제만 한다. A는 최신 판, B는 뒤처진 판으로 보인다.
  - 학교 관리자는 자기 학교 보고·제안만 보고, 교사는 보고를 볼 수 없다.
- e2e 새 단계(axe 위반 0)
  1. 관제가 보고를 모은다.
  2. JSON에 코드 하나를 더해 새 기본판을 낸다.
  3. 학교 A 설정에서 제안을 수락한다.
  4. 사본이 2판이 된다.

## 71~76차를 마치며(관제 점검: 이번에 더한 제한·예외)
- 새 표, 새 권한 경로, 새 예외는 없다. 모든 쓰기는 기존 DB 명령 함수를 탄다(AGENTS.md '권한·쓰기 경로는 역할마다 하나').
- 화면에서 정한 제한
  - 기록(`/records`)은 관리자 화면이다. DB 함수가 이미 관리자만 받는 일이라 같다.
  - 출결 달력·성적 마감은 관리자만, 점수 입력은 담당 교사도 한다. 모두 DB 판정과 같다.
- 74차에 홈페이지 설정 저장 뒤 탭이 바뀌던 결함을 고쳤다(사용자 목적과 무관한 기존 결함).
