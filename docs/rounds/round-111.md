# 111차: 출석인정 판정을 그 날짜에 유효한 코드 판으로만

- 날짜: 2026-11-27 · 세션: 사람이 연 세션(선생님 지시)
- 계기: `app.attendance_days`(하루 환산)가 출석인정 사유를 볼 때 코드 판의 유효 기간을 보지 않았다. 같은 문제를 수업 마감 입력(`app.offering_calc_inputs`)에서는 108차 Codex 지적(#169)으로 이미 고쳤다.

> **요약** 학교가 출결 사유 코드를 바꿔도(옛 판 → 새 판), 결석한 그 날에 유효했던 판만 보고 출석인정 여부를 정한다. 새 판 기간의 결석이 옛 판 때문에 출석으로 세이던 오류를 고쳤다.

> **왜** 사유 코드는 `app.add_code`로 새 판을 만들면 옛 판과 같은 코드를 쓰고 기간만 다르다. 예전 조건은 어느 판이든 '출석인정'이면 출석으로 셌다. 그래서 출석률, 만성 결석, 출석 2/3 판정, 그리고 그 값을 얼리는 학년도 기록·지정일 보고 스냅샷이 틀어질 수 있었다.

```terms
용어 | 쉬운 설명 | 예시
코드 판 | 같은 코드의 시기별 정의. 바꾸면 옛 판을 닫고 새 판을 연다 | 'recognized' 3/10 전에는 출석인정, 3/10부터는 아님
유효 기간 | 그 판이 쓰이는 날짜 범위(시작일 포함, 끝일 제외) | [3/10, 끝 없음)
하루 환산 | 하루 사건·반나절·교시 기록을 결석 1·0.5·0으로 바꾸는 계산 | 오전 결석 = 0.5
```

## 한 일
- 마이그레이션 `20261128001100_attendance_reason_effective.sql`: `app.attendance_days`를 최신 정의(F6 열람 계정 판, `20261127000100`) 그대로 다시 만들고 사유 판정에 `(c.effective_from is null or c.effective_from <= d.day) and (c.effective_to is null or d.day < c.effective_to)`만 더했다. 소유자는 원래처럼 마이그레이션 역할(`app_writer` 아님), 실행 권한은 `authenticated`만.
- 같은 패턴 점검(`list_key = 'attendance_reason'`)
  - `app.record_attendance`의 사유 검사: 이미 기간 조건 있음
  - `app.offering_calc_inputs`(수업 마감 입력): 108차에 고침
  - 옛 정의 2곳(`f3`, `f6`): 이번 판이 대신함
  - `attendance_summary`·학년도 기록 마감·지정일 보고·`/my` 열람은 모두 `attendance_days`를 거치므로 함께 바로잡힌다. TS 쪽은 `codes(…, day)`로 이미 날짜 기준 조회.
