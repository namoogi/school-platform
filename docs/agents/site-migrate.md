# 일 하나의 예: 옛 홈페이지를 새 디자인으로 옮기는 일 돕기 (87차)

학교 관리자가 `/site/templates` → '기존 홈페이지를 새 디자인으로 옮기기'에서 옛 주소를 읽고, 템플릿을 골라 **시안 쪽**을 만든 뒤에 학교 AI(Codex·Claude Code 등, 학교 구독)가 하는 일이다. 플랫폼은 유료 AI를 부르지 않는다(ADR 0032).

## 사람이 줄 것
- 관리 화면의 '학교 AI에게 맡길 글'(템플릿 이름, 옛 주소, 못 채운 칸, 사진 칸)
- 'AI 작업 공간'에서 발급한 작업 토큰: 종류 `page`, 권한 `read`·`upload`·`edit` (공개 권한은 주지 않는 것이 기본)

## 할 일
1. `GET /api/agent/entries/page`로 시안 쪽 목록을, `GET /api/agent/entries/page/<주소>`로 최신 판을 읽는다. 쪽 내용의 `[ … ]`가 남은 안내 자리다.
2. 옛 사이트에서 그 칸에 맞는 사실을 찾아 채운 **새 판**을 `POST /api/agent/entries/page/<주소>/versions`로 저장한다(`base_version`을 함께 보낸다. 그 사이 사람이 고쳤으면 409 → 다시 읽고 합친다).
   - 학비·날짜·연락처처럼 틀리면 안 되는 사실은 옛 사이트 글 그대로 옮기고, 어디서 가져왔는지 판 메모에 쓴다.
   - 옛 사이트에 없는 내용은 지어내지 않는다. 안내 자리로 두고 보고한다.
3. 사진 칸
   - 옛 사이트 사진 가운데 학교가 권리를 가진 것만 쓴다. 다른 사이트·검색 그림은 쓰지 않는다.
   - 새로 그릴 때는 실제 사람 얼굴·학생이 없는 삽화(건물·자연·사물·추상)로 만든다. 학교 이름·로고를 지어내지 않는다.
   - `POST /api/agent/assets?name=<이름>`으로 올리고(PNG·JPG·WEBP 5MB), 받은 id를 그 쪽 블록의 `asset`에 넣은 새 판을 저장한다.
4. 공개하지 않는다. 바꾼 쪽·판 번호, 남은 안내 자리, 사람이 확인할 사실을 목록으로 보고한다.

## 하지 말 것
- 공개·설정·구성원 변경, 다른 학교 자료, 실제 학생 사진을 허락 없이 올리기
- 옛 사이트 문구를 다른 학교 템플릿·예시에 쓰기
