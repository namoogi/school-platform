# 학교 성적표 분석 → 기본판에서 응용하기 (성적 산출·양식)

- 근거: ADR 0041
  - 선생님 2026-11-27: "대안학교는 그 양식이나 성적 산출하는 방식이 다를 수도 있어. 그건 각 학교별로 성적표를 받아서 분석하는 작업을 거쳐서 기본 DB에서 응용해서 양식을 만들어야 해."
- 누가: 학교 구독 AI(학교 작업 토큰) 또는 학교에 입장한 관제 세션이 분석하고 초안을 만든다(ADR 0032·0024). **확정은 학교 관리자**가 한다.
- 플랫폼 서버는 유료 AI로 분석하지 않는다(ADR 0032).

## 한눈에
```
학교 자료 받기 ─▶ 매핑표 만들기 ─▶ 가까운 기본판 고르기 ─▶ 학교 사본 고치기 ─▶ 미리 계산으로 맞춰 보기 ─▶ 사람이 확정
 (성적표·규정)    (칸·산출 방식)     (견본·척도·출력)       (새 판, '왜' 칸)     (경계값·실제 견본)       (다른 점은 질문)
```

## 1. 받을 자료
| 자료 | 왜 | 주의 |
| --- | --- | --- |
| 성적표·학생부·성적증명서 양식 | 어떤 칸을 어떤 순서·표기로 내는지 | **빈 양식**이나 이름·점수를 가린 견본을 받는다. 실제 학생 정보는 저장소·시험·대화 기록에 남기지 않는다 |
| 학업성적관리규정(또는 평가 규칙) | 반영비율, 반올림, 성취도 구간, P/F, 이수 기준, 동점자 처리 | 조항 번호를 '왜' 칸에 적는다 |
| 학기 평가 계획 한 과목 | 영역·만점·반영비율 실제 예 | 합성 숫자로 바꿔도 된다 |
| 계산된 결과 몇 줄(가림 처리) | 미리 계산과 맞춰 볼 정답 | 경계 근처(89.5, 59.5, 39) 학생이 있으면 좋다 |

## 2. 매핑표 (분석 결과물)
학교 자료를 아래 표로 정리한다. 빈칸은 '학교 확인 필요'로 남기고 추측하지 않는다.

| 묻는 것 | 학교 값 | 근거(조항·양식 위치) | 플랫폼 자리 |
| --- | --- | --- | --- |
| 영역과 반영비율, 만점 | 예: 프로젝트 50·포트폴리오 30·발표 20 | | 평가 항목(F2) |
| 합계 계산(정규화 여부, 반올림 순서·자리) | | | 계산식 판 `lets` |
| 성취도 구간·이름(A–E, A–F, 통과/미통과, 서술만) | | | 척도 판 + 계산식 `band` |
| P/F가 정해지는 곳(과목 속성·학생 판정) | | | `course.pass_fail`·`entry.level` |
| 이수 기준(점수·출석·산출물·보충) | | | 계산식 `passed`, `support.*` |
| 석차·석차등급·과목평균·분포 쓰는지 | | | 모집단 계산(`population.ts`) |
| 평점(GPA)·가중 | | | 척도 판 `points` + `gpa` |
| 학년·졸업 판정 | | | 학년도 범위 계산식(다음 단계) |
| 서술 칸과 글자 수(글자/byte) | | | 성적 정책 판 서술 한도 |
| 출력 양식 칸 순서·표기(예: `93/82.1`, `A(54)`) | | | 출력 프로필 판(F4) |

## 3. 가까운 기본판 고르기
| 학교가 닮은 것 | 계산식 견본 | 척도 견본 |
| --- | --- | --- |
| 한국 고등 공통 / 선택 / 과탐실험 / 체육·예술 | `kr_high_common` / `kr_high_elective` / `kr_high_science_lab` / `kr_high_arts_pe` | 공통 `kr_achievement` · 선택 `kr_elective` · 과탐실험 `kr_science_lab` · 체육·예술 `kr_arts_pe` |
| 한국 중학교 / 중학교 체육·예술 | `kr_middle` / `kr_middle_arts_pe` | `kr_elective` / `kr_arts_pe` |
| 드리미학교 방식(두 번 반올림, P/F 출처 둘) | `rounded_twice_bands` | `kr_achievement` |
| 미국 A–F / ± | `us_letter_pf` / `us_letter_plus_minus` | `us_letter`, `us_plus_minus` |
| 프로젝트 통과형 · 역량 도달형 · 가중 평균 · 동료 평가 혼합 | `pass_fail_project` · `competency_mastery` · `weighted_average` · `peer_teacher_mix` | `pass_fail` |

- **척도와 계산식은 같은 구간으로 짝지어 고른다.** 지금 수업 마감은 척도 판(`app.band_for`)으로 등급을 굳힌다. 짝이 어긋나면 계산식이 I(미이수)라고 해도 마감에서 C·이수가 된다. 견본 짝은 시험 `tests/calc-kr-us.test.ts`가 0~100점 전부로 맞춰 본다. 학교 사본을 고칠 때도 둘을 함께 새 판으로 쓴다.
  - **계산식으로 마감하기**(108차, ADR 0042): 마감 화면에서 '계산식'을 고르면 성취도·이수·학점을 그 식의 결과로 굳힌다. 보충 이수(보장지도·추가학습)와 과목 출석률이 반영된다. 이때 척도는 표시용이다. 계산식 없이 마감하면 척도만 보므로 보충 이수가 반영되지 않는다.

견본 목록과 식은 `GET /api/calc-rules`(`presets`, 로그인한 관리자·관제)로 본다. 학교 AI는 이 주소를 작업 토큰으로 읽지 못하므로, 템플릿 화면의 'AI 지시문'에 견본 목록과 템플릿 견본의 식이 들어 있다(127차). 근거는 `docs/research/kr-us-grading-2026-11.md`, `docs/research/dreamy-calc-rules-2026-11.md`.

## 4. 학교 사본 고치기
- 기본판은 그대로 두고 **학교 사본에 새 판**을 쓴다. 판은 고치지 않는다. 쓸 때 `base_version`을 붙이고, 그 사이 새 판이 생겼으면 409다.
- '왜' 칸에 학교 규정 조항과 다른 점을 적는다. 예: "규정 12조: 40 미만도 E, 보충 없음".
- 쓰는 곳
  - 척도 판·성적 정책 판: 성적 화면(`/grades`)은 정해진 척도 견본 추가와 정책의 점수·최종 자릿수·표준편차 방식만 받는다. 맞춤 척도 구간(경계·평점·이수)과 그 밖의 정책 칸(서술 글자 수 등)은 화면이 없어, 계산식 판과 같이 대화창 '새 대화' → 관제가 학교에 입장해 저장한다(`app.save_scale`·`app.save_grading_policy` 경로).
  - 계산식 판: `POST /api/calc-rules {action:'save'}`. 학교 관리자만 쓴다.
    - 학교 작업 토큰(`package`)으로 쓰는 길은 다음 단계다(ADR 0040).
  - 출력 프로필: 아직 고치는 화면·API가 없다(`app.save_output_profile` DB 함수만 있음). 학교 관리자가 대화창 '새 대화'로 초안을 보내면 관제가 학교에 입장해 저장한다(ADR 0024). 계산식 판도 화면이 없어 같은 길이다.
- 학교 맞춤은 설정값으로만 한다. 표·코드를 올리지 않는다(ADR 0035).

## 5. 미리 계산으로 맞춰 보기
- `POST /api/calc-rules {action:'preview', spec, samples}`를 쓴다. 합성 견본으로 계산하고 저장하지 않는다.
- 꼭 넣을 견본
  - 경계값: 89.5·89.49·59.5·39.5
  - 자료 없음: 점수 하나 비움, 출석 없음
  - P/F 과목, 학생 판정 P·F(또는 NP), 보충 이수 전·후
- 학교 결과 견본(가림 처리)과 하나라도 다르면 멈춘다. 어느 단계(반올림·구간·P/F)에서 갈렸는지 적고 **학교에 질문을 연다**. 새 규칙이 기존 확정 규칙을 조용히 덮지 않는다(규칙 6).

## 6. 확정과 기록
- 학교 관리자가 매핑표와 미리 계산 결과를 보고 확정한다.
  - 계산식 판·척도 판의 새 판이 그 확정이다. 수업 마감 판이 그 판 번호를 남기는 일은 다음 단계다.
- 매핑표는 학교 정의 기록이나 학교 연구 노트에 남긴다. 다음 학기에 규정이 바뀌면 매핑표부터 고친다.
- 다른 학교에도 쓸 만한 방식이면 PR 본문 `## 전체 적용 후보`에 적는다. 관제가 기본판 견본으로 올릴지 정한다(ADR 0027 갱신 제안).
