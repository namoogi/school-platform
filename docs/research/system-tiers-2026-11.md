# 시스템 구성안: 규모별 · 격리 등급별 (상용화 대비, 2026-11-26)

- 요청: 선생님 — "상용화 시기에는 학교별로 생성할 때 독립된 서버·DB·서비스 등으로 가격 정책을 다르게 하는 것이 필요하겠다. 시스템 커버 규모 등을 고려해 연구소에 시스템 구성을 정리해 올리자."
- 근거 문서
  - ADR 0019: 규모 설계 1,000곳
  - `docs/research/backend-tenancy-2026-11.md`: 드리미포털 방식 검토, 계층형 추천
  - 77~80차: 마이그레이션 Actions, RLS 문
- 표기: [사실] 공식 문서 · [추정] 가정에 따른 계산 · [판단] 관제 해석 · [확인 필요]
- 가격은 2026-11 검색 확인값이고 바뀔 수 있다. 판매 가격이 아니라 **원가 구조**다. 판매 가격은 선생님이 정한다.

## 1. 원칙 [판단]
1. **핵심 기록은 한 가지 코드로 지킨다.** 학적·성적 마감 판·발행본·열람 계정은 어느 등급이든 같은 코드·같은 규칙(모든 표 RLS·판·해시)으로 돈다. 등급은 '어디에서 도는가'만 바꾼다.
2. **격리는 위로만 옮긴다.** 공용형 → 확장형 → 전용형으로 학교를 옮길 수 있다. 모든 표에 `school_id`와 복합 외래키가 있어서 한 학교 행을 통째로 다른 프로젝트로 옮길 수 있다(ADR 0019 셀 나누기).
3. **결제처는 늘리지 않는다.** 모든 등급을 Supabase 조직 하나와 Vercel 팀 하나 안에 둔다. 프로젝트는 늘어도 청구서는 각 한 장이다.
4. **원가는 쓰는 학교에 붙인다.** 확장·전용형 원가는 그 학교 요금에 넣는다. 공용형 학교가 부담하지 않는다.

## 2. 격리 등급 네 가지

| 등급 | 무엇이 따로인가 | 누구에게 | 학교 AI가 할 수 있는 것 | 월 원가(학교 1곳) [추정] |
|---|---|---|---|---|
| **공용형** (기본) | 없음. 공용 DB(`school_id`+RLS), 공용 앱, 학교별 R2 접두어 | 대부분의 학교 | 코드·규칙 판·정의 엔진(기록 유형·양식·화면·출력·흐름)·홈페이지 | 약 $0.2~1 (100~1,000곳일 때 공용 원가를 나눈 값) |
| **확장형** | 학교 전용 **Supabase 프로젝트 1개**(그 안에 앱마다 스키마 칸) + 앱마다 Vercel 프로젝트. 핵심 기록은 공용에 둔다 | 자체 기능·앱을 AI로 만들려는 학교 | 위 + 자기 표(선언 `tables.json`, 플랫폼이 검사 뒤 생성)·서버 코드·외부 연동. 핵심과는 OIDC 로그인 + API 창구(허용목록·사용량 장부)로만 주고받는다 | 공용분 + Supabase 프로젝트 $10~15(Micro~Small) + Vercel 빌드·함수 사용량(앱 수·배포 빈도에 좌우) |
| **전용형** | 위 + **핵심 기록까지** 그 학교 전용 Supabase 프로젝트로(셀 크기 1). 백업·복원·컴퓨트가 학교 단위 | 큰 학교, 다른 학교와 성능·복원을 나눠야 하는 학교, 계약상 분리가 필요한 학교 | 확장형과 같음 | $15~60(Small~Medium) + 선택: 시점 복구 PITR $100 [사실] + 운영 시간 |
| **독립형** (협의) | 학교(또는 기관) 명의의 별도 Supabase 조직·지역, 또는 자체 서버(self-host) | 데이터 국외 저장이 막힌 기관, 교육청·재단 단위 | 계약으로 정함 | 학교가 인프라를 직접 부담 + 설치·업데이트 지원료 |

비고
- 공용형의 '학교당 원가'는 ADR 0019 추정치(100곳 월 $60~110, 1,000곳 월 $200~500)를 학교 수로 나눈 값이다.
- Supabase Pro는 조직당 $25/월(첫 프로젝트 포함)이고, 프로젝트를 더할 때마다 컴퓨트 $10/월부터 붙는다. 컴퓨트는 Micro $10 · Small $15 · Medium $60 · Large $110 [사실, supabase.com/pricing·compute 문서].
- Vercel Pro는 $20/월 + 사용량이고, 프로젝트 수로는 과금하지 않는다(포털 [잼] 앱 48개 운영). 포털 경험상 비용 변수는 **빌드 시간**이다.
- 독립형의 국외 저장 법률 판단은 전문가 확인 필요(이 문서는 법률 자문이 아님).

## 3. 규모별 구성

| 단계 | 학교 수 | 구성 | 해야 할 일(이미 한 것 ✔) |
|---|---|---|---|
| 지금 | ~3 | 공용형만. Supabase 1 + Vercel 1 + R2 | ✔ 학교별 R2 접두어(A1) · ✔ 마이그레이션을 Actions로, 배포 훅(77~79차) · ✔ RLS 문(80차) |
| 첫 유료 전 | ~10~30 | 공용형. 확장형 시범(드리미학교 1곳) | Vercel Pro 전환(약관) · 공개 홈페이지 캐시(A2) · DB 연결 줄이기(A3) · OIDC 제공자 · API 창구 · 확장 프로비저닝 시범 · 미리보기 DB |
| 성장 | ~100 | 공용형 대부분 + 확장형 일부 + 전용형 소수 | 공용 DB 컴퓨트 Small→Medium · 학교 떼어 내기/옮기기(A5) 자동화 · 관제 보고에 **가장 무거운 학교** 칸(평균 말고 최대) · 확장형 사용량 상한 |
| 확장 | ~1,000 | 공용형을 **셀** 몇 개로 나눔(지역·규모별) + 확장·전용형 | 학교 → 셀 연결 표 · 셀마다 마이그레이션(Actions 행렬) · 기본판 제안을 셀 사이로 · 셀별 감시 |
| 그 이상 | 1,000+ | 셀 여러 개 + 지역별 조직(국가별 보관 요구) | 독립형 표준 설치본 · 지역 조직 |

**한 그릇의 한계를 정하는 것**은 학교 수보다 **가장 무거운 한 학교**다(포털 교류). 그래서 성장 단계부터는 그 학교를 전용형으로 빼는 기준을 숫자로 둔다. 예: 질의 시간 상위 1% 점유 또는 행 수 상위. 숫자는 운영 측정 뒤에 정한다.

## 4. 등급별로 운영이 달라지는 것 [판단]

| | 공용형 | 확장형 | 전용형 |
|---|---|---|---|
| 마이그레이션 | 1번(Actions) | 핵심 1번 + 확장은 그 학교 선언 표만(플랫폼 검사기) | 그 학교 프로젝트에도 핵심 마이그레이션(Actions 행렬) |
| 기본판 갱신 | 제안 → 수락(지금) | 같음 | 같음(셀 사이로 전달) |
| 백업·복원 | 공용 일일 7일. 한 학교만 복원 불가 → 떼어 내기·내보내기로 보완 | 확장분은 학교 단위로 복원 가능 | 학교 단위 복원, PITR 선택 |
| 장애 범위 | 공용 장애는 모두에게 번짐 | 확장 앱 장애는 그 학교에 갇힘 | 그 학교에 갇힘 |
| 관제 보고 | 보고 계약 `school_report_v1` | 같음 + 확장 사용량 | 같음(프로젝트 사이로 모음) |
| 보안 문 | RLS 문(80차) | + 선언 표 검사기, API 허용목록 | RLS 문을 그 프로젝트에도 |

## 5. 가격 정책을 짤 때의 뼈대 (선생님 결정용) [판단]
- **공용형**: 좌석·기능(라이선스) 요금. 지금 구조 그대로다(학교 설정의 좌석·기능·예상 금액).
- **확장형**: 공용형 + '확장' 월정액(원가 $10~15 + 빌드·함수 사용량 상한 포함) + 초과 사용량
- **전용형**: 공용형 + 전용 월정액(컴퓨트 등급별) + 선택 PITR + 이전 설치비 1회
- **독립형**: 별도 계약(설치·업데이트·지원)
- 비용 정직성: 원가표를 학교에 보여 줄 수 있게 두고, 학교 설정의 '예상 금액'에 등급별 원가를 더한다.

## 6. 결정해 주실 것
1. 등급 이름과 네 등급 구성(공용·확장·전용·독립)으로 갈지
2. 확장형 시범을 드리미학교 1곳으로 시작할지(OIDC·API 창구·프로비저닝 순서)
3. (2026-11-27 결정, ADR 0035: 공용 기본 + 설정값 맞춤 + 이전 가능. 확장형은 요구가 생길 때) 백엔드 방향 계층형 백엔드 ADR 채택 여부. 채택하면 AGENTS.md '에이전트 DDL·코드 업로드 없음'을 '핵심에는 없음, 확장 프로젝트에서는 선언 표·코드 허용'으로 고친다.
