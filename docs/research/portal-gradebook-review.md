### 근본 원인
기능이 먼저 오고 설계가 뒤따랐다. 마이그레이션 흐름이 그 증거다 **[잼]**.
- 0117 settings → 0118 기재명 → 0119 학생별 기재명 → 0120 구양식 스냅샷 → 0121 자국 → 0136·0137 중·고 분리 → **0220 `source_course_id`(이름 대신 id로 잇기 시작)** → **0258 학생 구분** → **0261 게이트 단위 교정** → **0318 표기 덧칠** → **0348 통계 박기** → 0519 transcript 보강.
- 번호가 올라갈수록 '처음 이름으로 이어 둔 것을 사후에 고치는' 마이그레이션이 늘어난다. 0220·0258·0261·0318·0348이 모두 처음 설계에 없던 축(사람·수업 id, 학생 구분, 자료 단위, 표기 판, 모집단)을 뒤에 끼워 넣은 자국이다.

### 부실이 아니라 '사고에서 나온 규칙'인 것 (건드리기 전에 읽을 것)
포털 세션의 경고를 그대로 옮긴다. 밖에서 보면 비일관으로 보이지만 정리하면 같은 사고가 다시 난다.
- **게이트 단위**: 성적·수상은 학기, 창체·봉사·자격증은 연(0261 사고).
- '명단 0명이면 아카이브를 안 만든다'(의도된 문).
- 반영 '채우기만(fillOnly)': 향상된 점수를 덮어써 낮추지 않게(관리자 결정).
- 표기 덧칠은 원본을 고치지 않는다(`sr_course_display_overrides`).
- 정정대장 워크플로 없음, NEIS 바이트 강제 차단 없음: 미인가 학교의 의도된 선택.
- 학교급별로 일부 섹션(수상·자유학기·독서)은 중등에만 있다. 의도적으로 뺀 곳과 빠뜨린 곳이 섞여 있어 구분하는 표가 필요하다.
- 낙인 금지(줄 세우기·위험도 정렬 없음). 다만 너무 넓게 적어 영어 LMS 3단계가 막힌 반대 사고도 있었다.
- 학생부 과목명 = '대학 제출용 표기'. 바꾸는 것은 위조가 아니라 실무다(2026-09-05 AI가 이를 '성적 위조'로 거절한 사고). 바뀌지 않는 것은 수강 사실·원점수·성취도·세특이다.

## 3. 개선안 — 포털 쪽 단계적 경로 (멈추지 않고 고치기)
원칙:
- 한 단계는 한 축만 바꾼다.
- 새 길을 먼저 깔고, 옛 길은 '읽기 전용 → 대조 → 제거' 순서로 걷는다.
- 단계마다 **대조 도구**(옛 값 = 새 값)를 통과해야 다음으로 간다.
- 지금 도는 학생부 자료는 관리자 결정 없이 고치지 않는다.

| 단계 | 할 일 | 끝났다는 증거 | 부채 |
| --- | --- | --- | --- |
| P0 안전망 | 계산 순수 함수(성취도 분할점·반올림·가중치 합·P/F 분기·평균/표준편차)에 **경계값 테스트**. 예: `toAchievement(89.5)`, 79.995, 가중치 99.99/100.01. 사본 세 곳의 `getCourseStats`를 한 함수로(다른 두 곳은 import) | 테스트 통과, 사본 0 | D2·D4 |
| P1 열쇠 | 이름·메일 문자열 열 38개표 → id 열 추가(옛 열은 표시용으로 남김) → 쓰기는 id로 → 대조 → 읽기 전환. 우선순위: `student_transcript` 유일 제약(개명 이중 계상), `course_attendance.student_email`, `class_archive.students`, 드라이브 파일명 열쇠 | 이름으로 조인하는 질의 0, 유일 제약이 id 기반 | D1 |
| P2 표기를 1급으로 | 수업(실제명) ↔ **제출용 표기 판**(적용 학년도·용도)을 별개 표로. 학생부 행은 `course_id + label_version_id`. 기존 덧칠(`sr_course_display_overrides`)을 첫 판으로 옮김 | 표기를 바꿔도 통계·모집단이 그대로(박기 불필요) | D1·D2·D7 |
| P3 모집단 = 수업 id | 통계 모집단 열쇠를 `source_course_id`(수업 id)로. 92%는 이어져 있고 남은 8%는 대조 목록으로 사람이 연결. `entry_year` 없는 학생 1명 보완. 문서(AGENTS.md·0348 주석)와 코드 일치 | 0348 박기·split/rename 도구가 불필요(박힌 72행은 마감 판으로 이관) | D2 |
| P4 학교급·기수·학년을 칸으로 | `cohort` → `{level, n}` 두 칸, 학년도별 학년을 저장하거나 뷰로(계산식 한 곳), `term` 문자열 → 학기 표 id. 트랙 잣대 정규식(`/[789]기/`) 제거 | 10기 시험 자료로 모든 잣대 통과 | D5·D4 |
| P5 마감을 개념으로 | settings 스위치를 **'학기 마감 판'·'학년도 기록 마감 판'** 표로 옮김(학기 단위 자료 vs 연 단위 자료를 표가 구분, 0261 교훈을 구조로). 반영(fillOnly)과 되돌리기는 판 사건으로. DB 트리거로 마감 후 쓰기 거부(앱 밖 경로도 막힘) | 쓰기 경로 다섯이 모두 같은 거부, 학기 넘김 시험에서 연 단위 자료 유지 | D3 |
| P6 쓰기·읽기 경로 하나 | 학생부 쓰기를 DB 함수(또는 단일 서버 모듈)로 모으고, 구 `school_record_entries` 메뉴를 읽기 전용 → 제거. 시트 내보내기 두 구현을 하나로(이름 정리). 졸업번호·블라인드·평균표준편차 읽기를 한 곳으로 | 구 메뉴 쓰기 0, 내보내기 1구현 | D4 |
| P7 자국을 모든 표에 | `sr_change_log`를 일반 자국(대상 표·행·학생 nullable·행위자 id·사유)으로. 과목·가중치·표기·마감 판 변경도 남김 | 83개 표 전부 자국 가능 | D6 |
| P8 양식 = 렌더 판 | 구양식을 '전환 중'이 아닌 **영구 렌더 템플릿 판**으로. 자료는 하나의 모델, 발급 당시 양식은 템플릿 판 id. 블라인드 잣대 하나를 두 양식이 공유. 대조 도구로 89명의 표↔스냅샷 일치 확인 후 | PDF·시트가 두 양식 모두 지원, 블라인드 1벌 | D7 |
| P9 권한 보강 | RLS 꺼진 4개 표 결정(정책 또는 이유 명시), service key 경로에 감사 기록, 학생부 표는 DB 함수 실행 권한만 | 정책 행렬 문서 + 거부 시험 | 4-C |

- 순서 추천: **P0 → P1 → P3 → P2 → P5 → 나머지**.
  - P0은 하루치 일이고, 이후 모든 단계의 안전망이다.
  - P1·P3은 개명·표기 변경 사고를 근본에서 끊는다.
  - P5는 가장 큰 사고 유형(학기 넘김·마감 후 덮어쓰기)을 DB에서 막는다.
- 하지 않을 것:
  - 정정대장 워크플로 강제(미인가 학교의 선택)
  - 석차등급 산출
  - 표기명 변경 금지
  - 구양식 폐기
  - 한 번에 전부 옮기는 빅뱅 전환

## 4. 학교 플랫폼(ADR 0025)에 넣은 것
포털이 사고로 배운 것을 새 토대에서는 처음부터 구조로 둔다.

| 포털 교훈 | 플랫폼 토대 |
| --- | --- |
| 이름 문자열 연결(D1) | 사람·수업·과목·학교는 id로만(지침 7, ADR 0004 P2) — 이미 구현 |
| 표기 바꾸기가 정상 실무(5-②) | **과목 표기 판**(ADR 0004 P5 `subject_labels`)을 F2 범위에 명시. 학생부 행 = 수업 id + 표기 판 id |
| 모집단 정의 갈라짐(D2) | 모집단 키 = 개설 id(지침 8), 마감 판에 그때 값 고정 — 손으로 박기 불필요 |
| 학기 단위/연 단위 자료 혼동(0261) | 기록 유형마다 **자료 단위(학기·학년도·수시)** 를 정의 속성으로, 마감 판이 그 단위를 따름 |
| 마감 스위치 다섯(D3) | 마감 판 1급 개념 + DB 트리거 거부(지침 4·8) |
| 자국 반쪽(D6) | 모든 판 표가 이전 판·행위자·사유를 가짐, 정의 변경도 판 |
| 구양식 공존(D7) | 출력 프로필·렌더 템플릿 **판**, 발행본 스냅샷이 발급 당시 템플릿 판을 고정 |
| 규칙이 앱에만(2절) | 마감·정정·참조 규칙은 DB(제약·트리거·명령 함수), 계산 규칙은 판 + 경계값 테스트 |
| 사고에서 나온 규칙이 비일관으로 보임 | 규칙 판에 **'왜'(결정·사고 근거) 칸**을 두고, 학교 AI가 규칙을 바꾸는 제안을 만들 때 그 칸을 먼저 읽게 한다(ADR 0025 E2) |
| AI가 표기 변경을 위조로 거절(5-②) | 학교 AI 지시문(AI 연결 글)에 학교의 정상 실무 목록을 싣는 자리 |
| 테스트 0(4-E) | 플랫폼은 계산·마감·정정 경계값을 통합 시험으로(현재 282개) 유지 |
