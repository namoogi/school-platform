## 0. 근거의 한계 (먼저 읽기)
- 이 세션의 네트워크가 많은 1차 출처를 막았다: 교육부·법령정보센터·태국 OBEC/OPEC·표준 기관(ed-fi.org, ceds.ed.gov, 1edtech) 문서, PowerSchool·Infinite Campus 지원 문서. 해당 부분은 **검색 결과 발췌**나 공식 저장소(GitHub) 원문으로 확인했고 갈래 보고서에 구분해 적었다.
- 설계 결정에 바로 쓰는 수치·규정(기재요령 세부, OneRoster 필드, CLR 2.0 열거, 태국 STUDENT 표 필드)은 원문 재확인 목록(각 보고서 끝)을 거친다.
- 오픈소스는 코드 원문 근거라 가장 강하다. 상용은 공개 문서·커뮤니티 근거라 '실제 동작'보다 '공개된 설계'를 본 것이다.

## 2. 다섯 가지 핵심 발견

1. **"확정을 사건으로 남기는" 시스템은 거의 없다.** 오픈소스 5종 모두 날짜 창이나 상태 값으로만 막고, 상용도 같은 행을 고치며 감사 기록을 남긴다. 그 결과 지난 기간 가중치를 바꾸면 평균이 소급해 바뀌고(Blackbaud 사용자 경고), 성적표가 '살아 있는 자료'가 되어 PDF를 따로 보관한다. 한국 학생부의 "학년도 마감 → 정정은 심의·정정대장"과 우리 지침 4·8·10이 오히려 업계보다 엄격하고 맞는 방향이다. → **마감 판을 토대의 1급 개념으로.**
2. **골격은 이미 수렴했다.** 학교–학년도–학기 나무–과목–개설–수강, 기간 있는 연관 행, 학교별 코드 목록(Ed-Fi Descriptor), 대리 키 + 외부 식별자 표. 새로 발명할 것은 없고, 우리 ADR 0004 골격과도 맞는다. 빈 곳은 **학기 나무, 코드 목록, 외부 식별자, 보호자(가족), 교직원 배정**.
3. **역량·증거·서술이 표준과 대안교육의 공통 미래다.** CASE(역량 틀), OB 3.0/CLR 2.0(서명된 학습 이력), Mastery Transcript(역량·증거·코멘트), 포트폴리오·서술 평가. 드리미 같은 PBL·학생 설계 수업 학교에 필요한 것은 점수 표가 아니라 **역량 축 + 증거물 + 서술 + 확인(서명)** 이다. 학생이 정의하는 과목은 어느 표준에도 없다 → **제안 → 학교 승인 → 개설**의 판 흐름으로.
4. **국가 서식은 핵심이 아니라 출력이다.** 학생부(KR)와 ปพ.1/5(TH)는 항목·척도·글자 수가 국가·연도마다 바뀐다(기재요령은 매년 개정). 핵심에 하드코딩하면 openSIS·OpenEduCat처럼 굳는다. → **출력 규칙 층(출력 프로필)** 이 핵심 원장에서 서식별 스냅샷을 만든다. 미인가 대안학교는 학생부 대신 '자체 학생부 + 편제표'나 CLR로 같은 원장에서 낸다.
5. **확장은 '값 → 규칙 → 기록 유형 → 모듈' 사다리로, 코드 업로드는 없이.** 상용도 학교가 핵심 흐름·확정 규칙을 바꾸게 하지 않는다. 코드 업로드형 확장은 원격 코드 실행 사고를 냈다(RosarioSIS). **AI가 학교 기능을 만들게 하는 공급사는 없다** — 우리 차별점이자 가장 조심할 지점이다. AI는 데이터로 된 정의(기록 유형·양식·규칙·출력)를 만들고, 플랫폼 엔진이 그것을 검증·실행한다.

## 3. 시스템에서 가져올 것 / 피할 것 (갈래 보고서 요약)

**가져올 것**
- 학기를 자기참조 나무로(RosarioSIS `school_marking_periods.parent_id`, OneRoster AcademicSession).
- 정정은 확정–취소–원본을 가리키는 새 문서 + 낙관적 동시성(Frappe `docstatus`·`amended_from`·`check_if_latest`) — 우리 `base_version` 409와 같다.
- 성적표 작성은 발행 흐름(Gibbon Reporting: 주기 → 기준 → 값 → Draft/Final 보관본).
- 출결은 사건 원장, 일별 값은 계산 캐시(Gibbon `AttendanceLogPerson`, Ed-Fi AttendanceEvent). 출결 코드는 속성(결석으로 셈, 교사 입력 가능)을 가진 학교별 코드.
- 척도를 판으로(Frappe Grading Scale, PowerSchool·IC), 한 평가 항목에 축 여러 개(Gibbon 성취·노력 → 한국 성취도·원점수·석차등급).
- 보호자는 가족 단위(Gibbon Family) + 사람 id 쌍 관계.
- 학교별 코드 목록 + 표준 사상(Ed-Fi Descriptor: 네임스페이스·유효 기간·이전 코드).
- 외부 연동은 어댑터(OneRoster·LTI·CASE·OB/CLR·xAPI·NEIS·태국 MOE)로, 내부 스키마로 쓰지 않음.
- 확장 표 범위 선언(PowerSchool `plugin.xml`이 읽을 표를 선언, Veracross `resource:action` 범위) — 우리 범위 토큰과 같은 계열.

**피할 것**
- 외래키 없는 스키마, 이름 문자열 PK·참조, 쉼표로 이은 id 문자열.
- 학년도마다 학교·표 복사, `archived_*` 사본 표.
- `ALTER TABLE`로 열을 더하는 사용자 정의 필드, 업로드형 코드 확장.
- 트리거로 계산 결과(평균·석차) 덮어쓰기 — 계산은 마감 판에 그때 값으로 얼린다.
- 상태 값·날짜 창만으로 '확정'.
- 국가 평가 제도를 핵심 표에 하드코딩.
- 일부 표만 학교로 분리하는 다학교(OpenEduCat), ERP에 묶인 학사 핵심.
- 지원·관리 계정 하나가 전 학교 자료에 닿는 구조(PowerSchool 2024-12 유출: 다단계 인증 없는 지원 계정 하나로 유출, 서울 외국인학교 포함 보도). → 관제 세션 점검 토큰의 기한·범위·기록을 더 엄격히(ADR 0025 위험 절).
