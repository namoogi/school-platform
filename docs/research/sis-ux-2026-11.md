# 학사 시스템 UI·UX 조사 — 학사 관리 템플릿과 일상 화면 설계용 (2026-11-27)

- 작성: Claude(조사 서브 작업), 2026-11-27
- 목적: 학교가 고르는 **학사 관리 템플릿**(한국 일반 초·중·고, 한국 대안학교(프로젝트·P/F), 미국 K-12, 국제학교(IB/AP 혼합), 홈스쿨 공동체)과 그 주변 화면(템플릿 고르기 → 학교 사본 → 학교 AI 수정, 학교급·학년 구성, 성적 입력부, 출결 입력, 학기 마감, 기록 발행, 학생 한 명 보기)을 설계하기 위한 UI·UX 근거.
- 범위 밖: 데이터 모델·기능 구조. 이미 `docs/research/sis-rea/commercial-sis.md`, `docs/research/sis-rea-2026-11.md`에 있으므로 되풀이하지 않는다. 국가 견본(계산식·척도)은 ADR 0041, 화면 셸·표·토큰 일반 원칙은 `docs/research/ui-rea-2026-11.md`.
- 표기: **사실 [n]**(출처 표 n번) / **추정**(필자 해석) / **확인 필요**(근거가 약하거나 원문을 못 봄). 4·6절의 '우리에게 적용'은 **우리 판단**이며 사실이 아니다.
- 화면 디자인을 베끼지 않는다. 구조·흐름·정보 배치 원리만 뽑았다. 실제 학생·교직원 정보는 다루지 않았다.

---

## 1. 핵심 요약

1. 상용 시스템은 **템플릿을 고르는 화면이 거의 없다**. 대신 ① 교육과정 유형 선택(Toddle의 과목·수업·IB 설정 유형), ② 작은 척도 프리셋(Google Classroom 3종), ③ 의존 순서가 있는 설정 점검표(Blackbaud·Infinite Campus), ④ 지난해 복사·학년 올리기 마법사로 나눠 해결한다 — 우리 '템플릿 → 학교 사본'은 이 넷을 한 흐름으로 묶는 자리다.
2. 일상 화면은 **교사 = 수업 중심, 관리자 = 학생·설정 중심**이 공통이다. 성적부는 격자 + '빈 칸만 채우기', 출결은 '기본 출석 + 예외만 표시' + 좌석표, 마감은 '검토 → 잠금 → 발행' 3단이다.
3. 가장 큰 실패 사례(4세대 나이스 출결: 학생 한 명씩 열어 입력, 좌우 스크롤)는 **일괄 입력 경로를 없앤 것**이다. 일괄·기본값·예외 우선 원칙을 지키는 것이 기능 수보다 중요하다.

## 2. 조사 방법과 한계

- 방법: 웹 검색(standard) 약 30회 + 열 수 있는 원문 직접 읽기. 원문을 연 곳: Blackbaud 도움말(학년도 설정·성적 설정 안내·학생 학업 프로필), Toddle 관리자 탐색 개편 안내, Google Classroom 관리자 기본 성적 설정, Gradelink 설정 안내, Alma 신설 학교 안내, 한국교육신문 2019 인터뷰.
- 막힌 곳: `help.managebac.com`(403), Coda에 미러된 Toddle 도움말(로그인 요구로 넘어감), `support.powerschool.com`·`kb.infinitecampus.com`은 지난 REA와 같이 본문 대신 **검색 발췌**로만 봤다. 교육부 4세대 나이스 보도자료 원문은 찾지 못했다.
- 근거 성격: PowerSchool·Infinite Campus·Skyward는 공급사 문서보다 **학군·주 교육청의 교사용 안내서**(버전·설정이 학군마다 다름)가 대부분이다. 메뉴 이름은 판마다 다를 수 있다. 빈 화면(empty state)과 점진적 공개는 공개 자료가 거의 없어 대부분 **확인 필요**로 남겼다.
- 수치는 출처 발췌에 있는 것만 옮겼다.

## 3. 시스템별 UI·UX 요점

### 3.1 PowerSchool SIS / PowerTeacher Pro
- **탐색**: 교사 시작 화면은 '이번 학기 내 수업' 목록이고, 수업 옆 아이콘으로 명단 → 학생 이름 → 학생 화면으로 내려간다. 학생 화면은 학교가 기본 쪽을 정하며, 안내서는 수업별 성적·교사·출결을 한 화면에 모은 Quick Lookup을 기본으로 추천한다. **사실 [6]**(학군 안내서 발췌)
- **성적부**: 점수 칸을 고르고 '채우기' 아이콘으로 세로(한 과제의 모든 학생) 또는 가로(한 학생의 여러 과제)로 채운다. **이미 점수가 있는 칸은 건드리지 않는다** → 예외를 먼저 넣고 나머지를 채우는 작업 순서가 안내된다. 점수 검사 창(Score Inspector)에는 '제출함' 같은 표시용 단축키가 있다. **사실 [1]**(검색 발췌, 학군 PDF)
- **표준 기반**: 과제 점수에서 표준별 최종 등급을 자동 계산하고 교사가 덮어쓸 수 있다. 학생 옆 패널에 과제·표준 진척·의견 기록이 나뉜다. **사실 [3][2]**
- **출결**: 좌석표 아이콘으로 좌석표를 열어 그 날 출결을 바로 넣는다 **사실 [4]**. '모두 출석' 빠른 방법은 제3자 안내서에만 있다 **확인 필요 [5]**.
- **새 학년도**: 새 학년도·학기를 만들면 출결 코드·환산·종 시간표 등이 지난해에서 복사되고, 그 뒤 점검 항목을 따라 확인한다(학년도·학기 → 종 시간표 → 달력 → 최종 성적 보고 기간 → 교직원·과목·시간표 → 학생 등록 순). 공식 단일 점검표는 못 찾았다. **사실 [7][8]**(주 교육청 안내), 순서 자체는 **추정**

### 3.2 Infinite Campus
- **탐색**: '새 모습(new look)'에서 교사 도구는 왼쪽 탐색의 Instruction 아래 분류별로 묶였다. 교사 첫 화면은 Control Center(지금 할 일 요약)이며, 2017년 발표에서 반응형으로 휴대폰·태블릿·PC가 같은 배치를 쓰고 출결·점수 입력을 화면을 떠나지 않고 한다고 했다. **사실 [13][14]**
- **성적부**: 채점 패널 위에 '채우기' 영역이 있고, 여기 넣은 값은 **그 패널의 기존 값을 덮어쓴다**(PowerSchool과 반대). 공통 점수 또는 '모두 제출함' 표시를 한 번에 넣는다. **사실 [9]**
- **좌석표·출결**: 좌석표는 가나다순(A–Z/Z–A)·무작위·수동 배치로 만들고, '주 좌석표'로 지정한 것이 출결에 쓰인다. 출결은 명단 또는 좌석표에서 P/A/T로 넣는다. 수업 화면이 아닌 다른 경로로 들어가면 좌석표가 안 열린다는 안내도 있다. **사실 [10]**(학군 안내서 발췌)
- **학년 말·새 학년**: 학년 말 점검표가 '마감 일 + 다음 학년 준비'를 한 문서로 묶고, 달력 마법사(Calendar Wizard)로 새 달력 만들기·앞으로 굴리기·기존 달력에 복사를 고른다. 복사는 원본·대상의 시간표 이름·학기 이름 등이 일치해야 한다. **사실 [11][12]**
- **휴대폰**: 교사 전용 앱은 못 찾았고, 웹 도구를 휴대폰용으로 맞췄다는 발췌가 있다(휴대폰에서는 단순 채점 편집기). **확인 필요 [13]**

### 3.3 Veracross
- **출결**: 교사 포털의 수업 → 출결 탭에서 하며, 여러 학교 안내서가 **모든 학생이 '출석'으로 미리 채워져 있고 예외만 바꾼다**고 쓴다. 지각·학교 행사 같은 코드는 행정실이 넣고 교사 화면에는 '기타 메모' 칸으로 보인다. **사실 [15]**(학교 안내 발췌)
- **수업 중심 탭**: 공급사 소개에 '수업마다 성적·의견(Grades & Comments) 탭'이 있다. **사실 [16]**(마케팅)
- **사람 찾기**: 교사 포털의 사람 찾기가 학생의 **지금 위치(수업·모임)**를 보여 준다. **사실 [17]**
- 학생 상세 화면 구성은 공개 자료에서 못 찾았다. **확인 필요**

### 3.4 Blackbaud (Education Management / SIS)
- **설정 순서를 문서가 강제한다**: 성적 설정 안내는 "앞 단계가 뒤 단계를 떠받치므로 처음부터 차례로 읽으라"며 12단계(성적 환산표 → 성적 분류 → 성적증명서 분류 → 평가 기간 → 평가 기술 → 성적 계획 묶음(학교급·과목 유형별) → 성적 계획 → 계획별 성적 칸 → GPA 식 → 석차 → 과목과 연결 → 성적표 제작기)를 점검표와 함께 준다. 지난해 설정 전체 복사는 설명하지 않고, 식·의견 분류는 해마다 재사용, 과목 학점은 해마다 다시 지정한다. **사실 [19]**(원문)
- **학년도 설정 화면**: 학년도·묶음 유형·학교급·성적 묶음으로 거른 뒤 학기 줄마다 '추가'로 평가 기간(입력 시작·끝, 마감 여부, 검토 날짜)을 넣고 이어서 성적 칸을 넣는 **2단 마법사**(다음 → 저장 후 나가기)다. 전통 성적과 기술(skills) 기반이 같은 틀에서 갈린다. **사실 [18]**(원문)
- **마감**: 검토자가 성적을 '검토함'으로 표시하고 그 화면에서 바로 고칠 수 있다. 평가 기간에 검토 시작일이 있어야 '검토 필요'로 뜬다. **사실 [21]**. 새 성적 탭이 검토·잠금된 성적을 다시 바꾸게 한다는 사용자 보고가 있다 **사실(사용자 증언) [22]**.
- **학생 프로필**: 머리 띠(이름·졸업 연도·재적 상태·비상 연락처·담당 교사·'지금 어디' 위치) + 알림 띠(보류·학습 지원 프로필 존재 알림) + 끌어서 순서를 바꾸는 타일(기기마다 기억). 역할마다 보이는 부분이 다르다. **사실 [20]**(원문)
- 좌석표 출결 도입 공지 제목이 커뮤니티에 있다. **확인 필요 [23]**

### 3.5 ManageBac (Faria)
- **설정 위치·순서**: 학교 이름·언어·학년도·학년(year level)·학기를 학교 설정에서 먼저 정한다. 수업·학년 묶음·보고서가 이것에 기대기 때문이다. 학기는 **프로그램(PYP·MYP·DP 등)마다** 따로 둔다. 학년 이름표는 가져오기 자료의 학년과 일치해야 한다. **사실 [24]**(검색 발췌, 원문 403)
- **프로그램별 빠른 시작 안내**: IB 비사용(Curriculum First)·EYP/PYP용 구현 빠른 시작 안내가 따로 있다 **사실 [26]**(제목 수준). 관리자 첫 로그인 때 QuickStart 마법사가 뜬다는 블로그 발췌가 있으나 원문에서 확인 못 함 **확인 필요 [27]**.
- **학년 넘기기**: 해마다 학년 묶음이 한 단계 올라가고 졸업생은 보관된다. 학생을 묶음에 넣으면 묶음 학년을 따르는 것이 기본이고, '학생 학년 유지'·'학년 없는 학생에게만 적용' 선택지가 있다. 상위 SIS가 사람을 공급하면 그쪽을 먼저 바꾼다. **사실 [25]**
- **학생 프로필**: 한눈에 보는 타일(Core·포트폴리오 갱신), 다가오는 과제, **6주 마감 부담 표시**. 출결 기능을 켠 학교에만 나오는 부분이 있다. **사실 [28]**

### 3.6 Toddle
- **설정 유형을 먼저 고른다**: 학교는 과목 기반·수업(course) 기반·IB 설정 중 하나로 구성되고, 과목 기반에서는 과목에 준 수준·학과가 연결된 수업으로 자동으로 내려간다. **사실 [30]**(검색 발췌, 비공식 미러) — 본 조사에서 가장 '템플릿'에 가까운 사례.
- **관리자 탐색 2층**: 위쪽 전환기에서 학교(공통 설정)와 프로그램(PYP 등)을 고르고, 학교 쪽은 '학교 기본(학교 정보·시간대·운영 요일·학년·학년도·평가 기간·생활·출결 설정) / 구성원 / 프로그램 구역 / 성적증명서 / 기타'로, 프로그램 쪽은 '프로그램 설정 / 명단 / 학사 설정 / 기타'로 나뉜다. 설정 검색창이 위에 있다. **사실 [29]**(원문)
- **새 학년도 마법사**: 학년 묶음 검토 → (선택) 수업 수준 → 과목–학과 연결 → 평가 기간 → 수업·반 만들기, 학년 묶음은 자동으로 한 단계 올라간다. **사실 [31]**(검색 발췌)
- **성적표**: 관리자가 '보고서 양식'(한 평가 기간 / 여러 평가 기간 2종)을 먼저 만들고, 그 위에 '보고서 묶음'을 만든다. 배치 패널에서 표지·인사말·서명·요약 등 구획을 켜고 끄며 **켠 구획만 교사에게 보인다**. 척도 구획은 설정된 척도를 자동으로 반영한다. 양식을 고치면 **잠기지 않은 묶음에만** 반영된다. AI가 인사말 초안을 돕는다. **사실 [32][33]**

### 3.7 Schoology
- 숙달(mastery) 척도는 교사가 아니라 **시스템(학군) 관리자가** 정하고 학군 목표에 맞춘 모든 자료에 적용된다. 표준 기반 성적부는 상위 목표 → 세부 목표로 내려가며 반 평균 숙달과 수준별 학생 분포를 본다. **사실 [34][35]**
- 성적부의 평가 기간 거르기는 기본값이 '현재 기간'이고, 기간 없음 항목은 성적부에 안 보인다. **사실 [36]**(검색 발췌, 정확한 출처 쪽 확인 필요)

### 3.8 Google Classroom
- **가장 단순한 프리셋**: 관리자가 조직 단위별로 기본 평가 기간·계산 방식(전체 성적 없음 / 총점 / 분류 가중)·분류·**척도 프리셋 3종(숙달·글자 성적·4점제) 또는 사용자 정의**를 정한다. 부모 단위 설정이 자식 단위로 내려가고, **새로 만드는 수업에만** 채워지며 교사가 고칠 수 있다. 유료판 기능이다. **사실 [39]**(원문)
- 과제는 마감일(없으면 게시일)로 평가 기간에 자동 분류되고, 범위 밖 과제는 손으로 넣는다. 기간은 겹칠 수 없고 해마다 손으로 갱신한다. 분류 가중은 합 100%여야 저장된다. **사실 [37][38]**
- SIS에서 학생·공동 교사·분류·평가 기간을 끌어올 수 있다. **사실 [40]**

### 3.9 나이스(NEIS, 4세대 포함)
- 2019년 계획 단계에서 출결 같은 간단한 정보는 모바일로 입력하게 하고, 필요한 정보만 넣으면 보고서·도표를 만들게 한다고 밝혔다. **사실 [51]**(2019 인터뷰, 구현 여부는 이 자료로 확인 불가)
- 2023년 6월 개통 뒤 교사 불만: 3세대에서는 출결을 한꺼번에 넣었는데 **학생 이름을 하나씩 눌러 들어가 입력**해야 하고, 내용 복사가 안 되며, 좌우 스크롤이라 일반 모니터 배율에 맞지 않는다는 지적. **사실 [49]**. 교원단체 설문에서 불만족 96.2%, 개통 시기 부적절 99.1%. **사실 [50]**(발췌, 설문 주체·문항은 원문 확인 필요)
- 결시생 인정 점수를 넣자 다른 과목 점수가 바뀐 오류, 인쇄 때 다른 학교 성적표가 나온 보도. **사실 [50][53]**. 교육부는 4세대로 옮긴 성적을 3세대 자료와 대조할 수 있게 조회 기능을 제공했다. **사실 [52]**
- 4세대 메뉴 구조·학교급 통합 화면은 원문을 못 찾았다. **확인 필요**

### 3.10 그 밖 (선택)
- **Arbor**: 출석부를 목록 보기(학생 옆 드롭다운)와 프로필 보기(한 명씩 크게, '건너뛰기')로 넣고, 결석을 고르면 사유 코드 창이 뜬다. 출석부 권한은 Arbor가 관리하는 업무 역할에 미리 배정돼 있다. **사실 [41][42]**

- **Skyward**: 좌석표 출결, 표준 성적부의 빠른 채점·일괄 점수 안내가 있다(세부 동작은 못 봄). **사실 [47][48]**(제목·발췌 수준)

### 5.2 설정이 단계로 나뉘는 방식 (공통 3층)

1. **틀**: 학교 정보·언어·시간대·학년도·학년·학기 (ManageBac [24], Toddle 학교 기본 [29]) — 다른 모든 것이 기댄다.
2. **평가 규칙**: 척도·환산 → 분류 → 성적 계획·평가 기간 → 계산식 → 과목 연결 (Blackbaud [19], Google [39])
3. **출력**: 성적표·증명서 양식 → 묶음(발행 단위) (Blackbaud 12단계 끝, Toddle 양식 → 묶음 [32])
- 그 위에 해마다 도는 **굴리기 마법사**(Toddle [31], IC [11])와 **사용 전 시험**(Alma [45])이 있다.

## 6. 우리 화면 설계 시사점 (모두 우리 판단)

### 6.1 템플릿 고르기 → 학교 사본 → 학교 AI 작업 흐름

```
[1 템플릿 고르기] → [2 미리 보기·비교] → [3 학교 사본 만들기] → [4 남은 설정 점검표] → [5 AI 맞춤(성적표 분석)] → [6 사람 확정] → [7 시험 학생으로 둘러보기]
```

1. **고르기**: 카드 5장(한국 일반 초·중·고 / 한국 대안(프로젝트·P/F) / 미국 K-12 / 국제(IB·AP 혼합) / 홈스쿨 공동체). 카드에는 이름보다 **'이 템플릿을 고르면 생기는 것'**을 적는다: 학교급·학년 범위, 학기 구조(2학기·4분기 등), 척도(성취도 A–E·P/F·글자 성적·IB 1–7), 출결 단위(하루/교시), 발행 기록(학생부·성적증명서·학업 기록), 석차 유무. (P8)
2. **미리 보기·비교**: 두 템플릿을 나란히 놓는 비교표. 학교가 '우리는 둘 사이'인 경우(국제학교의 IB+AP, 대안학교의 일부 과목 점수제)가 흔하므로 **가장 가까운 것을 고르고 나중에 고친다**는 안내를 둔다(ADR 0041 '가까운 견본 고르기'와 같은 말).
3. **학교 사본 만들기**: 확인 화면에 '승인하면 바뀌는 것 / 안 바뀌는 것 / 되돌릴 수 있는지'(AGENTS.md 설명 순서). 사본은 기본판 판을 가리키며, 이후 학교 화면 곳곳에 **'견본 그대로 / 학교가 바꿈'** 표시를 둔다(기본판 갱신 제안 때 학교 값 유지 규칙(ADR 0027)이 눈에 보이도록).
4. **남은 설정 점검표**: Blackbaud식 의존 순서(P6)를 쓰되, 템플릿이 채운 단계는 '완료(견본)'로 접어 두고 학교만 할 수 있는 단계(학년도 날짜, 수업일, 교직원 배정)만 펼친다. 각 단계는 앞 단계가 안 끝나면 잠김 + 이유 한 줄.
5. **AI 맞춤**: 학교 AI(범위 토큰)가 성적표·규정을 분석해 **새 판 초안**을 쓴다. 화면은 초안을 '변경 묶음'으로 보여 준다: 무엇이(척도 경계·칸 켜기) / 왜(규정 조항, '왜' 칸) / 미리 계산 결과(시험 학생 점수로 전후 등급 비교). 결과가 학교 성적표와 다르면 질문으로 연다(지침 6).
6. **사람 확정**: 묶음 단위 확정 + 항목별 되돌리기. 확정 버튼 문구는 결과를 그대로('척도 판 2건 확정').
7. **둘러보기**: 아래 6.3.

### 6.2 학교급·학년 체계 화면

- **나무 한 장**: 학교 → 학교급(초·중·고, 또는 PYP·MYP·DP, 또는 '하나의 무학년 과정') → 학년 서수 → 학년 묶음(반). 학교급마다 다른 학기 나무·척도를 걸 수 있음을 줄마다 보여 준다(ManageBac 프로그램별 학기 [24], Gradelink 학년별 척도 [44], Blackbaud 학교급별 성적 묶음 [19]).
- **무학년·혼합 연령**을 1급 선택지로 둔다(대안학교·홈스쿨). 템플릿에 따라 기본값만 다르고 화면은 같다.
- **학년 넘기기 규칙**을 이 화면에 미리 적는다: 해마다 한 칸 올림, 졸업 학년 다음은 보관, 예외(유급·월반) 처리. ManageBac의 '묶음 학년 따름 / 학생 학년 유지' 선택지 [25]처럼 기본과 예외를 명시.
- 이름표(1학년·Grade 1·Year 2·ม.1)는 표시용이며 서수 id로 묶는다(지침 7). 가져오기 자료와 이름표가 안 맞으면 대응표를 보여 준다(ManageBac 일치 요구 [24]의 함정 회피).

### 6.3 일상 화면 요점

- **성적 입력부**: 수업 × 평가 항목 격자. 화살표·Enter 이동, '빈 칸만 채우기'(P4), 예외 표시(결시·인정점) 단축키. 대안학교 템플릿은 같은 격자에 P/F·서술 칸, 표준 기반은 목표별 열 묶음(Schoology·PowerSchool 표준 보기 [3][34]). 4세대 나이스 결시 인정점 오류 [50] 같은 '한 칸 입력이 다른 과목을 바꾸는' 일이 없도록 저장 전 **바뀔 칸 미리 보기**.
- **출결 입력**: 기본 출석으로 열고 예외만(P3), 보기 전환 목록/좌석표/한 명씩(P5), 하루·교시 단위는 템플릿이 정함. **한 화면에서 반 전체를 저장**(나이스 실패 [49]의 반대). 휴대폰 폭에서 목록 보기가 기본.
- **학기 마감**: 진행 표(수업별 입력률·검토 상태) → 미입력·질문 목록 → 마감(판 확정) → 발행. 잠금 해제 버튼은 없고 '정정 새 판'만(P11).
- **기록 발행**: 출력 프로필을 고르면 미리 보기(스냅샷)와 누락 질문이 나란히. 켠 구획만 입력·출력에 보임(P10). 인쇄·내려받기는 학교 경계 시험을 거친 경로만(나이스 '다른 학교 성적표' 보도 [53]).
- **학생 한 명 보기**: 고정 머리 띠(이름·학년·재적 상태·주의 알림) + 탭(요약 / 수업·성적 / 출결 / 기록·발행본 / 가족). 요약 탭은 '지금 필요한 것'(결석 경고·미제출·열린 질문). 역할마다 탭이 다르게 보임(Blackbaud [20]). 다만 타일 끌어 놓기 같은 개인 배치는 처음엔 두지 않는다(유지 비용 대비 이득 불명).

### 6.4 시연 학교 '둘러보기' 순서 (예시학교, 합성 자료)

1. **관리자: 템플릿 고르기** — '한국 일반 고' 카드와 '미국 K-12' 카드를 비교해 고름 → 사본 생성 확인 화면.
2. **관리자: 학교급·학년 나무** — 견본 표시와 학교가 바꾼 표시가 섞인 상태를 보여 줌.
3. **관리자: 남은 설정 점검표** — 학년도 날짜 하나만 넣으면 끝나는 상태.
4. **AI 작업 공간: 맞춤 초안** — 합성 성적표에서 뽑은 척도 변경 묶음, 전후 미리 계산, 확정.
5. **교사: 오늘 수업 → 출결** — 기본 출석, 두 명만 예외, 저장.
6. **교사: 성적 입력부** — 예외 두 칸 → 빈 칸 채우기 → 저장 전 미리 보기.
7. **관리자: 학기 마감** — 입력률 표 → 질문 1건 해결 → 마감 판.
8. **관리자: 기록 발행** — 학생부 출력 프로필 미리 보기 → 발행본.
9. **학생 한 명 보기** — 마감·발행 결과가 학생 화면에 모이는 것 확인. 이어 `/my`에서 보호자가 보는 모습.
- 같은 순서를 '한국 대안(P/F)' 템플릿으로 한 번 더 돌려 **같은 화면이 템플릿에 따라 구획만 달라지는 것**을 보여 주면 플랫폼의 요점(공용 DB + 설정값 맞춤, ADR 0035)이 잘 드러난다.

## 7. 피할 것

1. **일괄 경로 없애기**: 학생 한 명씩 열어 입력, 복사 불가, 좌우 스크롤 격자(4세대 나이스 [49]).
2. **채우기 규칙 숨기기**: 같은 '채우기'가 어떤 제품은 빈 칸만, 어떤 제품은 덮어씀 [1][9]. 미리 보기 없이 덮어쓰지 않는다.
3. **잠금 구멍**: 검토·잠금된 성적을 새 화면이 다시 바꾸게 하는 것 [22]. 잠금 해제 대신 정정 판.
4. **발행본을 '살아 있는 자료'로**: Blackbaud 사용자들이 진짜 사본을 PDF로 따로 보관한다는 보고(기존 REA). 우리 발행 스냅샷 원칙 유지.
5. **설정 순서를 문서에만 두기**: 의존 순서를 도움말에 '차례로 읽으라'고만 적고 화면이 막지 않으면 잘못된 순서로 만든 설정이 남는다 [19] — **추정**.
6. **이름 일치에 기대는 복사·가져오기**: 이름표가 일치해야 복사·가져오기가 되는 구조 [12][24]. id·대응표로 대신한다.
7. **'아무도 안 봤는데 출석'**: 기본 출석은 편하지만 저장 여부를 구분하지 않으면 미입력이 출석으로 남는다 — **추정**.
8. **학기 중 전면 교체**: 4세대 나이스 개통 시기 부적절 99.1% [50]. 새 템플릿·화면 전환은 학년도 경계에서, 옛 자료 대조 화면과 함께 [52].
9. **화면 디자인 복제**: 공급사 화면을 베끼지 않는다(이 문서도 구조 원리만 뽑음).
