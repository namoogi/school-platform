# 학교 운영 플랫폼 UI/UX 신속 근거 평가(REA) 보고서

- 검색·작성일: 2026-11-22
- 대상 제품: 다학교(멀티테넌트) 학교 운영 플랫폼 (Next.js, 한국어 우선·영어·태국어 학교 지원)
- 목적: “조잡하다”는 현재 UI(남색 좌측 사이드바 + 카드 + 기본 표)를 복잡하고 체계적인 업무 서비스에 맞는 디자인 기반으로 바꾸기 위한 근거와 명세 초안 마련
- 출처 번호 표기: 본문의 [S1]~[S29]는 「3. 출처 표」의 번호다.

## 1. 요약 (핵심 권고 12개)

1. **앱 셸을 “상단 전역 막대 + 그룹형 좌측 탐색 + 본문(+선택적 보조 패널)” 3구역으로 재구성한다.** 상단에는 학교 전환·검색·알림·도움말·계정처럼 모든 화면에 공통인 전역 항목만 두고, 모듈별 메뉴는 좌측 탐색에 둔다. 좌측 탐색은 제목이 붙은 구역(섹션)으로 묶고 접을 수 있게 한다. [S2][S15][S16][S14][S24]
2. **학교 전환기(테넌트 스위처)는 상단 막대 왼쪽, 제품 로고 옆에 고정하고, 현재 학교 이름을 항상 보이게 한다.** 플랫폼 관리자 영역은 학교 영역과 다른 진입점·다른 색 띠로 구분한다. 상위 계정의 권한은 하위로만 흐르고, 하위 관리자에게는 상위 전용 메뉴가 아예 보이지 않게 한다. [S15][S2][S25][S26]
3. **역할에 따라 메뉴 자체를 숨기고, 보이지만 바꿀 수 없는 정보는 “읽기 전용” 상태로 보여 준다.** 비활성(disabled)과 읽기 전용을 구분하고, 권한 때문에 읽기 전용이면 이유를 적는다. [S6][S26]
4. **표는 하나의 표준 데이터 표 컴포넌트로 통일한다.** 제목·도구 막대(검색·필터·표 설정, 동작은 최대 5개, 나머지는 더보기 메뉴)·선택 시 나타나는 일괄 작업 막대·정렬 가능한 열 머리글·페이지 나눔을 기본으로 둔다. 숫자는 오른쪽 정렬과 고정폭 숫자(tabular-nums), 로딩은 스켈레톤, 빈 칸은 그냥 비워 둔다. [S1][S9][S13][S21]
5. **밀도는 행 높이 3단계(촘촘 32px / 기본 40px / 넉넉 48px)로 두고, 머리글 행 높이를 본문 행에 맞춘다.** 관리 화면은 기본적으로 고밀도로 하되 구획선과 면 색으로 구역을 나눈다. [S1][S9][S13]
6. **많이 쓰는 목록(자료, 증거 행, 학교, 구성원, 접근 기록)에는 “저장된 보기” 탭을 둔다.** 검색어·필터·정렬 조합을 이름 붙여 저장하고, 필터마다 한 번에 지우기를 둔다. 필터가 많거나 응답이 느리면 “필터 적용” 버튼으로 한꺼번에 반영한다. [S13][S6]
7. **상태 표시는 “색 + 글자(+아이콘/모양)”를 함께 쓰는 의미색 체계로 통일한다.** 상태 이름은 동사가 아닌 형용사·명사로 쓰고 클릭할 수 있게 만들지 않는다. 한 화면의 상태 종류는 적게 시작하며, 여러 상태를 합칠 때는 가장 주의가 필요한 색을 쓴다. [S4][S12][S9][S16][S19]
8. **검토·확정 흐름은 “확인 후 확정” 패턴으로 만든다.** 확정 전에 요약 목록(키–값 + 행마다 “변경” 링크)과 근거 목록을 함께 보여 주고, 확정 버튼 문구는 결과 동작을 그대로 적는다(예: “규칙 3건 확정”). 되돌릴 수 없는 동작은 결과를 설명하는 위험(danger) 대화상자로 한 번 더 확인한다. [S11][S6][S8]
9. **변경 불가 기록(확정 규칙·양식·발행본·원본 행)은 수정 버튼 대신 “새 버전 만들기”와 버전 이력(타임라인)으로 표현한다.** 이력에는 누가·언제·무엇을(이전 값 → 새 값) 바꿨는지와 사유를 남긴다. 학교 현장의 정정 관행(마감 후 원칙적 정정 금지, 증빙·심의·정정대장 결재)과 맞물리도록 “정정 요청 → 심의 → 새 판 발행” 흐름을 준비한다. [S9][S14][S25][S28][S29]
10. **피드백은 위치 기반으로 고른다.** 필드 오류는 필드 옆 인라인 메시지와 페이지 상단 오류 요약(포커스 이동, 각 오류로 연결) 둘 다, 페이지 단위 결과는 본문 상단 배너, 화면 밖 결과만 짧은 토스트로 알린다. 토스트는 접근성 문제가 보고된 사례가 있으므로 핵심 정보를 토스트에만 담지 않고 `role="status"` 등으로 보조기기에 알린다. [S10][S5][S8][S19]
11. **시각 기반은 의미 토큰(semantic token) 3층 구조로 만든다.** 원시 색(gray/brand/상태 색 단계) → 의미 토큰(text/surface/border/status) → 컴포넌트 토큰. 간격은 4px 단위(2·4·8·12·16·24·32·48·64), 반경 4·6·8, 그림자는 2겹 공식 3단계, 서체는 한국어 Pretendard 계열과 `word-break: keep-all`, 라이트·다크·고대비 테마를 같은 의미 토큰으로 바꾼다. [S3][S17][S18][S9][S27]
12. **접근성 기준선은 WCAG 2.2 AA(국내는 KWCAG 2.2 대응 확인 필요)로 둔다.** 본문 대비 4.5:1, 입력란 테두리·포커스 표시 3:1, 클릭 대상 24×24px 이상, 고정 머리글이 포커스를 가리지 않게, 끌기 동작에는 대안, 같은 과정에서 입력한 값 재입력 금지. [S19][S20][S18]

## 2. 방법

### 2.1 검토 질문

| 번호 | 질문 |
|---|---|
| Q1 | 다모듈·멀티테넌트 관리 제품의 정보 구조와 탐색(사이드바 묶음, 학교 전환, 경로 표시, 명령 팔레트·검색, 역할별 메뉴) |
| Q2 | 고밀도 화면: 표(정렬·필터·저장된 보기·일괄 작업·밀도), 대시보드·요약 지표, 상태 배지 |
| Q3 | 검토·승인·감사 흐름: 근거 표시, 확정·수정 흐름, 버전·이력, 변경 불가 기록, 감사 로그 |
| Q4 | 양식·설정·결제/라이선스 화면, 빈 상태·오류·로딩, 피드백(토스트·인라인 검증) |
| Q5 | 시각 기반: 디자인 토큰(색·글자 크기·간격·반경·그림자), 밀도 모드, 다크 모드, 한국어 타이포그래피, 접근성(WCAG 2.2, KWCAG) |

### 2.2 검색 전략

- 웹 검색어(예): `Carbon design system data table row height sizes batch actions toolbar`, `KRDS 범정부 UI/UX 디자인 시스템 타이포그래피 Pretendard 색상 토큰`, `Atlassian design system navigation sidebar app switcher lozenge`, `Nielsen Norman Group enterprise applications complex apps`, `Fluent 2 design system type ramp spacing ramp shadow elevation tokens`, `PowerSchool SIS school picker ... start page`, `Infinite Campus new look navigation search "Campus Tools"`, `Canvas LMS admin sub-accounts ...`, `Instructure UI design system InstUI tokens`, `한국형 웹 콘텐츠 접근성 지침 KWCAG 2.2`, `nngroup data tables four common user tasks`, `nngroup dashboards preattentive`, `PowerSchool SIS "change history" audit`, `ManageBac report cards publish ...`, `학교생활기록부 정정 대장 마감 후 수정 절차`, `Veracross school switcher multi-school`.
- 원문 열람 방식: 이 세션의 네트워크 정책상 대부분의 디자인 시스템 웹사이트(carbondesignsystem.com, primer.style, atlassian.design, design-system.service.gov.uk, krds.go.kr, nngroup.com, w3.org, 각 학교 제품 도움말)는 직접 열 수 없었다. 대신 **각 디자인 시스템의 공식 문서 원본 저장소(GitHub)와 공식 npm 패키지를 직접 받아 원문을 읽었다.** 사이트 문서가 이 원본에서 만들어지므로 1차 자료로 취급했다. 열람한 저장소 커밋 날짜·패키지 버전은 출처 표에 적었다.
- NN/g 글과 학교 제품(PowerSchool, Infinite Campus, Canvas, ManageBac, Veracross) 자료는 **검색 결과 요약·발췌만** 확인했다. 이 자료는 근거 강도를 한 단계 낮춰 평가했고, 세부 내용은 「확인 필요」에 올렸다.

### 2.3 포함·제외 기준

- 포함: 공식 디자인 시스템 문서(원본 저장소·패키지 포함), 공급사 공식 도움말·지식 베이스, 표준 문서(WCAG), 인정된 UX 연구 기관(NN/g), 정부 공식 안내(교육부 학교생활기록부 지원 누리집).
- 제외: 출처 없는 블로그 목록 글, 마케팅 페이지, 제3자 요약 사이트(검색에 나온 oppadu, skills.sh, KolFluent 등은 값 확인용 단서로만 보고 근거로 쓰지 않음).
- 검색 결과가 다른 제품(QuickSchools, Aspen, Gibbs Smith 등)을 보여 준 경우는 근거에서 제외했다.

### 2.4 평가 방식

- 관련도: 상(이 제품 화면에 바로 적용) / 중(원칙 수준으로 적용) / 하(참고).
- 근거 유형: 공식 지침 / 연구 / 제품 관찰(공급사 도움말에서 기능 존재 확인).
- “수렴 패턴”은 강한 출처(공식 지침 또는 연구) 2개 이상에서 같은 방향이 확인된 경우로 정의했다.

### 2.5 한계

- 신속 평가라 체계적 문헌 고찰 수준의 전수 검색·이중 평가는 하지 않았다. 평가자 1인.
- 웹사이트 직접 열람이 막혀 Carbon·Primer·GOV.UK·Polaris·SLDS·KRDS·WCAG는 원본 저장소로, Atlassian·Fluent는 npm 패키지 문서·코드로 확인했다. 사이트에만 있고 저장소에 없는 내용(예: Atlassian 내부 전용 지침, 그림 속 수치)은 확인하지 못했다.
- Primer 문서 저장소(primer/design)의 최신 커밋은 2025-07-01로, 이후 사이트 변경이 반영되지 않았을 수 있다. Shopify Polaris React는 2025-10-01부로 지원 중단(웹 컴포넌트로 이전)이라고 저장소 README에 적혀 있어, 패턴 근거로만 쓰고 구현 라이브러리로는 권하지 않는다.
- NN/g 원문, 학교 제품 도움말 원문, KWCAG 2.2 원문은 직접 읽지 못했다.
- 사용자 조사(이 제품 실제 사용자 대상)는 범위 밖이다. 권고 수치(글자 크기, 행 높이 기본값 등)는 출처의 값을 바탕으로 한 **제안**이며 사용자 시험으로 검증해야 한다.

## 4. 질문별 종합

### Q1. 정보 구조와 탐색

**수렴 패턴 (강한 출처 2개 이상)**

- **상단 = 전역, 좌측 = 제품/모듈.** Atlassian은 상단 탐색을 “앱 간 전역 동작 전용”으로 두고 앱별 주 메뉴를 좌측 탐색으로 옮겼다 [S15]. Carbon도 머리글은 왼쪽(제품)에서 오른쪽(전역)으로 갈수록 범위가 넓어지고 좌측 패널이 더 깊은 탐색을 맡는다 [S2]. Salesforce는 앱 런처 + 앱 이름 + 앱 내 항목을 한 줄로 묶는다 [S14].
- **좌측 탐색은 제목이 있는 구역으로 묶고 펼침/접힘을 지원.** Atlassian MenuSection(제목+구분선)·펼침 항목 [S16], Carbon 좌측 패널 하위 메뉴 펼침 [S2], SLDS 세로 탐색의 접힘·펼침·compact 상태와 `aria-current` [S14], Infinite Campus의 범주→메뉴→도구 묶음 [S24].
- **현재 위치를 항상 알 수 있게.** Primer는 사용자가 지금 어디 있는지 늘 알 수 있어야 하고, 자식 페이지에는 경로 표시나 뒤로 가기를 두라고 한다 [S7]. PowerSchool 시작 페이지도 경로 표시를 탐색 막대에 둔다 [S25].
- **상위–하위 계정 구조와 권한의 단방향 상속.** Canvas는 권한이 상위에서 하위로만 흐르고 일부 메뉴가 하위 계정에 아예 나타나지 않는다 [S26]. PowerSchool은 학교·학기 메뉴로 범위를 바꾼다 [S25]. (둘 다 제품 관찰, 검색 발췌 수준.)

**갈리는 선택**

- 학교(테넌트) 전환 위치: Atlassian은 앱 전환기를 상단 시작 영역(로고 옆)에 둔다 [S15]. Carbon은 스위처를 머리글 가장 오른쪽(가장 전역)에 둔다 [S2]. PowerSchool은 탐색 막대의 학교 메뉴 [S25].
- 검색: Infinite Campus는 통합 검색에 “도구 검색” 모드를 넣어 메뉴 찾기를 검색으로 해결한다 [S24]. Atlassian은 검색을 상단 가운데에 둔다 [S15]. **명령 팔레트(⌘K)** 에 대한 강한 1차 지침은 이번 검색에서 찾지 못했다(확인 필요).
- 보조 패널: Atlassian은 맥락 정보를 위한 크기 조절·접기 가능한 패널을 본문 옆에 두고, 집중 작업은 모달로 분리한다 [S15].

**이 제품 권고**

- 셸: 상단 막대(왼쪽부터: 좌측 탐색 접기 버튼 → 제품 로고 → **학교 전환기**, 가운데: 전역 검색, 오른쪽: 도움말·알림·계정). 학교 전환기를 로고 옆에 두는 이유는, 이 제품에서 학교는 “전역 동작”이 아니라 **모든 화면의 데이터 범위를 정하는 맥락**이라 늘 눈에 보여야 하기 때문이다(Atlassian 방식 채택, Carbon 방식은 기각).
- 좌측 탐색 구역 예시:
  - **업무**: 자료 접수, 검토 대기(건수 배지), 문서실
  - **학교 관리**: 학교 설정(라이선스·모듈), 구성원·초대, 결제 기록, 접근 기록
  - **플랫폼 관리**(플랫폼 관리자에게만 보임): 학교 목록, 학교 만들기, 가격표, 명세서
  - **개발·실험**(권한자만): 계획, 도구, 방법, 실험, 할 일
- 플랫폼 관리 영역은 학교 영역과 다른 맥락이다. 상단 막대에 “플랫폼 관리” 표시(색 띠 또는 라벨)를 두어 학교 데이터를 보고 있는지 플랫폼 데이터를 보고 있는지 헷갈리지 않게 한다. 학교 ID는 클라이언트 값이 아니라 로그인 사용자의 소속에서 정하는 기존 규칙과 맞물린다. 전환기는 사용자가 소속된 학교만 보여 준다.
- 권한이 없는 메뉴는 숨긴다(Canvas 방식). 단, 볼 수는 있지만 바꿀 수 없는 화면은 숨기지 않고 읽기 전용으로 보여 준다(Q3·Q4 참고).
- 경로 표시는 2단계 이상 깊이(예: 문서실 › 학기말 보고서 › 3판)에서만 쓴다. 최상위 화면은 페이지 제목만으로 충분하다.
- 1차 검색은 “메뉴·화면 찾기 + 학교/구성원/문서 찾기”를 한 입력란에서 처리하는 통합 검색으로 시작하고, 키보드 단축키(예: `/` 또는 `Ctrl+K`)는 단축키 표시가 있는 버튼으로 노출한다 [S15]. 명령 팔레트는 시범 적용 후 결정한다.

### Q2. 고밀도 화면: 표, 대시보드, 상태 배지

**수렴 패턴**

- **표 구성 요소의 표준 해부도**: 제목(필수)·도구 막대(검색·필터·표 설정)·정렬 가능한 머리글·선택 열·행 동작·페이지 나눔 [S1][S9][S13].
- **선택하면 나타나는 일괄 작업 막대.** Carbon은 선택 시 표 위에 일괄 작업 막대가 나타나고 그동안 행 단위 동작을 비활성화하며 취소나 전체 해제로 빠져나온다 [S1]. Polaris 인덱스 표도 일괄 작업을 기본 변형으로 둔다 [S13].
- **밀도 단계.** Carbon 24/32/40/48/64px [S1], Primer condensed/normal/spacious [S9], Polaris는 관리자 화면을 기본 고밀도로 두고 구획선·면 색으로 구역을 나눈다 [S13].
- **필터와 저장된 보기.** Polaris는 저장된 보기를 탭으로 만들고(만들기·이름 바꾸기·복제·삭제) 검색·필터·정렬을 결합한다 [S13]. Carbon은 일괄 적용 필터(“필터 적용” 버튼, 느린 응답에 적합)와 즉시 적용 필터를 구분하고 전체 지우기를 요구한다 [S6].
- **셀 표기 규칙.** 숫자 오른쪽 정렬+고정폭 숫자, 빈 셀은 기호 없이 비움, 스켈레톤 로딩, 큰 데이터는 페이지 나눔 [S9].
- **표가 지원할 과업**: 찾기·비교·한 행 보기/편집·동작 실행 [S21]. 카드 나열은 비교에 불리하다는 NN/g 발췌는 현재 “카드 위주” 화면을 표로 바꿀 근거가 된다.
- **상태 표시: 색 + 글자(+모양).** Carbon 아이콘 지시자는 아이콘·모양·의미색·라벨을 함께 쓴다 [S4]. GOV.UK 태그는 색만으로 전달하지 말라고 하고 WCAG 1.4.1을 근거로 든다 [S12][S19]. Primer·Polaris·Atlassian·KRDS 모두 success/warning(attention)/danger(critical)/info/neutral 계열의 의미색 역할을 둔다 [S9][S13][S16][S18].
- **상태는 적게, 클릭 불가로.** GOV.UK는 태그를 링크·버튼으로 만들지 말고 형용사로 쓰며 상태 수를 최소로 시작하라고 한다 [S12]. Carbon은 행동이 필요 없으면 일반 글자로 쓰고 지시자가 5~6개를 넘으면 부담이 된다고 한다 [S4].

**갈리는 선택**

- 줄무늬: Carbon은 선택 옵션으로 제공 [S1]. Polaris는 구획선과 면 색으로 구분 [S13]. → 기본은 행 구분선, 넓은 표만 줄무늬 옵션.
- 상태 배지 모양: GOV.UK는 2026년 갱신에서 연한 배경+진한 글자로 바꿔 버튼 오인을 줄였다 [S12]. Primer는 진한(emphasis)·연한(muted) 두 강도를 모두 둔다 [S9]. → 표 안 상태는 연한 배경, 강조가 필요한 단일 상태만 진한 배경.
- 대시보드: NN/g는 대시보드를 빠른 확인용으로 보고 양은 길이·위치로 표현하라고 한다 [S22]. Carbon은 차이(증감) 지시자에 +/− 기호나 화살표를 필수로 둔다 [S4].

**이 제품 권고**

- `DataTable` 하나로 학교 목록, 구성원, 결제 기록, 접근 기록, 증거 행, 자료 목록을 모두 그린다. 화면마다 따로 만든 표를 없앤다.
- 밀도 3단계: **촘촘 32px / 기본 40px / 넉넉 48px** (Carbon sm/md/lg 값 차용). 접근 기록·증거 행처럼 행이 많은 표는 촘촘을 기본값으로, 학교 목록·구성원은 기본. 사용자 선택은 표 설정 메뉴에서 바꾸고 사용자별로 기억한다.
- 저장된 보기 예시: 검토 대기 “내게 배정됨 / 충돌 있음 / 오늘 들어옴”, 접근 기록 “실패한 로그인 / 관리자 동작 / 최근 7일”.
- 개요 화면(학교 홈, 플랫폼 홈)은 “지금 처리할 일” 중심의 운영형 대시보드로 만든다: 검토 대기 건수, 충돌 질문 수, 남은 좌석/전체 좌석(막대), 이번 달 예상 청구액. 원형·면적 차트는 피한다 [S22]. 증감에는 기호를 붙인다 [S4].
- 숫자(좌석 수, 금액, 건수)는 오른쪽 정렬+`font-variant-numeric: tabular-nums` [S9].

### Q3. 검토·승인·감사 흐름

**수렴 패턴**

- **제출 전 확인(Check answers) + 키–값 요약.** GOV.UK는 확인 페이지가 사용자 확신을 높이고 오류를 줄인다고 하며, 요약 목록 행마다 “변경” 링크와 화면낭독기용 숨김 문구, 결과를 말하는 제출 버튼을 요구한다 [S11]. Primer는 위험한 제출 전 확인과 동사+대상 버튼 문구를 요구한다 [S8]. Carbon은 되돌릴 수 없는 결정에 결과를 설명하는 위험 모달을 쓴다 [S6].
- **이력은 세로 타임라인.** Primer Timeline은 항목의 이력과 활동을 연결된 세로선으로 보여 주고 각 항목 안에 상태를 글로 적으라고 한다 [S9]. SLDS 활동 타임라인은 과거·현재·예정 활동과 펼침 상세(aria-controls, aria-expanded)를 정의한다 [S14].
- **읽기 전용 상태.** Carbon은 처리 중·잠김·권한 세 경우에 읽기 전용을 쓰고, 읽기 전용 데이터는 비활성과 달리 “살아 있는 값”으로 취급한다 [S6].
- **학교 현장의 잠금·발행 관행.** ManageBac은 교사 입력 → 관리자 검토 → 성적부 잠금 → 초안 미리보기 → 예약 공개·알림 → 발행, 초안은 이력에 보관한다 [S28]. 교육부 안내는 마감 후 정정을 원칙적으로 막고, 예외는 증빙 → 학업성적관리위원회 심의 → 정정대장 결재를 거친다 [S29]. PowerSchool 변경 이력은 이전·이후 값을 보여 주지만 일부 필드만 기록하고 보관 기간이 제한된다(지역 안내서·커뮤니티 답변 기준) [S25].

**갈리는 선택**

- 단계 표시: SLDS Path처럼 진행 단계를 가로 막대로 보여 주는 방식 [S14] vs GOV.UK처럼 확인 페이지 하나로 마무리하는 방식 [S11]. → 자료 접수→검토→확정→발행처럼 단계가 정해진 흐름에는 Path형 단계 표시를, 한 화면 안의 확정 동작에는 확인 요약을 쓴다.
- 감사 범위: PowerSchool은 선택된 필드만 기록한다 [S25]. 이 제품은 DB 트리거로 변경 불가 표를 보호하므로, 모든 확정·발행·권한 변경을 기록하는 쪽이 맞다.

**이 제품 권고**

- **관리자 검토 화면 = 3열 분할**: 왼쪽 “검토 대기 목록(표, 상태 필터)”, 가운데 “추론된 규칙(키–값 요약 + 수정 가능한 필드)”, 오른쪽 “근거 목록(Evidence list: 원본 파일명·행 번호·발췌·신뢰도 배지·원본 열기)”. 화면이 좁으면 근거 목록은 보조 패널로 접는다 [S15].
- **확정 버튼 문구**: “확정” 대신 “규칙 3건 확정”, “2학기 보고서 2판 발행”처럼 대상과 수를 적는다 [S8][S11]. 확정은 변경 불가 기록을 만드는 동작이므로 위험 모달이 아닌 **주 버튼 + 확인 요약**으로, 삭제·권한 회수·좌석 축소처럼 손실이 생기는 동작만 위험 모달로 처리한다 [S6].
- **충돌 질문**: 새 자료가 확정 규칙과 다르면 `주의(warning)` 상태의 인라인 알림으로 “확정 규칙과 다름 — 질문 열림”을 보여 주고, 기존 규칙과 새 값을 나란히 비교하는 표를 제공한다. 자동으로 덮어쓰지 않는다는 데이터 경계 규칙을 화면에서 드러낸다.
- **변경 불가 기록 표현**: 발행본·확정 규칙·양식 화면에는 편집 버튼을 두지 않는다. 대신 상단에 “확정됨 · 3판 · 2026-11-20 김OO” 메타 정보와 “새 판 만들기”, “판 이력”을 둔다. 읽기 전용 필드는 입력란 모양을 버리고 글자로 보여 준다 [S6].
- **판 이력·감사 로그 = Timeline 컴포넌트**: 항목마다 행위자, 시각(절대 시각+상대 시각), 동작(만듦/확정/발행/새 판/정정 요청), 대상, 이전 → 새 값 요약, 사유. 상세는 펼침 [S9][S14].
- **정정 흐름(설계만, 구현은 결정 대기)**: 발행본에 “정정 요청” → 사유·증빙 첨부 → 승인자 검토 → 새 판 발행, 이전 판은 “대체됨(superseded)” 상태로 남긴다 [S29][S28]. 실제 결재 단계·권한은 학교별 규정이 달라 확인이 필요하다.

### Q4. 양식·설정·결제/라이선스, 빈·오류·로딩 상태, 피드백

**수렴 패턴**

- **검증 오류는 두 곳에.** GOV.UK는 오류가 하나라도 상단 오류 요약과 필드 옆 오류 메시지를 함께 보여 주고, 요약으로 포커스를 옮기며 각 필드로 연결한다 [S10]. Primer도 필드 검증은 인라인 메시지, 여러 필드 오류는 배너와 함께 쓴다 [S8]. Carbon도 양식의 인라인 알림을 위나 아래에 둔다 [S5].
- **입력값 보존.** 저장 실패·검증 실패 시 사용자가 입력한 값을 유지한다 [S8][S10]. WCAG 3.3.7은 같은 과정의 재입력을 막는다 [S19].
- **저장 방식을 섞지 않음.** 한 양식 안에서 자동 저장과 명시 저장을 섞지 않는다 [S8].
- **설정 화면 2열.** Polaris는 왼쪽에 설정 묶음의 제목·설명, 오른쪽에 카드로 묶은 설정을 둔다 [S13]. GOV.UK 요약 카드는 같은 종류의 여러 묶음에 제목과 카드 단위 동작을 붙인다 [S11].
- **빈 상태.** Carbon은 제목·다음 행동 설명·주 버튼(선택)·보조 동작으로 구성하고, 첫 사용·사용자 동작 결과·오류를 구분한다 [S6]. Polaris 인덱스 표도 자원이 없을 때 목적을 설명하는 빈 상태를 둔다 [S13].
- **피드백의 위치 원칙.** 관련 항목 근처(인라인) → 페이지·구역 상단(배너) → 화면 밖(토스트) 순으로 방해 정도가 커진다 [S5][S8].
- **권한·자격 판정은 검증 메시지로 하지 않는다.** GOV.UK는 자격·권한 문제를 오류 메시지가 아니라 별도 안내 페이지로 처리하라고 한다 [S10].

**갈리는 선택**

- **토스트**: Carbon은 토스트를 정식 컴포넌트로 두고 쌓임·고정 폭·버튼 1개 규칙을 준다 [S5]. Primer는 github.com의 토스트에 접근성 문제가 있다며 사용을 자제시키고 토스트 컴포넌트를 비권장으로 돌렸다 [S8]. → 이 제품은 토스트를 “화면 안에서 결과가 보이지 않는 짧은 성공 알림”에만 쓰고, 오류·행동이 필요한 알림은 인라인/배너로 보낸다. 토스트를 쓸 때는 `role="status"`(WCAG 4.1.3) [S19], 자동 사라짐 시간 충분히, 마우스 올림·포커스 시 멈춤을 적용한다.

**이 제품 권고**

- **학교 설정**: 탭(라이선스·모듈 / 구성원·초대 / 결제 기록 / 접근 기록)으로 나누고, 각 탭은 2열 설정 레이아웃(왼쪽 설명, 오른쪽 카드) [S13]. 탭은 URL을 바꾸는 방식으로 통일한다 [S7].
- **라이선스·좌석 카드**: “사용 중 42 / 50석” 막대 + 남은 좌석, 모듈 목록(사용 중/꺼짐 상태 배지), “좌석 변경” 동작. 좌석 축소처럼 사용자에게 영향이 있는 변경은 영향받는 구성원 수를 보여 주는 확인 대화상자로 [S6].
- **결제 예상·명세서**: 금액은 오른쪽 정렬·통화 단위 고정, “예상”과 “확정” 상태를 배지와 글자로 구분한다. 결제·외부 발송처럼 되돌리기 어려운 동작은 기존 지침대로 대상과 영향을 확인한 뒤 실행하고, 그 확인 화면을 확인 요약 패턴으로 만든다 [S11].
- **초대 양식**: 이메일 여러 개 입력 → 미리보기 표(유효/중복/이미 소속 상태) → “구성원 5명 초대”. 오류는 행 단위 인라인 + 상단 요약 [S10].
- **빈 상태 3종**: 첫 사용(“아직 올린 자료가 없습니다” + “자료 올리기”), 필터 결과 없음(“조건에 맞는 기록이 없습니다” + “필터 지우기”), 권한 없음(별도 안내: 누구에게 요청하면 되는지) [S6][S10].
- **로딩**: 표·카드는 실제 모양과 비슷한 스켈레톤 [S9], 버튼 동작 중에는 버튼 안 회전 표시+중복 클릭 방지, 오래 걸리는 처리(자료 분석)는 진행 상태를 상태 배지(처리 중)와 함께 목록에 남긴다.
- **페이지 이동 시 저장 안 된 변경 경고**를 편집 화면에 적용한다 [S7][S8].

### Q5. 시각 기반

**수렴 패턴**

- **4px 기반 간격 척도.** Carbon 2·4·8·12·16·24·32·40·48·64… [S3], Fluent 2·4·6·8·10·12·16·20·24·32 [S17], KRDS 2·4·8·12·16·20·24·32·40·48… (rem, 1rem=10px) [S18]. 셋 다 2px 미세 단계 + 4/8 중심.
- **의미 토큰 층.** Primer는 accent/success/attention/danger/done 등 역할 색과 진함/연함 두 강도 [S9], KRDS는 `text/surface/border × danger/warning/success/information/primary` 의미 토큰과 원시 색 단계(5~95)를 분리 [S18], Carbon은 회색 중심 테마와 층 모델 [S3], InstUI는 원시값 → 테마 대비 → UI 토큰 구조와 고대비 테마를 둔다(2차 확인) [S27].
- **테마 전환은 같은 의미 토큰의 값만 바꾼다.** Carbon 라이트/다크 테마와 층 모델 [S3], KRDS 라이트/고대비 모드(`data-krds-mode=high-contrast`) [S18], InstUI 고대비 테마 [S27].
- **제품 화면용 글자 크기는 작고 고정적.** Carbon은 제품 화면에 고정 크기 productive 세트를 쓰고 마케팅용 expressive는 제품에서 산만하다고 한다 [S3]. Fluent 기본 본문은 14px/20px(Base300) [S17]. 반면 KRDS 공공 웹 본문은 17px [S18] — 대국민 웹과 업무용 관리 화면의 차이로 본다.
- **반경은 작게.** Fluent 2·4·6·8·12px [S17], KRDS 2·4·6·8·10·12px [S18].
- **그림자는 2겹(주변광+방향광) 단계.** Fluent shadow2~64 [S17].
- **접근성 수치.** 대비 4.5:1, UI 구성 요소·포커스 3:1, 대상 24×24px, 색만으로 전달 금지, 포커스 가림 금지 [S19].
- **한국어 조판.** KRDS는 Pretendard GOV, 줄높이 1.5, `word-break: keep-all`을 기본으로 둔다 [S18].

**갈리는 선택**

- 기본 본문 크기: 업무 도구 14px [S17] vs 공공 웹 17px [S18]. 한국어는 같은 px에서 라틴 문자보다 획이 조밀해 보인다는 실무 관찰이 있으나 이번 검색에서 연구 근거는 찾지 못했다(확인 필요).
- 다크 모드: Carbon·Atlassian(문서 그림에 라이트·다크 변형)은 다크를 지원 [S3][S15], KRDS는 다크 대신 고대비 모드를 둔다 [S18].

**이 제품 권고**

- 본문 기본 **14px / 줄높이 22px**(한국어 가독성을 위해 Fluent 20px보다 약간 넓힘, 제안값), 긴 글(발행본·근거 발췌)은 **15~16px / 24~26px**. 사용자 설정에서 글자 크게(+2px) 단계 제공.
- 다크 모드는 2단계로: 1단계에서 모든 색을 의미 토큰으로 바꿔 라이트만 출시, 2단계에서 다크·고대비 값 추가. 처음부터 하드코딩된 색을 없애는 것이 핵심이다.
- 다국어: 한국어(Pretendard), 영어(같은 Pretendard 라틴 글리프), 태국어(Noto Sans Thai, 줄높이 더 넓게 — 확인 필요)를 `:lang()` 별 서체 스택으로.

### 5.2 레이아웃 (앱 셸)

```
┌──────────────────────────────────────────────────────────────────┐
│ [≡] 로고 │ [드리미 예시학교 ▾]      [ 🔍 검색 (Ctrl+K) ]    ? 🔔 👤 │  상단 막대 48px
├───────────┬──────────────────────────────────────────┬───────────┤
│ 업무       │ 문서실 › 학기말 보고서                     │ (보조 패널) │
│  자료 접수  │ ┌PageHeader─────────────────────────────┐ │ 근거/이력   │
│  검토 대기 ③│ │ 학기말 보고서  [확정됨] 3판             │ │ 접기 가능   │
│  문서실     │ │ 설명 한 줄              [보조] [주 동작] │ │            │
│ 학교 관리   │ └───────────────────────────────────────┘ │            │
│  설정 …     │ [탭: 내용 | 판 이력 | 접근 기록]            │            │
│ 플랫폼 관리 │ 본문 (표·카드·양식)                         │            │
│ (권한자만)  │                                          │            │
│ ── 꼬리 ── │                                          │            │
│ 도움말·버전 │                                          │            │
└───────────┴──────────────────────────────────────────┴───────────┘
  좌측 탐색 240px(접으면 56px 아이콘 레일)            보조 패널 320~400px
```

- **상단 막대(48px)**: 시작(탐색 접기, 로고, 학교 전환기) · 가운데(통합 검색) · 끝(도움말, 알림, 계정) [S15][S2]. 도움말 위치는 모든 화면에서 같게(WCAG 3.2.6) [S19]. 상단 막대는 `position: sticky`일 때 포커스 요소를 가리지 않도록 `scroll-padding-top` 지정(WCAG 2.4.11) [S19].
- **학교 전환기**: 현재 학교 이름(+학교 유형/언어 배지)을 버튼에 표시, 누르면 검색 가능한 목록(소속 학교만), 최근 학교 상단. 전환 시 같은 모듈의 첫 화면으로 이동(다른 학교의 상세 ID를 그대로 들고 가지 않음). 플랫폼 관리자는 목록 하단에 “플랫폼 관리로 이동”.
- **좌측 탐색(240px)**: 구역 제목(MenuSection) + 항목, 현재 항목은 `aria-current="page"`와 brand-50 배경+왼쪽 3px 막대 [S14][S16]. 처리할 건수는 숫자 배지. 접으면 아이콘 레일(툴팁 라벨). 배경은 surface-default(흰색)로 바꿔 무거운 남색 면을 없애고, 브랜드 색은 로고·선택 상태에만 쓴다.
- **본문**: 최대 폭 제한 없음(표 화면), 양식·설정·확인 화면은 읽기 폭 720~880px [S11].
- **경로 표시**: 2단계 이상에서만, PageHeader 위 [S7].
- **PageHeader**: 제목(heading-md) + 상태 배지 + 메타(판·확정일·확정자) + 설명 + 오른쪽 동작(주 동작 1개, 보조 동작, 더보기). 페이지 탭은 PageHeader 바로 아래 [S9][S13][S14].
- **주요 동작 위치**: 페이지 전체 동작 = PageHeader 오른쪽 / 표 전체 동작 = 표 도구 막대 오른쪽 / 선택 항목 동작 = 일괄 작업 막대 / 한 행 동작 = 행 끝 더보기 / 양식 제출 = 양식 아래 왼쪽 정렬(주 버튼 먼저) [S1][S13].
- **반응형**: 1024px 이하에서 보조 패널은 겹침(overlay)으로 [S15], 768px 이하에서 좌측 탐색은 서랍(drawer). 표는 가로 스크롤 허용(2차원 배치가 필요한 콘텐츠는 WCAG 1.4.10 예외)하되 첫 열 고정.

### 5.3 컴포넌트 목록과 규칙

| 컴포넌트 | 규칙 |
|---|---|
| **PageHeader** | 화면마다 1개. 제목은 `<h1>`. 주 동작은 최대 1개, 나머지는 보조/더보기. 변경 불가 기록이면 편집 대신 “새 판 만들기”. 위험 동작은 더보기 메뉴 안 맨 아래, 위험 색 글자 [S9][S13]. |
| **Button 계층** | primary(brand 채움, 화면 구역당 1개) / secondary(테두리) / ghost(글자만, 도구 막대·행 동작) / danger(위험 채움, 확인 대화상자 안에서만) / icon-only(접근 가능한 이름·툴팁 필수). 라벨은 동사+대상(“구성원 초대”, “규칙 3건 확정”). 처리 중엔 버튼 안 표시+재클릭 방지 [S8][S13]. |
| **Badge / Status** | 상태 전용, 클릭 불가, 형용사·명사 라벨(“확정됨”, “검토 대기”, “충돌”). 항상 글자 포함, 표 안에서는 연한 배경+진한 글자, 필요 시 앞에 점/아이콘. 화면당 상태 종류는 적게 시작. 합산 상태는 가장 높은 주의 단계 색 [S4][S12]. 숫자 배지(건수)는 별도 `CountBadge`. |
| **Table (DataTable)** | 제목(보이거나 화면낭독기용) 필수, `<table>` 의미 구조·`<th scope>`, 정렬 머리글은 버튼+`aria-sort`, 숫자 오른쪽 정렬+tabular-nums, 빈 셀은 비움, 스켈레톤 로딩, 페이지 나눔(기본 50행), 선택 열·일괄 작업 막대, 행 동작 열은 머리글 숨김 문구, 밀도 3단계, 열 표시/숨김·순서는 표 설정에서 [S1][S9][S13]. |
| **Toolbar / Filter** | 왼쪽: 저장된 보기 탭 → 검색 → 필터 버튼, 오른쪽: 표 전체 동작(최대 5개)+더보기. 적용된 필터는 제거 가능한 칩으로 표시, “모두 지우기” 제공. 필터가 3개 이상이거나 서버 응답이 느리면 “필터 적용” 버튼으로 일괄 적용 [S1][S6][S13]. |
| **Tabs** | 한 화면 안에서 URL을 바꾸는 탭과 바꾸지 않는 탭을 섞지 않는다. 페이지 수준 탭은 URL 변경(뒤로 가기·공유 가능) [S7]. |
| **Field / Form** | 라벨은 입력란 위, 도움말은 라벨 아래, 오류는 입력란 아래(아이콘+글자, `aria-describedby`). 제출 시 검증 → 상단 오류 요약(포커스 이동, 각 필드로 링크, 같은 문구, `<title>` 앞 “오류:”) + 필드 오류 [S10]. HTML5 기본 검증 끔. 한 양식 안에서 자동/명시 저장 혼용 금지, 실패 시 값 보존, 이동 시 저장 안 된 변경 경고 [S8]. 같은 흐름에서 이미 입력한 값 다시 묻지 않음 [S19]. |
| **Card / Section** | 카드 = 제목(heading-sm) + 선택적 설명 + 본문 + 카드 동작(오른쪽 위). 설정 화면은 Section(왼쪽 제목·설명 / 오른쪽 카드) 2열 [S13]. 키–값 정보는 `SummaryList`(`<dl>`, 행별 “변경” 링크에 숨김 문구) [S11]. 카드 안에 표를 넣을 땐 카드 제목이 표 제목을 겸하되 중복 금지 [S9]. |
| **EmptyState** | 유형 3가지(첫 사용 / 결과 없음 / 권한·오류). 구성: 제목(무엇이 없는지) + 다음 행동 설명 + 주 동작(선택) + 보조 동작(선택). 권한 문제는 오류처럼 보이지 않게 안내형으로, 요청할 대상 명시 [S6][S10]. |
| **Toast / Inline alert / Banner** | 인라인 알림: 관련 항목 바로 옆, 해결 전까지 유지 [S5]. 배너: 페이지·구역 상단 본문 안(전체 폭이지만 전역 막대에 붙이지 않음) [S8]. 토스트: 화면 밖 결과의 짧은 성공 알림만, 오른쪽 아래, 고정 폭, 새 것이 위, 동작 버튼 최대 1개, `role="status"`, 6초 이상 + hover/focus 시 멈춤, 오류는 토스트로 보내지 않음 [S5][S8][S19]. |
| **Dialog** | 집중이 필요한 짧은 작업·확인에만. 맥락 정보·근거 보기는 보조 패널로 [S15]. 열리면 포커스 이동·포커스 가둠·Esc 닫기·닫으면 원래 버튼으로 복귀. 위험 확인 대화상자: 제목에 동작과 대상(“구성원 3명 접근 권한 회수”), 본문에 결과·되돌릴 수 있는지, 버튼은 “취소”와 동작명 [S6][S8]. |
| **Timeline / Audit log** | 세로 타임라인, 최신이 위. 항목 = 아이콘(동작 유형) + 행위자 + 동작 + 대상 + 시각(절대+상대, `<time datetime>`) + 사유 + 펼침 상세(이전 → 새 값, `aria-expanded`). 장식용 구분선은 보조기기에 숨김, 각 항목 글이 상태를 스스로 설명 [S9][S14]. 접근 기록 탭은 같은 데이터를 표로도 볼 수 있게(필터·내보내기). |
| **Evidence list** | 근거 1건 = 출처(파일명·시트·행 번호) + 발췌(일치 부분 강조, 색 + 굵기) + 신뢰도/일치 상태 배지 + “원본 보기”. 추론 규칙의 각 필드와 근거를 양방향 연결(필드에 근거 수, 근거에서 관련 필드로 이동). 충돌 근거는 warning 상태로 위에 모음. 근거는 원본 행 스냅샷을 보여 주고 현재 자료를 다시 조회해 바꾸지 않음(발행본 규칙과 같은 원칙). |
| **추가 권장** | `Stepper/Path`(자료 접수→검토→확정→발행 단계, 현재 단계 `aria-current="step"`) [S14], `SchoolSwitcher`, `SidePanel`, `Skeleton`, `CountBadge`, `Meter`(좌석 사용량, 글자 값 병기). |

### 5.4 상태 색 의미표

| 의미 단계 | 토큰 | 이 제품 상태 예 | 표현 | 사용자 행동 |
|---|---|---|---|---|
| 높은 주의 — 위험 | danger | 검증 오류, 발행 실패, 좌석 초과, 로그인 실패 급증, 결제 실패 | 빨강 글자·연한 배경 + 경고 아이콘 | 즉시 조치 필요 |
| 높은 주의 — 경고 | warning | 충돌 질문 열림, 확정 규칙과 다른 새 자료, 좌석 90% 이상, 라이선스 만료 임박 | 주황/황 글자·연한 배경 + 삼각 아이콘 | 검토 필요 |
| 중간 — 진행 | info | 분석 중, 검토 대기, 발행 예약됨, 초대 보냄 | 파랑 글자·연한 배경 (+회전/시계 아이콘) | 기다림 또는 담당자 처리 |
| 낮음 — 완료 | success | 확정됨, 발행됨, 결제 완료, 초대 수락 | 초록 글자·연한 배경 + 체크 | 행동 불필요 |
| 낮음 — 중립 | neutral | 초안, 비활성 모듈, 보관됨, 이전 판(대체됨) | 회색 글자·연한 배경 | 참고 |
| 낮음 — 새로움 | discovery | 새 기능, 실험(개발·실험 보드) | 보라 글자·연한 배경 | 참고 |

규칙: (1) 같은 상태는 모든 화면에서 같은 색·같은 라벨 [S12]. (2) 색만으로 구별하지 않고 항상 글자, 필요하면 아이콘 모양으로 이중 표시 [S4][S19]. (3) 주 버튼에 success(초록)를 쓰지 않는다 — 브랜드 파랑과 상태 초록을 분리해 “완료”의 의미를 보존한다(Primer는 주 버튼에 success를 쓰지만 이 제품에서는 기각) [S9]. (4) 여러 하위 상태를 합칠 때는 가장 높은 단계 색 [S4].

### 5.5 접근성 체크리스트 (WCAG 2.2 AA 기준, KWCAG 2.2 대응은 확인 필요)

- [ ] 본문 글자 대비 4.5:1 이상, 18.66px 굵게/24px 이상은 3:1 (1.4.3) [S19]
- [ ] 입력란 테두리·체크박스·포커스 표시·의미 있는 아이콘 3:1 이상 (1.4.11) [S19]
- [ ] 색만으로 상태·오류·선택을 전달하지 않음 (1.4.1) [S12][S19]
- [ ] 320px 폭에서 가로·세로 양방향 스크롤 없이 사용 가능(표 등 2차원 콘텐츠 예외) (1.4.10) [S19]
- [ ] 모든 기능 키보드로 가능, 포커스 순서 논리적, 포커스 표시 항상 보임
- [ ] 고정 상단 막대·토스트·보조 패널이 포커스된 요소를 완전히 가리지 않음 (2.4.11) [S19]
- [ ] 클릭 대상 24×24px 이상 또는 충분한 간격 (2.5.8) [S19]
- [ ] 끌어 놓기(파일 올리기, 열 순서 바꾸기)에 버튼 대안 (2.5.7) [S19]
- [ ] 도움말 위치가 화면마다 같음 (3.2.6) [S19]
- [ ] 같은 흐름에서 이미 입력한 정보를 다시 입력하게 하지 않음 (3.3.7) [S19]
- [ ] 로그인에 기억·퍼즐 같은 인지 테스트만 요구하지 않음(비밀번호 붙여넣기·비밀번호 관리자 허용) (3.3.8) [S19]
- [ ] 저장 완료·필터 결과 건수·처리 상태 변화는 `role="status"`/`aria-live`로 포커스 이동 없이 알림 (4.1.3) [S19]
- [ ] 오류 시 상단 오류 요약으로 포커스 이동, 각 오류에서 해당 필드로 이동, `<title>` 앞에 “오류:” [S10]
- [ ] 탐색 현재 항목 `aria-current`, 펼침 메뉴 `aria-expanded`/`aria-controls` [S14][S15]
- [ ] 표: `<caption>` 또는 `aria-labelledby`, `<th scope>`, 정렬 상태 `aria-sort`, 행 동작 버튼에 행 이름 포함 숨김 문구 [S9][S11]
- [ ] 페이지 `<html lang>`과 학교 언어별 `lang` 지정(ko/en/th), 건너뛰기 링크
- [ ] 고대비 테마(2단계) 또는 OS 강제 색 모드(`forced-colors`)에서 테두리·포커스가 사라지지 않음 [S18][S27]
- [ ] 자동 사라지는 알림은 충분한 시간과 멈춤 수단 제공 [S5]
- [ ] 자동화 검사(axe 등) + 화면낭독기(NVDA·VoiceOver) 수동 점검을 e2e 흐름에 포함
